# ADR-20261031: 动效分层，内容与空间变化参照 iOS 弹簧

- 状态：已接受
- 日期：2026-10-31
- 覆盖：[DESIGN「动效」](../DESIGN.md#动效)中内容与空间变化原有的曲线、时长与位移取值

## 背景

过程组收起的多轮真机录屏复核发现，许多过渡在观感上接近瞬间。逐帧计算显示，原进入曲线 `(0, 0, 0, 1)` 配 160–180ms 时长，第一帧就完成 43–46%，约 90ms 完成 90%；4–8px 的位移在第一帧后只剩约 3px 可见。曲线本身是常见的减速曲线，问题在于把按压一类的短时长用在了内容出现与空间变化上。

比较公开设计系统的做法：Carbon 分为 productive 与 expressive 两套，Material 3 与 Fluent 按尺寸与移动距离选择时长档位，iOS 对内容与空间变化使用弹簧；它们都把按压、悬停等操作反馈与内容、空间变化分开，前者短而即时，后者更长。

团队在状态展厅与 staging 设置中用正式组件并排比较了四套参数：原规范、缓入缓出 `(0.2, 0, 0.2, 1)` 300ms、减速 `(0.2, 0, 0, 1)` 300ms、iOS 无回弹弹簧约 500ms，选定 iOS 弹簧。比较过程见内部方案 [内容与空间过渡复核](../plans/completed/20261031-motion-content-space.md)。

## 决策

1. 动效分两层。「操作反馈」包括按压、悬停、复制反馈、菜单与 Popover，保持原有短时长与曲线。「内容与空间」包括发送气泡与在线新行进入、过程组与工具展开收起、Toast、居中 Modal、浮动入口与局部提示、桌面侧栏收展、图片阅读器几何、发送跟随与内容淡入，改用独立曲线 `--pwa-ease-content`。
2. 内容曲线参照 iOS SwiftUI `.smooth`：临界阻尼、无回弹、体感时长等于过渡时长，用 `linear()` 的 33 个等距采样点表达并归一化到终点。500ms 时第一帧约 2%，约 300ms 完成 90%。过程组自动收起取同一曲线，不再单设对称曲线。
3. 出现与展开约 500ms，收起 350ms；侧栏 450ms；Modal 与 Toast 离开 250ms 并继续使用退出曲线，保持离开更快。位移加大为 Modal、Toast 与浮动入口 12px，发送气泡 12px，折叠 8px。具体取值以 DESIGN「动效时长」与 `pwa-theme.css` 为准。
4. 脚本经 `pwaContentEasing` 读取内容曲线；浏览器不支持 `linear()` 时回退到标准曲线，避免 WAAPI 抛错。系统开启减少动态效果时规则不变，统一为 120ms 短淡化。
5. Drawer、设置页与手势松手收尾暂沿用原覆盖模型（200ms 标准曲线），将在后续一批中按同一参照处理，并引入松手时接住手势速度的机制。同一时刻多处变化的编排规则另行确定。

## 影响

- 高频操作（发送、展开收起）的单次过渡变长，换来起步平缓、收尾柔和的观感；如果在真机上发现个别场景拖沓，只调整该场景的时长，不改分层与曲线。
- 发送跟随与过程组收起的脚本时钟随 `message-in`、`collapse-*` 变长，期间新输出贴底的时机相应后移。
- 发送、交接等机制测试固定测试用时钟断言中间帧，主题取值由守卫与使用主题值的专门用例覆盖。
- 当前规则以 [DESIGN](../DESIGN.md) 为准。

## 补充决策：覆盖模型与跟手收尾（2026-10-31）

本节取代上文第 5 条中 Drawer、设置页与手势收尾「暂沿用」的部分；编排规则仍另行确定。

1. Drawer（移动导航、电脑选择、工具与文件阅读器）与设置页改用内容曲线：进入 450ms、离开 350ms，遮罩同步；整屏面板比局部内容略短，以免拖慢导航。原「进出同长」改为与其他叠层一致的「离开更快」。
2. 跟手拖动松手后，以松手速度作为初速度现场生成临界阻尼弹簧（`linear()` 采样）；参照 iOS，时长固定取去向对应的进入或离开时长，不随剩余距离缩短。初速度上限取弹簧角频率，曲线单调、不越过终点，面板不会冲出边缘再弹回。
3. 切换会话的淡出按同一规范：移动导航中的选择随 Drawer 离开同步淡出，桌面等没有导航退出的入口以 250ms 与内容曲线淡出，再以内容淡入换上新会话。

## 修订：时长整体缩短为 0.8 倍（2026-10-31）

staging 真机体验后，用户反馈整体略慢。曲线与分层不变，内容与空间层全部时长乘以 0.8：出现与展开 400ms、收起 280ms、Modal 与 Toast 离开 200ms，Drawer 与设置页 360／280ms，侧栏 360ms，图片 400／280ms，内容淡入 320ms，切换淡出 200ms。出现类过渡约 240ms 完成 90%，处于 iOS 系统动画体感时长（约 0.35–0.5 秒）的中段。上文各节中的具体毫秒数以本节与 DESIGN 为准。

## 补充决策：编排（2026-10-31）

本节取代上文「编排规则另行确定」。核对后同一时刻并列变化的场景有三处，用户确认均采用先后方案：

1. 空会话发出第一条消息：空态提示在原位淡出（`fade`，不占布局），本端气泡等淡出结束再进入；输入区回缩不等待，代价是首条气泡晚约 120ms 出现。
2. 回复正文接在过程组之后：过程组先自动收起，同一提交里新进入的正文等收起结束再淡入。显示队列照常放出文字，只推迟显示，不改变队列与 `run_end` 语义。
3. 本轮结束：完成时间改为淡入；没有正文的组同时自动收起时，等收起结束再淡入。活动区是不可见的占位，随 `run_end` 一并撤下。

等待只在行创建时确定，之后新进入的行不受影响；减少动态效果时等待时长随 `reduced` 缩短。

## 修订：发送衔接（2026-11-01，真机录屏复核）

iOS 录屏复核发现发送时不协调，逐帧核对后修正：

1. 空会话首条消息时空态提示离开状态截断了外边距，提示下移约 16px 后才淡出；改为按显示时的位置在绘制前补偿，保持原位淡出。
2. 发送时滚动的阻尼参数仍按旧的 160ms 调校，约 150–200ms 到位，比输入区回缩与气泡（`message-in`）快一倍多；改为角频率取 2π／`message-in`，从静止起步时与内容曲线同形，三者同时到位。
3. 气泡自身上移与跟随滚动叠加成两种位移，且与「在线新行只淡入、位移由跟随滚动承担」不一致；用户确认本端气泡只淡入，只有空会话的第一条消息（没有跟随滚动）保留上移。
4. 过程组自动收起后内容不足一屏时，跟随中的滚动位置会随收起被浏览器压到顶部，并在到顶时以约每帧 28px 的速度急停；改为开始收起即保留全部待收回高度，滚动以收起时长与同一曲线平滑移到收起后的位置，再释放临时空间。

## 修订：过程组先收起再出正文，收起时组头原位（2026-10-31）

用户复核反馈：正文接在过程组之后时，折叠与正文输出看起来同时发生；希望先折叠完再输出文字，展开与收起时组头位置固定、始终从下方伸缩，放不下时由用户滚动。核对实现后确认两处原因：上文编排第 2 条只把正文行的入场淡入推迟 `collapse-settle`，正文行从第一帧起就占布局并持续增长，收起与增长在同一时段发生，等待结束时攒下的文字一次淡入；跟随中的收起按底部锚定，收回的高度由浏览器钳制滚动位置，组头随收起下移（长对话中表现为 BACKLOG 记录的短促下移）。用户确认以下修订：

1. 正文接在过程组之后（权威顺序中紧接思考或工具）时，显示队列在其首个可见字到达后先等待 `collapse-settle`，期间不放出文字；显示快照以等待项表示「正文已到」，过程组据此自动收起，等待项不渲染为行。等待结束时首批字素与等待项在同一快照交接，之后逐字放出。等待期间该正文算作未放完，其后的新行与 `run_end` 照常排在其后。重置、补齐与前台恢复不等待。正式版本未经流式直接到达时，仍沿用正文入场推迟淡入的兜底。本条取代上文编排第 2 条「显示队列照常放出文字，只推迟显示」。
2. 跟随中过程组开始收起（自动与手动）时，组头原位不动：收回的高度暂留为列表末尾的临时空白，滚动位置保持；本轮仍在运行时由随后的输出填入，内容越过原位置后恢复普通跟随；本轮已结束或空闲时，等收起结束后以同一时长与内容曲线平滑收回空白。保持期间又有组收起时在已保留的空间上叠加；手动展开（阅读暂停）期间保持继续，只随明细重新填入而缩减；本端发送时空白随发送滚动平滑收回，不一次撤掉；用户滚动、Latest 与重置结束保持。回看时的锚点规则不变；减少动态效果时收起没有高度过渡，不建立保持。本条取代上文修订第 4 条，以及 [ADR-20261030 过程组](20261030-thinking-tool-process-groups.md) 决策 7 中跟随时「随收起回落到新的底部」。
3. 临时空白由列表末尾的伪元素承担，不加在底部内边距上：滚动容器的盒高不能小于自身内边距，保留量超过可视高度时会把列表撑高，滚动范围随之失真。

## 修订：用户回看优先于自动滚动（2026-11-05）

用户反馈手动滚动时仍有自动滚动拉动位置。核对发现，输入事件先清理运动对象、再判断是否中断，可能丢失回看意图；发送等过渡的程序回执又可能先把手动位置写回旧目标。用户确认将跟随资格与动画状态分开，统一采用以下规则：

1. 用户主动回看并离开底部后持续保持阅读位置，只有主动滚回真正底部或点击「最新」才恢复跟随；到底只容忍像素舍入误差，不沿用 32px 附近带。布局收缩、锚点补偿或程序回执造成的被动到底不算恢复信号，自动运动追赶中的暂时离底也不算用户回看。
2. 回看时发送文字或附件也不拉到底部；发送、出队、回复增长、Working 显隐、过程组收起与视口变化都不得覆盖回看意图。本条取代此前成功发送即恢复跟随的规则，原本仍在跟随时的发送过渡不变。
3. 用户接管优先于旧程序回执。手指按住、拖动、惯性与回弹期间暂停所有自动滚动分支；静止 200ms 只解除临时输入暂停，不重新开启回看中的跟随。无移动轻点不永久关闭原有跟随。
4. 手动滚动保留浏览器原生惯性，历史继续提前加载、在滚动静止后前插并保持语义锚点；位置补偿用于稳住原内容，不属于追最新。自动跟随继续复用单一协调器与连续运动，不另加滚动器或调整曲线、时长。首次打开、会话重置与会话位置恢复规则不变。

本节仅修订自动滚动的接管与恢复条件，不改变上文的内容编排、收起保持空间或动效参数；当前行为以 [DESIGN](../DESIGN.md#实时与只读历史) 为准。
