# ADR-20261030: 会话输出连续性与 Working 兜底

- 状态：已接受
- 日期：2026-10-30
- 覆盖：[ADR-20261030 过程组](20261030-thinking-tool-process-groups.md) 决策 2 的自动收起时机与决策 6（Working 承载）；[ADR-20261011](20261011-live-tool-grouping.md) 的「Working 提示修订（2026-10-12）」

## 背景

2026-10-30 的 iOS 录屏显示，正文已经按积压匀速放出、淡入并平滑跟随，但一轮里约四分之三的时间处于思考与工具阶段，这段呈现以跳变为主：思考只显示首行摘要，被截断后静止；工具在执行开始时才出现，快速命令同一帧整组出现且已打勾；思考结束后摘要退回「Thinking」；Working 在组头、末尾和正文下方之间迁移；本轮结束时 Working 隐藏、完成时间出现，正文却还在放出最后几行。

原因有三：Working 表达的是「Pi 仍在运行」，与正文、组头争位置；文字经显示缓冲，结构变化、工具状态与 `run_end` 却直接穿透到界面，两套时钟；新行与 Working 显隐直接改变高度，平滑跟随只认 Pi 正文。

方案、录屏逐帧证据与实施记录见[会话输出连续性方案](../plans/active/20261030-stream-output-continuity.md)。

## 决策

1. Working 只在界面没有明确动作时兜底：本轮活动区内连续 400ms 没有任何可见变化（文字放出、新行、工具状态或参数变化）且视口内没有转动的工具图标时显示，任何变化立即隐藏。网络停滞导致正文或思考不再变化时同样显示。
2. Working 只出现在时间线末尾固定高度的活动区内，显隐只改透明度；活动区从本轮开始运行起保留，到本轮结束呈现时收起。过程组组头不再承载 Working。
3. 显示队列统一呈现节奏：正在观看的一轮里新出现的行按事件顺序逐个放出（间隔 120ms，前一段文字放完前不插队，积压超过 1s 追赶，单次超过 6 行视为补齐）；工具进行中视图至少保持 300ms；本轮 `run_end` 在本轮内容全部呈现后才进入显示，完成时间与收起不早于正文最后一个字。本端消息进入对话区时上一轮剩余文字继续按节奏放完。Composer 的发送与排队判断仍以 Pi 的真实运行状态为准。
4. 过程组在其后紧接的同轮正文出现第一个字、且组内没有进行中的成员时自动收起；组后没有正文的在本轮结束呈现后收起。手动选择与阅读保护仍然优先。
5. 运行中的思考在明细内显示两行尾部预览；结束后保留最后有效的标题或首行摘要，不退回占位。
6. 工具调用在模型开始生成时就以「准备中」出现：协议为工具 partial 新增 `status: "preparing"`，Extension 在 `toolcall_start`／`toolcall_delta` 时按调用节流发布，执行开始后同一 `partial_id` 原位转为运行；运行结束仍未执行的准备中调用不再显示。
7. 跟随时，仍有成员运行的过程组与流式正文一样平滑接续；在线会话追加的新行只淡入。流式正文的最后一块临时补闭合未完成的行内标记。

## 影响

只有正式 `run_end` 能确认整轮结束的语义不变（[ADR-20260930](20260930-strict-run-completion.md)）：显示队列只推迟呈现，不补造、不推断结束。

协议新增枚举值后，旧 PWA 收到准备中帧会拒收并显示协议提示，必须先部署 PWA 再发布 Extension（同 [DEPLOYMENT](../DEPLOYMENT.md#extension-npm-发布)）。当前视觉与交互规格以 [DESIGN](../DESIGN.md#组件规则) 为准，显示队列的职责见 [ARCHITECTURE](../ARCHITECTURE.md#流式显示队列)。

## 备选方案

- 保留「具体运行图标优先、组头承载 Working」：Working 仍会在多个位置之间迁移，并在正文输出时一直挂着，不采用。
- Working 直接跟随 `working` 状态，只延迟显示：无法区分「正在输出」与「网络停滞」，不采用。
- 工具准备中沿用 `running` 状态、不改协议：免去发布顺序约束，但无法区分模型生成与真正执行，审批与状态文案会误导，不采用。
- 新行做高度展开动画：每帧触发布局，与跟随滚动叠加时位移更明显，改为只淡入、由跟随滚动承担位移。
