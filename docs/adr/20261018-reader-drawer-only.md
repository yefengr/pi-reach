# ADR-20261018: 阅读器统一为右侧 Drawer

- 状态：已接受
- 日期：2026-10-18
- 取代：阶段 D「宽屏工作面板」中的分栏阅读设计

## 背景

阶段 D 把工具详情与已发布文本文件改为宽主区下的可调宽非模态第二列（见 [PWA 宽屏工作面板](../plans/active/20261017-pwa-ui-ux-motion-evolution.md#13-阶段-d-实施与验证记录)）。这套设计在实践中带来两个持续成本：

1. 分栏判据不是固定断点，而是「视口 ≥ 768px 且主区扣除侧栏、卡片外边距与安全区后的可用宽 ≥ 900px」。侧栏一收一展，同一个阅读器会在非模态分栏与模态 720px Drawer 之间来回切换；为此需要正文宿主迁移、选区与滚动恢复、文件 pin 交接、Escape 与 history 归属切换等一整套逻辑。
2. 窄桌面（例如 1100px 视口展开侧栏时可用宽 832px）本来就一直走 Drawer，分栏只在更宽的屏幕上生效。同一产品在相近尺寸下有两套阅读器行为，验收与问题定位都要覆盖两种形态。

实际使用中更看重阅读器行为稳定、单一：详情打开即独占阅读，关闭后回到原位置。边看边写并非必要能力，遮罩下的对话保持原状即可。

## 决策

1. 工具详情、已发布文本文件、图片与摘要统一为右侧 Drawer：视口 ≥ 768px 时宽 720px（另加右安全区），< 768px 全屏。不再有第二列、分隔条、宽度拖拽或列宽偏好。
2. Drawer 使用遮罩、焦点陷阱与页面滚动锁；打开时压入一条不改变 URL 的历史记录，系统返回、浏览器后退、Escape、遮罩点击与关闭按钮都只关闭阅读器。移动端保留左缘返回与右滑关闭。
3. 关闭后只恢复仍失效或仍位于阅读器内的焦点；阅读位置由原时间线维护。普通 leaf 推进、流式更新与迟到文件结果不替换当前正文，也不重新打开已关闭的阅读器。
4. 删除分栏专属实现：`WorkPanelLayout`、可调宽 hook、分隔条与其样式、正文宿主迁移、`replacePanel` 原地替换语义、宽度相关文案与测试。工具与文件继续共用 `ReaderShell`。
5. 保留与形态无关的既有行为：单条 history 与 Back、焦点回送、文件 pin 生命周期、迟到结果防护、移动端滑动、图片放大与回源。

## 后果

- 桌面失去「边看详情边输入」；阅读时对话、草稿与发送在遮罩后保持原状，关闭后继续。
- 同一视口不再因侧栏收展改变阅读器形态；`use-work-panel-reader` 的宿主迁移、选区恢复与「宽窄切换不结束阅读」一类回归风险随之消失。
- 工作区仍有会话列容器，但只负责主区左右安全区与纵向布局，不再承载第二列。
- [DESIGN](../DESIGN.md) 删除「宽屏工作面板」一节，改为单一 Drawer 规则；分栏相关组件测试与远程 E2E 辅助按 Drawer 重写，并新增桌面 720px、遮罩与滚动锁、Back 与回焦的回归用例。
- 评审原型 [20261018 PWA 工作面板](../prototypes/20261018-pwa-work-panel/index.html) 保留为历史快照，状态视为已失效，不再对应当前实现。
