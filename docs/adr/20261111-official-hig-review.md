# ADR-20261111: 对照 Apple 官方规范复核后的圆角、边界、图标与按钮形状调整

- 状态：已接受
- 日期：2026-11-11
- 覆盖：[ADR-20261101](20261101-hairline-concentric-radii.md) 补充决策中「行内按钮保持 8，不做胶囊」「所有按钮胶囊不采纳」、用户消息气泡圆角 16、设置页分组圆角 12，以及正文决策中「只靠描边成形的标签与图标块保持 1px」；[ADR-20261111 图标、按钮与卡片](20261111-icons-buttons-cards.md)中用户气泡内附件卡片保留 1px `line` 的例外、「按钮改为胶囊形」的未采纳结论，以及按钮内图标与其他图标同为 1.5px 线宽；DESIGN 中 Modal 圆角 12、块级内容圆角 8、启动失败卡片圆角 12、返回入口使用箭头图标
- 后续调整（2026-11-12）：决策 3 中的「电脑图标块改为 `tonal` 底」不再沿用。电脑面板的电脑行改为与设置页单选行相同的裸图标（20，在线与离线只靠图标颜色区分），不加底色块；原 31×31 的尺寸是描边时期遗留、不在尺寸档位内，DESIGN 中「20 的选项图标、图标与文字 10」的描述保持不变。

> 原型清理（2026-11-13）：旧评审原型已从当前目录移除，下方链接固定到删除前提交的历史源码。原决策与后续取代关系保持不变，当前规则仍以 DESIGN 和后续 ADR 为准。

## 背景

此前几轮「参照 iOS」的调整依据的是对 iOS 的印象和二手报道，决策记录、方案与 DESIGN 中没有引用过 Apple 官方文档。本次按 [参照 iOS 的原则](20261101-ios-reference-structure-not-material.md)，逐项对照官方 Human Interface Guidelines、Liquid Glass 采用指南与相关 WWDC 讲座，复核边框、圆角、间距、布局、字体、图标、按钮、卡片与页面、交互和动效。官方原文的摘录见 [iOS 官方设计规范摘录](../reference/ios-design-guidelines.md)。

复核结论是现有规则大部分与官方一致：字号基准与标题档位、44 点击区、每个视图一个主操作、嵌入式卡片靠底色而浮层才有外框、悬浮侧栏、滚动边缘、跟手与弹簧动效都有官方依据。偏离集中在下面几处。

官方文档不提供圆角、间距与分隔线的具体数值，只说明方向（分组与面板圆角增大、嵌套同心、触控用胶囊）。本记录中的数值是 Pi Reach 的取值，经对比原型 [`docs/prototypes/20261111-radius-button-shape/`](https://github.com/yefengr/pi-reach/blob/2c4e9f635bfef87d46c915d65a43200ee2b4dd60/docs/prototypes/20261111-radius-button-shape/page.html) 评审确定。

## 决策

1. **圆角按表面大小与层级取值**，修正原先最大的浮层（Modal 12）圆角小于消息气泡（16）与 Toast（22）、680 宽的代码块与 32 高的标签同为 8 的倒挂：
   - 居中 Modal 12 → 24，新增通用 token `--pwa-radius-2xl`。
   - 块级内容 8 → 12：代码块、工具输出容器、独立内容图片（含缩放阅读器与几何过渡层）、文件预览、错误块。
   - 页面级嵌入容器 12 → 16：设置页分组、启动失败卡片（公共样式 `pwa-card`）。
   - 用户消息气泡 16 → 20，新增专用 token `--pwa-radius-bubble`：与内部圆角 8 的附件卡片加 12 内边距同心。
2. **触控设备上的按钮为胶囊，细指针下保持圆角 8**。官方的说法是胶囊适合触控布局，高密度桌面环境只用于突出操作、中小控件继续用圆角矩形。判定与按钮高度相同：纯细指针且可悬停时为圆角矩形，存在任一粗指针或不可悬停时为胶囊。
   - 范围：常规按钮、文字按钮，以及行内文字操作的视觉底（Toast 操作、输入区提示操作、Composer 模型标签）。
   - 常规按钮的胶囊取单行高度的一半（22），文字换行时仍是大圆角，不成椭圆两端。
   - 导航底部入口与电脑面板内的配对入口属于导航行与面板行，不改：与导航行同形，并与面板圆角同心。
3. **去掉剩余的不透明 1px 描边**：用户气泡内的附件卡片改用页面底色 `bg`，不再描边（对 `message` 浅色约 1.12:1、深色约 1.36:1）；电脑图标块改为 `tonal` 底；空会话图标块保留运行轻底、去掉边框，`--pwa-running-line` 随之删除。卡片规则不再有例外。
4. **按钮内的行内图标实际线宽为 2px**。官方要求图标与相邻文字的字重一致；按钮文字为 600，原 1.5px 的图标偏细。其他位置的图标仍为 1.5px。
5. **返回入口使用向左尖角**（移动端全屏页面与阅读器、设置页）。官方的标准返回符号是尖角。桌面设置页保留文字「返回工作区」，这是网页常见做法；命令菜单内的返回行不在本次范围。
6. **不再全大写**：英文界面的电脑状态标签（Online、Offline、Checking、Partial、Current）与命令菜单分组标题按文案原样显示。官方自 iOS 26 起分区标题改用标题式大小写。

## 有意偏离

以下与官方规范不一致，保持现状并记录原因：

| 官方规范 | Pi Reach | 原因 |
| --- | --- | --- |
| 文字至少能放大到 200% | 字号三档，最大约 125% | 更大的档位需要调整布局（横排改纵排、行与容器增高）；桌面可用浏览器缩放 |
| 不提供应用内的外观设置，不重复系统级设置 | 设置页有外观与字体大小 | 网页应用在浏览器标签页与桌面上有此惯例；默认跟随系统 |
| 手势带动量时给一点回弹 | 松手收尾不越过终点 | 贴边面板回弹会露出空隙 |
| 半屏面板与屏幕边缘留空 | 底部电脑选择面板贴边，只有上沿圆角 | 网页无法可靠取得设备圆角；下拉关闭与官方一致 |
| 带底的控件周围留约 12 | 相邻按钮间距 8 | 沿用现有间距档位，点击区已满足 44 |
| 一次只显示一个弹窗（确认类除外） | 快捷键帮助可叠在其他弹窗之上 | 帮助是只读内容，关闭后回到原弹窗 |

## 未采纳

- 输入框去掉轮廓：官方表单输入框无边框，但轮廓承担 3:1 的可识别性。
- 连续曲率圆角：目前只有 Chromium 支持，iOS Safari 用户看不到。
- 两端都用胶囊：官方明确高密度桌面的中小控件用圆角矩形。

过程组自动收起后正文等待约 280ms 才出现（[ADR-20261111 动效细节](20261111-ios-motion-refinements.md)），与官方「不让人等动画」有张力；等待期间可以操作，去掉等待会让正文随上方收起而跳动，本次保持不变，留待真机观感复核。

## 影响

- 同一界面在手机与桌面上按钮形状不同；带触屏的笔记本按触控处理，显示胶囊。
- 样式守卫新增通用圆角 24、专用圆角 20 与随指针切换的按钮／行内操作圆角的登记；脚本 token 守卫校验按钮内图标的 2px 线宽；对比度测试校验 `bg` 对 `message` 不低于 1.1。
