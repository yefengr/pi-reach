# ADR-20261106: PWA 安装引导移到首次打开与设置页

- 状态：已接受
- 日期：2026-11-06
- 覆盖：[ADR-20261105](20261105-floating-composer-and-notices.md) 决策第 5 条中「PWA 安装提示移到侧栏与移动导航底部」的部分；[DESIGN「反馈呈现」](../DESIGN.md#反馈呈现)中安装提示的呈现位置，以及「主区空状态」最多一个操作的规则在未配对且可以安装时的例外
- 后续调整：见[决策记录索引](20260518-closed-decisions.md#决策记录索引)。

## 背景

安装 PWA 是 Pi Reach 的主要使用方式。ADR-20261105 把安装提示从主区顶部移到侧栏与移动导航底部，解决了提示条推开正文的问题，但也让提示失去了时机：

- 移动布局的导航是默认关闭的抽屉，未配对首屏与日常会话都看不到提示；iPhone 用户恰好最需要手动「添加到主屏幕」的引导。
- 用户第一次打开时只看到配对说明，安装与配对没有先后关系，往往先在浏览器标签页里完成配对再考虑安装。
- 提示关闭后只在下次打开时再出现，设置页没有安装入口，用户想主动安装也找不到说明。
- 已配对、正在使用时，桌面侧栏底部长期被与当前任务无关的卡片占用。

## 决策

1. 安装引导只出现在两处：未配对时的主区，与设置页最上方的「应用」分区。侧栏、移动导航与已配对的工作区不再显示安装提示。
2. 未配对且在浏览器标签页中可以安装时，主区是两步的首次使用流程，一屏只做一件事：第一步只讲安装，第二步只讲配对，两者不同时出现。第一步可选「先在浏览器中使用」进入第二步，第二步可返回安装步骤；进入第二步与其他运行时提示的关闭一样只在本次打开期间生效。
3. 浏览器提供安装事件时给「安装应用」按钮；需要手动添加时只给步骤：iPhone／iPad 上的任意浏览器为「添加到主屏幕」，Mac 上的 Safari 17 及以上为「添加到程序坞」。从主屏幕、程序坞或应用窗口打开，或安装完成后，两处引导都不再显示，未配对主区恢复单一配对状态。
4. 侧栏与移动导航底部的 `Alert` 只保留浏览器不支持离线应用模式的提示，位置与关闭规则不变。
5. 安装状态从 Service Worker 注册组件中拆出，由入口级 Provider 持有，未配对主区与设置页共享同一安装事件。

## 没有采用的方案

- **首屏同时列出安装与配对两张卡片**：评审中否决。安装与配对是两个独立的动作，同屏出现两个主操作会让用户不知道先做哪个；改为一屏一步的流程。
- **保留侧栏提示并在首屏补充引导**：同一件事在两处同时提示，已配对后侧栏卡片仍然常驻，问题没有解决。
- **说明主屏幕应用与浏览器分开保存数据，作为先安装再配对的理由**：各平台与系统版本的行为未经真机验证，不写入界面；安装可以跳过，顺序不强制。
- **用 Toast 提醒安装**：Toast 用于操作反馈，会自动消失，不适合需要多步操作的引导。

## 后果与验证边界

- 评审原型为一次性临时预览，未纳入仓库；当前规则以 [DESIGN「反馈呈现」](../DESIGN.md#反馈呈现)与「主区空状态与加载」为准。
- 本记录只改变 PWA 呈现与安装状态的归属，不改变协议、Relay、Extension、Service Worker 注册与更新提示。
- 组件测试覆盖安装事件的捕获与清除、iPhone 标签页与主屏幕打开的判断、分步与返回、换步与安装后的焦点去向和设置页分区；iOS 与 Mac Safari 的实际添加流程仍须真机核验。
