# ADR-20261027: 会话附件支持在线取回原件预览与保存

- 状态：已接受
- 日期：2026-10-27
- 取代：[会话附件上传](../plans/completed/20261002-session-attachments.md#已确认的产品决策)决策 13「第一版不支持原件下载」，以及 [DESIGN](../DESIGN.md#组件规则)「会话附件」中「无原件下载或大图弹窗」

## 背景

会话附件上线后，PWA 中已发送的图片和文件只有只读卡片：图片只有 32px 展示的有界缩略图（JPEG，最大 320px、32 KiB），文件只有名称和大小，不能点开查看，也不能保存。用户发出的截图、文档在手机上无法再次查看，需要回到电脑上找原件。

与此同时，[会话文件发布与获取](../plans/completed/20261003-session-file-publishing.md)已经建立了经既有 session route 获取电脑端原件的完整链路：Extension 安全只读打开、按 `transfer_id` 分片读取并给出 SHA-256，PWA 校验后在页面缓存中提供图片阅读、受限文本阅读和保存。附件原件长期保留在电脑端 `~/.pi/pi-reach/attachments/` 下，具备被同一链路读取的条件。

只放大现有缩略图只能得到 320px 的模糊图，且对非图片附件无效，不能解决问题。

## 决策

1. 正式消息中的附件可以从在线 Pi 取回原件，在既有阅读 Drawer 中预览并保存；预览与保存能力、页面缓存、校验和资源上限与发布文件一致。
2. 取回只在在线、当前会话、当前分支上进行：附件须属于当前分支上已绑定正式消息的附件元数据。只读历史、离线状态、pending、队列和草稿不提供取回，与发布文件的历史边界一致。
3. 授权范围与时间线可见性一致：当前会话中已授权的任何 Owner 都可以取回，不按 `sender_ref` 限定发送者本人。
4. 协议新增独立请求 frame `file_attachment_open` 承载附件取回，不扩展 `file_open` 的字段；读取、分片、关闭与错误复用文件 frame。旧 Extension 无法解码新 frame，以 `protocol_upgrade_required` 回复，PWA 只把它视为该次取回不可用并提示升级电脑端扩展，不降级、不猜测。
5. Extension 不接受客户端路径，路径只由附件元数据和服务端存储规则在电脑端确定；读取结果必须与元数据中的长度和 SHA-256 一致，原件被改动、删除或替换时受控失败。
6. 原件只在点击后获取，不随时间线滚动自动拉取；不进入 IndexedDB 或 Service Worker。
7. 旧版内联 image block 不在本决策范围内，保持现状。

## 后果

- 附件不再是「只上传、不回取」的单向通道；ARCHITECTURE「会话附件」中「不能从 PWA 下载原件」与 DESIGN 中对应规则须随实现更新。
- 协议变更遵循先部署 PWA、再发布 Extension 的顺序；新 PWA 连接旧 Extension 时附件卡片可点击但取回会提示更新 Pi。
- 附件原件在电脑端由 Pi 或用户修改后，取回会失败而不是展示变化后的内容；原件长期保留策略不变，本决策不新增清理或配额。
- 当前安全打开仅支持 macOS 与 Linux，其他平台的附件取回与发布文件一样被拒绝。
- 详细设计、验证与实施步骤见[附件原件预览与保存方案](../plans/active/20261027-attachment-original-preview.md)。
