# ADR-20261106: iOS 软键盘下的输入区：保持系统上推，按显示模式调整底部留白与阴影，发送后收起键盘

- 状态：已接受
- 日期：2026-11-06

## 背景

2026-11-06 输入区浮层（[ADR-20261105](20261105-floating-composer-and-notices.md)）的 iOS 真机验收中，点输入框弹出软键盘后有三处观感问题：

- 整页被系统上推，会话标题区移出屏幕，收起键盘后恢复。
- 主屏 PWA 的输入区与键盘之间约 34pt：其中 24px 是为 Home 指示条保留的底部留白（[ADR-20261028](20261028-ios-solid-status-bar.md)），其余约 10pt 是系统在辅助栏上方留出的空隙。
- 键盘上方有系统表单辅助栏（上下箭头与完成）。

2026-10-26 的 #139 曾尝试用脚本补偿（外壳跟随 visual viewport、锁文档高度、复位窗口滚动、收起过渡），补偿与系统上推互相干扰，标题区会先下坠再回位，因此改为完全交给浏览器，并接受标题区滑出屏幕。本次在 Safari 27 支持 `interactive-widget` 之后重新调研。

## 真机调研

2026-11-06 在 iPhone（Safari 27.2）上用独立探测页测量，探测页不接业务代码，按同一套几何读数比较各方案。

| 问题 | 结果 |
|---|---|
| `interactive-widget=resizes-content` 能否让外壳缩到键盘上沿 | 不能。WebKit 自 Safari 27.1 起支持该声明，但主屏 PWA 键盘弹出后 `position: fixed; inset: 0` 的盒仍为 812 高，可见区只剩 415，整页上推 397；外壳高度取 `100dvh`、`100lvh`、`100%` 或 `position: fixed` 四种结果相同 |
| 键盘上方的辅助栏能否去掉 | 不能。`textarea`、`input` 与 `contenteditable` 弹出键盘后可见区同为 415，辅助栏都存在；网页没有关闭接口 |
| 能否让系统不上推 | 能。点按时先聚焦屏幕顶部不可见的代理输入框，键盘弹出后把外壳缩到可见区高度，再把焦点交回真实输入框：标题区全程可见，页面上推为 0，焦点交回后键盘没有收起 |
| 系统上推的节奏 | 可见区读数一帧跳到终点；键盘比整页上推早 2–3 帧升起，弹出时键盘会短暂盖住输入区下半截（7–10 帧） |
| Safari 标签页 | 键盘弹出时浏览器在输入区与键盘之间显示地址栏，输入区下方本来就隔着浏览器的区域；同一页面两次弹出，输入区停的位置相差约 38pt，原因未查明 |

## 决策

### 标题区保持系统上推

不采用代理聚焦。它需要拦截首次点按、在键盘打开后转移焦点，第一次点按无法定位光标，并且要与中文输入、听写、联想栏及输入区现有的焦点返回逐项重新验证；标题区留在屏幕上的收益不足以抵消这些风险。软键盘仍交给浏览器，不恢复脚本补偿。

### 主屏 PWA：聚焦时收起底部留白

触屏移动布局下输入框聚焦时，输入区底部留白由 24 收为 0，卡片贴住键盘辅助栏，剩下系统自带的约 10pt 空隙；失焦后恢复。收起延迟 `collapse-out`，等整页上推基本结束再以 `collapse-in` 下沉，避免在键盘升起时把卡片往键盘里拉；恢复以 `collapse-out` 进行、不延迟。只看聚焦、不检测键盘。

### 浏览器标签页：固定小留白

触屏浏览器标签页的输入区底部留白固定为 8，聚焦时不变、不过渡。

### 贴底阴影

卡片下方可见区域所剩无几时，`0 6px 20px` 投影会被截成一道硬边。新增 `--pwa-shadow-composer-docked`：保留接触层，投影上移 6px、内缩 6px（`0 -6px 20px -6px`），只向上方和两侧散开，卡片底边处浓度不足 1%。触屏浏览器标签页始终使用；主屏 PWA 在聚焦时随留白收起同步切换。深色模式本无 Composer 阴影，贴底阴影同为 `none`。

### 发送后收起键盘

触屏移动布局下发送成功后收起软键盘。按下发送仍不抢走输入框焦点；等本端发送过渡结束（footer 移除 `data-own-send`）再让输入框失焦，键盘下落不与气泡进入、输入区回缩叠在同一时刻。没有发送过渡时下一帧收起（附件需先上传时即属此类）；等待期间已开始输入下一条、发送失败而草稿保留或焦点已离开时保持现状。桌面布局不变，发送后焦点与键盘保持。

## 尝试过、没有保留的做法

| 做法 | 没有保留的原因 |
|---|---|
| 恢复脚本补偿 | #139 已证实与系统上推互相干扰，标题区会下坠再回位 |
| 改外壳高度基准（`dvh`／`lvh`／`%`／`fixed`） | 主屏 PWA 不执行 `resizes-content`，四种结果相同 |
| 聚焦时立即收起留白 | 收起过渡恰在键盘升起时把卡片往键盘里拉，遮挡更深；改为延迟后，每次弹出完全看不到发送键的帧数从 5 降到 3–4 |
| 留白收为 0、保留原投影 | 投影被截成硬边（切口处亮度由 218 直接跳到 254） |
| 留 8–12px 间距、保留原投影 | 投影约 26pt 才完全消失，8pt 处仍有淡切口；12pt 时卡片离辅助栏约 22pt，失去贴住的效果 |
| 聚焦时只保留接触层阴影 | 切口消失，但卡片过平 |
| 浏览器标签页也在聚焦时收起留白 | 与 Safari 底部工具栏收成地址栏的动画叠加，输入区约 300ms 内来回位移 4–14pt；收起对卡片到键盘的距离几乎没有影响 |
| 浏览器标签页只在聚焦时换贴底阴影 | 未弹键盘时卡片下方 8 处也是浏览器工具栏，原投影同样被截断 |

## 后果与验证边界

- 自动化验证覆盖：触屏模拟下标签页与主屏 PWA 的留白、阴影和过渡时序，桌面与非触屏窄窗口不变，发送后收起键盘的各个分支，以及贴底阴影 token 在浅色与深色下的取值。桌面 Chromium 无法模拟 iOS 软键盘，观感以 2026-11-06 主屏 PWA 与 Safari 标签页的 staging 真机录屏为准。
- 已知限制：接外接键盘的 iPhone 聚焦时同样收起留白；横屏按桌面布局，不收起；弹出瞬间键盘仍会短暂盖住输入区下半截；带附件的消息发送后立即收起键盘，不等待上传后的发送过渡。
- 重新评估条件：WebKit 让主屏 PWA 在键盘弹出时缩小布局视口或视口单位，或网页能提前得知键盘即将弹出时，重新评估标题区与外壳高度。
