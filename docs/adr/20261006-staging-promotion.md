# ADR-20261006: 同机 staging 验收与同 digest 晋升

- 状态：已接受
- 日期：2026-10-06
- 覆盖范围：PWA／Relay 自动发布流程；不改变 Extension 发布、协议或身份模型。

## 背景

[ADR-20261001](20261001-ci-deploy-ghcr.md) 建立了 GitHub 托管 runner 构建 GHCR 镜像、production 审批与受限 SSH 部署。原流程没有隔离测试阶段，移动交互、HTTPS 与 Service Worker 升级无法先在独立 origin 的真实设备上验收。

维护者选择同一服务器、不同域名的测试环境，并要求实际受测镜像经人工审批晋升生产，而不是验收后重新构建。本记录明确调整原单环境发布决策；旧 ADR 保留原始背景和历史，不改写为新流程已经存在。

## 决策

1. 代码继续通过短期功能分支和 PR 合入 `main`，不维护长期 test／release 分支。部署隔离使用 GitHub staging／production Environment、固定 Compose 项目、容器、loopback 端口、目录和独立受限密钥。
2. 只构建所选组件一次。staging 未选组件对齐生产当前实际 digest，形成完整受测组合；自动 smoke 通过后，由维护者确认真实 iOS／Android 与同 origin 升级证据，再批准 production。production 使用同一 build digest，不重新构建。
3. 环境只由服务器固定命令选择。保留三字段 `deploy` 请求，新增 `snapshot <production|staging>` 只读固定容器元数据；读环境选择不赋予写环境权限。快照只接受健康且能核验来源仓库 digest 的实际镜像，不读取或输出容器设置。
4. Compose 运行镜像使用不可变 digest，本机备用入口使用加载后的实际 image ID；服务器回滚保存实际旧 image ID，版本标签不再是运行或回滚真源。Compose 的完整规范化配置与可信模板比较，不要求服务器新增 Node/jq，环境绑定不匹配时在 Docker 写操作前拒绝。
5. PWA 在容器启动时安全注入公开默认 Relay metadata，浏览器只有一个默认值入口；预缓存保存所属 origin 的注入 HTML。镜像未设变量时保留生产默认，staging Compose 强制提供配置，非法值／注入失败拒绝启动。staging 拒绝启动不具备运行时配置能力的旧 PWA 镜像，首次候选必须包含新版 PWA。
6. staging 不清理镜像，并固定先取得生产原目录锁再取得测试原目录锁；production 与本机备用入口仍持生产原目录锁。复用原有锁机制，防止共享镜像清理删除另一环境待回滚镜像。
7. 整条工作流串行，包括审批等待。未发布候选失败后，修复合入 `main`，手动重新构建同版本的新 digest 并重新验收；被替换的 pending run 需要手动补跑。审批后及重跑时核对当前 staging、来源和未选生产组件，旧 run 不能把新候选当作旧验收结果。
8. staging 不创建正式标签或 Release。生产镜像/source 和公网检查通过后才创建；标签创建成功、Release 失败可在验证同提交、同线上镜像后补建，不重复部署或覆盖公开标签。

## 备选方案

- **长期 test／release 分支**：没有多条稳定版本线维护需求，新增分支会增加合并与补丁同步成本，不能代替环境隔离，也不能保证合并后构建仍是原受测镜像。
- **按环境构建两份 PWA**：会让生产镜像不同于受测镜像，因此采用容器启动配置。
- **第二台服务器或自托管 runner**：当前不需要新增编排平台或服务器；构建仍在 GitHub 托管 runner，公开仓库不把未信任代码运行到生产主机。
- **恢复 test/promote 状态文件体系**：工作流 outputs／摘要和现有 Environment 审批已经承载候选与批准，不另建状态真源。

## 影响

- 仓库能力与远程准备分别验收。服务器入口、Compose、受限命令、限额、Caddy 和 GitHub Environment 需维护者另行安装；自动部署不上传任意脚本，也不修改这些配置。
- 同机只做逻辑与部署权限隔离，不是宿主安全沙箱。共享 Docker 权限、内核、磁盘和 Caddy reload 的生产影响仍存在；资源限额先测量，禁止同机压力测试。
- 锁覆盖单次部署和快照，不是跨组件事务。多组件后续失败可能留下部分上线，备用部署应避开晋升窗口；最终快照漂移阻止 Release，不把失败宣称为整体恢复。
- `main` 可以领先生产。公开版本标签和实际 digest 表示已发布内容；真机验收缺失时不能批准晋升，也不能把 smoke 当作功能通过证据。
- Compose v2 兼容能力、严格模板同步、可核验 GHCR 元数据成为初始化要求；只有本地备用镜像时不能伪造 digest，需要维护者恢复可追溯镜像后重新测试。
