# ADR-20261011: 工具调用实时分组

- 状态：已接受
- 日期：2026-10-11

## 背景

[ADR-20260930](20260930-strict-run-completion.md) 规定工具摘要只在本轮收到正式 `run_end`、且无同组流式内容后，把相邻的至少两条成功工具合并成一行。运行期间工具逐条显示，结束后整段突然收成一组；缺少 `run_end` 的历史也一直逐条显示。工具多时，运行中的会话被工具行占满，用户也看不出当前在跑哪一条。

方案与效果稿评审见 [工具调用实时分组与折叠方案](../plans/active/20261011-tool-call-live-grouping.md)。

## 决策

- 工具组是展示分组，不等于完成确认。同一轮内展示相邻的工具从第一条起即进入默认收起的工具组，不要求 `run_end`，不限最少条数，运行中、失败、中断和状态未知的工具都进入；正文、思考、可见记录、已发布文件和历史缺口仍打断分组。
- 折叠时组头按开始顺序排队显示新出现的工具，每条显示一次：后面还有排队时每条至少停留 0.8 秒，积压超过 3 条时跳到最新一条，最后一条结束后停留满 1.5 秒再回到分类摘要；已显示过的工具不再回到组头，组内仍有工具运行时摘要附旋转图标；展开时组头只显示分类摘要。
- 展开选择只由用户决定，执行状态不自动展开或收起。运行中末段工具组的展开不暂停自动跟随，其余展开照旧暂停。
- 原「Pi 正在思考…」改为「Working…」，按 `working` 与末尾输出状态显示，不推断整轮结束。

本决策取代 ADR-20260930 中“工具摘要沿用同组、展示相邻、至少两条成功工具及无同组流式内容的条件”一条。

## 影响

只有正式 `run_end` 能确认整轮结束这一语义不变：轮末完成时间与结束状态仍只在收到 `run_end` 后显示，Pi 空闲、下一轮出现或工具全部结束都不能替代；不补造结束事件，不清空 partial。`run_end` 不再影响工具分组与组头。

只改 PWA 展示，不改协议、Relay 或 Extension。缺少 `run_end` 的历史现在也显示为工具组，但仍不显示轮末完成时间。

## 备选方案

- 运行结束后再分组（现状）：运行中仍被工具行占满，结束时结构突变。
- 组头循环轮播所有运行中的工具：信息重复出现、干扰阅读，不采用。
- 组头显示最早开始、仍在运行的工具：后开始的工具要展开才能看到，长时间运行的命令会一直占住组头，不采用。
- 组头立即换成最新开始的工具：快速连续或并行的工具一闪而过，几乎看不到，改为排队显示。

## Working 提示修订（2026-10-12）

原决策按 `working` 与末尾输出状态显示 Working，只在暂时没有输出时提示。该提示因此表达的是“等待输出”，而不是“Pi 仍在运行”。为让运行状态保持连续，Working 改为持续运行指示，正文和思考输出、工具执行不再抑制提示，输出间隙也不再延迟显示。

本修订取代上方决策中 Working 的显示条件，具体显示边界以 [DESIGN「会话正文」](../DESIGN.md#组件规则) 为准。仅调整 PWA 提示的展示，不改变工具组行为、协议或正式 `run_end` 的完成确认语义；隐藏 Working 不代表该轮已被确认结束。

## 工具组摘要与状态图标修订（2026-10-14）

用户确认：折叠组头应在整批工具结束后稳定显示摘要，不能在连续或并行调用之间提前切到摘要、随后又显示调用。最后一条的最短展示时间统一为 0.8 秒，状态图标与展开后的工具行一样放在右侧。

据此修订组头规则：

- 只有组内工具全部结束，且该组之后出现同一轮的正文／思考或收到本轮正式 `run_end`，才允许从调用切到摘要。仅当前已收到的工具全部结束，不足以确认这一批已经结束。
- 最后一条从进入组头起至少展示 0.8 秒，不是从执行结束后重新计时。切换到下一条时重新计时；排队顺序和积压超过 3 条时跳到最新调用的规则不变。
- 同一批进入摘要后不再重播调用。首次加载的已结束历史工具不排队重播；展开态仍为组头摘要加下方工具列表，执行状态不覆盖用户选择。
- 左侧只放工具名和参数摘要，状态图标在右侧、折叠箭头之前。失败计数与汇总提示保留；当前调用的状态图标已经表示失败时，不重复添加同一错误图标。

本修订取代原「决策」中最后一条停留 1.5 秒、仅该条结束就回到摘要的规则，以及原「影响」中“`run_end` 不再影响工具分组与组头”的组头部分。`run_end` 仍不参与工具首次建组，但现在是确认批次闭合的信号之一；只有正式 `run_end` 能确认整轮结束的语义不变，后续正文／思考只能确认展示批次的边界，不能生成轮末完成时间。

此次不改变协议、工具执行、阅读锁或 Working 的运行边界。Working 的当前优先级与可见性规则继续以 [DESIGN「会话正文」](../DESIGN.md#组件规则) 为准；组头的当前展示规则见 [DESIGN「思考与工具行」](../DESIGN.md#组件规则)。

## 组级运行提示修订（2026-10-16）

组头文字按队列展示，可能暂时停在已完成的调用，而后续调用仍在运行。若右侧图标只表示当前轮播调用的状态，Working 就会随轮播位置反复出现和消失，额外改变列表高度。经效果稿确认，右侧图标改为优先表达整组运行状态；具体展示边界以 [DESIGN「思考与工具行」](../DESIGN.md#组件规则) 为准。

本修订替代组头图标跟随当前轮播调用状态的规则，不改变调用队列、批次闭合、展开选择、各工具真实状态、阅读控制或正式 `run_end` 的完成确认语义。Working 仍在当前轮没有实际可见的具体运行提示时立即显示。

## 手动展开与字号层级修订（2026-10-16）

用户确认：较小字号只用于展开后的思考正文和工具明细，思考标题与工具组头保持与正式正文相同的 16px，展开内容为 14px。标题在展开与收起时保持同一字号。

手动展开运行中末段工具组时继续贴底，会把组头向上推，形成与思考向下展开不同的观感。手动展开工具组现统一暂停自动跟随，保持阅读位置；新调用和执行状态变化不恢复跟随，用户可通过「最新」恢复。此规则取代原决策中“运行中末段工具组的展开不暂停自动跟随”的例外；组选择继承、详情阅读器、组级运行提示与正式 `run_end` 语义不变。当前规格见 [DESIGN](../DESIGN.md#组件规则)。
