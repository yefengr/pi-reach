# ADR-20261111: 图标固定线宽与随字号放大、细指针按钮高度、卡片边界规则

- 状态：已接受
- 日期：2026-11-11
- 覆盖：DESIGN「基础层」图标的线宽 1.8 与 12 档线宽 2.4、「字号档位」中图标不缩放、「按钮尺寸」中常规按钮与文字按钮固定高 44、启动失败卡片与选择 Pi 可点行的 1px `line` 描边

## 背景

参照 iOS 复核图标、按钮与卡片三处规则时发现：

- 图标线宽按 24 画布的 1.8 等比缩放，16 图标实际约 1.2px、20 约 1.5px、24 为 1.8px。用得最多的 16 图标最细，又常与 600 字重的文字并排；12 的旋转图标已经单独把线宽补到 2.4，说明等比缩放本身需要例外才能成立。
- 图标不随字号档位放大。触控基准与大、特大档下正文为 17 到 21px，同行的图标仍是 16。
- 常规按钮一律高 44。44 是触控点击区的要求，纯细指针下偏高；菜单行已按「细指针 40、触控 44」区分，字号也已分为桌面与触控两套基准（[ADR-20261110](20261110-touch-type-scale.md)）。
- 卡片的边界没有统一规则：设置页分组只靠底色差，启动失败卡片与选择 Pi 的可点行是 `surface` 加 1px `line`（浅色下 `surface` 与 `bg` 同为白色，轮廓完全依赖描边），附件卡片是 `panel` 加 1px `line`。

## 决策

1. 图标以固定实际线宽 1.5px 绘制，各尺寸一致；取消 12 档的单独线宽，单个图标不再写 `strokeWidth`。
2. 行内图标（`size` 16）随字号档位放大为 16／18／20；图标按钮内的图标（`size` 20）在触控设备上为 22。TSX 仍只写 16／20／24，实际尺寸由 token 与样式决定，线宽同步换算，实际线宽不变。36 圆形视觉底与 44 点击区不变。
3. 纯细指针且可悬停时，常规按钮与文字按钮高 36；存在任一粗指针或不可悬停时保持 44，判定与菜单行一致。带触屏的笔记本按触控处理。图标按钮、输入框、菜单行与其他已登记的点击区不变。
4. 卡片按位置分为嵌入式与浮层两类：嵌入式只靠底色差成形，不描边、无阴影；浮层用发丝线 `edge` 外框。新增 `card` token（浅色 `panel`、深色 `surface`）作为 `bg` 上的卡片底，启动失败卡片与选择 Pi 的可点行改用它并去掉描边。
5. 用户气泡内的附件卡片保留 1px `line`，登记为例外：浅色下 `panel` 对 `message` 约 1.04:1，去掉描边后轮廓不可辨。只有底色差不足时才允许描边。
6. DESIGN 增加「卡片」一节，列出卡片类型、边界、底色与圆角。
7. 嵌入式卡片的底色、圆角与边界提取为公共样式类 `pwa-card`，设置页分组、启动失败卡片与选择 Pi 的可点行共用；不新增只转发属性的 React 包装组件，与「Mantine 复用边界」一致。

## 未采纳

- 按钮改为胶囊形：会牵动同心圆角规则以及所有弹窗与设置页，收益主要在风格。
- 输入框随按钮降到 36：输入框在移动端需保持 16px 字号与 44 高度，桌面单独调整留待后续评估；目前桌面表单中 44 的输入框与 36 的按钮上下排列，不在同一行内对齐。
- 以材质高亮代替按压缩放、导航大标题与底部标签栏：属于原生控件行为。

## 影响

- 桌面上按钮变矮，设置页分组内的操作、弹窗操作区与文字按钮的高度由 44 变为 36；触控设备不变。
- 16 图标的线条由约 1.2px 变为 1.5px，24 图标由 1.8px 变为 1.5px；大档与特大档下行内图标变大，固定宽度的图标槽位需容纳 20px。
- 浅色主题下启动失败卡片与选择 Pi 的可点行由白底描边变为浅灰底无描边。
- `pwa-script-token-guard` 校验脚本注入的线宽与主题 token 同值，并限制 `strokeWidth` 只引用全局常量；`pwa-style-guard` 校验卡片底只由公共规则引用。
- 浏览器测试中常规按钮的高度断言改为读取当前的 `--pwa-button-height`：Linux 无头 Chromium 关闭触控模拟后「存在粗指针」的状态不会复位，同一次运行里后续文件看到的按钮高度取决于运行顺序。
- 当前规则以 [DESIGN「基础层」](../DESIGN.md#基础层)、[「卡片」](../DESIGN.md#卡片)与[「按钮尺寸」](../DESIGN.md#按钮尺寸)为准。
