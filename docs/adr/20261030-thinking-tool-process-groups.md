# ADR-20261030: Thinking 与工具统一为过程组

- 状态：已接受
- 日期：2026-10-30
- 覆盖：[ADR-20261011](20261011-live-tool-grouping.md) 中关于 Thinking 断组、默认收起且只由用户控制、组头排队展示、右侧状态图标和展开明细 14px 的规则
- 部分被覆盖：决策 4 中明细行状态槽的含义由本文 2026-11-12 修订调整；决策 2 的自动收起时机与决策 6（Working 承载）由 [会话输出连续性 ADR](20261030-stream-output-continuity.md) 替代；决策 7 中跟随时的收起回落由 [ADR-20261031 动效分层](20261031-motion-layers-ios-spring.md#修订过程组先收起再出正文收起时组头原位2026-10-31)的组头原位规则替代

## 背景

[ADR-20261011](20261011-live-tool-grouping.md) 把相邻工具合成实时工具组，但 Thinking 仍是独立的可折叠行，并且会打断工具组。一轮输出常是"思考 → 工具 → 思考 → 工具"交替，结果被切成许多碎行。组头为了让每条调用都能被看到，按 0.8 秒排队轮播；状态图标在右侧，展开明细又改用 14px 字号，同一段过程里出现了两套折叠、两种字号和隐藏的计时器。

方案、效果稿和 R01—R04 的确认记录见 [Thinking 与工具展示统一重构实施方案](../plans/active/20261030-thinking-tool-process-groups.md)。

## 决策

1. 同一轮中展示相邻的 Thinking 与工具调用合成一个过程组。Pi 正文、用户消息、已发布文件、未保存缺口、本地压缩提示或跨轮会断开分组。组身份由稳定成员继承，增量更新、历史前插、拆分与合并都不重建已有组。
2. 运行中的组默认展开；只有收到本轮正式 `run_end` 才自动收起；首次加载的已结束历史直接收起。用户的手动选择按成员记录，优先于默认行为（R01）；Reader 打开或退出中、焦点位于明细内时，暂缓自动收起（R04）。默认展开不暂停自动跟随，只有手动展开和打开阅读器才保持阅读位置。
3. 收起时，组头显示最后开始且仍有效的成员，并用"+N"计数其他运行中的工具（R02）；展开时，或没有当前活动时，组头显示分类摘要。删除组头排队、轮播计时器和文字进入动画。
4. 左侧固定 16px 状态槽表达真实状态，右侧计数提示不重复状态槽已表达的同一状态；组头与明细同字号，相邻明细之间用短竖线连接。Thinking 的槽位不伸缩，标题不横移；保留标题解析与 120ms 有界摘要合并。
5. 有正文的 Thinking 打开与工具详情同款的 Reader（R03）。时间线不再展开 Thinking 正文；正文为空的历史痕迹保持静态行。
6. 当前过程组成员有可见的具体运行图标时，不显示通用 Working。否则由末段过程组的组头原位承载 Working；没有合适的组时，在时间线末尾兜底。正文、本地提示等硬边界之后，不把 Working 挂回较早的组；单个空痕迹不承载 Working。
7. 视口新增"过程组开始收起"的几何通知：跟随中的自动收起，与同一次提交里出现的完成时间合并，按净高度处理，不先为新增内容向下追赶。回看时，原位置可达则保持不动；下方内容不足导致原位置不可达时，内容随收起平滑下移一次，不保留占位。契约细节见方案第 10.5 节。

## 影响

只有正式 `run_end` 能确认整轮结束，这一语义沿用 [ADR-20260930](20260930-strict-run-completion.md)：工具全部结束、后续正文、离线或 `working=false` 都不能替代它，也不补造完成时间。

只改 PWA 展示和视口协调：不改协议、Relay、Extension、投递、运行时状态或持久化。当前视觉与交互规格以 [DESIGN](../DESIGN.md#组件规则) 为准。

## 备选方案

- 保留独立 Thinking 行，只把工具合组：交替输出仍被切碎，Working 的归属也难以判断，不采用。
- 运行中默认收起，只显示组头：看不到并行和刚完成的调用，又需要重新引入轮播，不采用。
- 往回看且原位置不可达时，用临时底部空白暂时保住位置：空白不能长期保留，释放时内容照样移动，只会多出一次停顿，不采用。

## 思考标题并入组头与自动收起节奏修订（2026-10-31）

真机录屏复核发现三处问题：自动收起以 140ms 标准曲线播放，曲线前段很陡，明细约 60ms 内淡出、高度在一帧内回落约 60px，同时组头文案替换、正文出现，观感生硬；被同轮后续输出取代、但仍处于流式状态的思考被判为状态未知，组头追加「1: 状态未知」与提示图标；运行中的思考同时显示组头「Thinking」、斜体标题行与两行预览三层，标题与预览内容重复。

用户确认以下修订：

- 运行中的当前思考无论组是否展开都由组头显示其标题，明细中该思考只保留两行尾部预览，预览整块作为阅读入口；思考结束后标题回到明细行；组内已有其他成员时，新思考有了文字才接管组头，不先以「Thinking…」占位替换摘要。没有工具的组收起后显示最后一个有正文的思考标题，不再退回「Thinking」；展开时与工具组一致显示分类摘要。本条修订决策 3 中“展开时，或没有当前活动时，组头显示分类摘要”的规则。
- 系统自动收起（正文接续或本轮结束）改用 320ms（第三轮真机复核后由 260ms 调整）：高度、透明度与位移同用对称曲线，内容边淡出边收拢，退出期间冻结收起前最后呈现的内容，组头文案在收拢后再切换；手动收起保持 140ms 的直接反馈。决策 7 的几何通知按实际退出时长计算保持期。
- 同轮后续输出已出现的流式思考按已结束（中性）处理，不计为状态未知；离线、空闲残留与旧轮 partial 仍为未知。

状态槽图标的取舍另行评估，本修订不改变决策 4。当前规格见 [DESIGN](../DESIGN.md#组件规则)。

## 明细行距与单行思考预览修订（2026-11-01）

用户复核后确认两处收紧：

- 过程组明细行之间的 6px 间隔取消，44px 行紧邻排列，行距由 50px 降为 44px；点击区不变，相邻图标之间的竖线仍居中于 28px 断口。
- 运行中思考的尾部预览由两行改为一行：换行合并为空格；放得下时左对齐，放不下时最新内容贴右、左缘渐隐。思考结束时预览收起带来的高度变化随之变小。本条取代上文修订中「明细中该思考只保留两行尾部预览」与[会话输出连续性 ADR](20261030-stream-output-continuity.md) 决策 5 的两行预览。

## 明细图标表示工具类型与桌面行高修订（2026-11-12）

展开的过程组里每个成功调用都显示同一个绿色对勾，组头再多一个；结束后的组几乎全是成功，一列相同图标不提供信息，也掩盖了真正需要关注的失败。同时工具类型已在展示层分类，却没有呈现；明细行直接显示原始工具名（`read`、`bash`），与组头本地化的分类摘要说法不一致，路径从仓库根写起，窄屏省略时先截掉文件名。

参照 Claude 的工具调用列表（图标表示做了什么、成功不额外标记、文案为动词＋对象），用户确认以下修订：

- 明细行左侧图标改为表示工具类型：成功时为中性色类型图标；运行中、准备中、失败、中断与未知仍换成对应状态图标，失败的图标与动词用错误色。决策 4 中「左侧状态槽表达真实状态」对明细行改为「异常时表达状态」，组头状态槽不变，但整组完成的对勾改用中性色。
- 明细行与收起组头的工具文案改为动词＋对象；路径先显示文件名，目录随后并最先省略；原始工具名保留在悬停提示、可访问名称与阅读器标题中。
- 修改工具真实返回 diff 时显示增删行数，没有 diff 不显示，不从请求参数推算。
- 纯细指针且可悬停时明细行高由 44 降为 36，与常规按钮同一判定；触控与混合输入保持 44，组头始终 44；相邻图标之间的竖线随行高缩短并保持居中。

未采用：连续同类调用合并为一行（需要第二层折叠，违背单层总折叠）；明细文字缩小一档（保留组头与明细同字号）。当前规格见 [DESIGN](../DESIGN.md#组件规则)。
