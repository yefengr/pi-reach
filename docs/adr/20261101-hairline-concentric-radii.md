# ADR-20261101: 发丝线分隔、滚动边缘与同心圆角

- 状态：已接受
- 日期：2026-11-01
- 覆盖：[DESIGN「嵌套、圆形与胶囊」](../DESIGN.md#嵌套圆形与胶囊)原有的「嵌套不递减」规则，以及 Composer 圆角 16、浮层面板圆角 8 与内边距 6；次级按钮「surface＋1px line」、危险入口「错误色轮廓」与状态标签「只用描边」的外观；[ADR-20261028](20261028-square-navigation-and-drawers.md) 中底部电脑选择 Drawer 的直角规则

## 背景

[动效分层 ADR](20261031-motion-layers-ios-spring.md) 让内容与空间变化参照 iOS 弹簧之后，界面静态部分与 iOS 还有三处差异：

1. 装饰分隔全部是 1px 不透明 `line`，在 3 倍屏上是 3 个物理像素，落在 `bg`、`panel`、`message` 上浓淡不一。
2. 移动会话标题区与设置页固定顶栏没有分隔，内容滚到下方时被硬切；电脑选择 Drawer 头部又始终带分隔。
3. 小内边距下的嵌套圆角不同心：Composer 外框 16，底部半径 18 的圆形按钮比外角还圆；浮层面板 8 内放 8 的菜单行，原规则以「嵌套不递减」回避了公式算出的 2。

间距档位、gutter、阅读列宽与点击区已与 iOS 一致，不在本次调整范围。方案与对比原型见内部方案 [边框、分隔与圆角参照 iOS 的调整](../plans/active/20261101-ios-borders-spacing.md)。

## 决策

1. 新增 `--pwa-hairline` 与半透明中性色 `--pwa-separator`，分两档：默认 1px 配常规分隔色（浅色 `#0000001F`、深色 `#FFFFFF2E`，叠在 `bg` 上与原 `line` 同深）；首屏前实测浏览器画得出 0.5px 时改为 0.5px 配发丝线档（浅色 `#00000033`、深色 `#FFFFFF3D`）。Chromium 会把 0.5px 边框画成 1 个 CSS 像素，按屏幕密度直接启用会让 Chrome 系浏览器的线更重，因此只按实测结果切换。装饰分隔、浮层与 Composer 外框改用发丝线；输入控件轮廓、次级按钮、只靠描边成形的标签与图标块、选中描边、焦点与状态色边框保持 1px。
2. 列表行间分隔：有外框的容器左右对称缩进、不碰外框；无外框的分组按 iOS 只缩进左侧。
3. 固定顶栏只在下方滚动容器离开顶部时显示发丝线分隔。滚动状态由已有的全局滚动监听写入 `data-scroll-edge`，不另起监听。
4. 「嵌套不递减」改为「同心」：子表面到外缘的距离不大于 16 时，外圆角 = 内圆角 + 距离，只放大外圆角。浮层面板改为圆角 12、内边距 4；Composer 圆角改为 32。距离更大的 Modal 等表面不要求同心。

## 影响

- WebKit 高分屏（iOS、macOS Safari）上分隔与外框变轻；Chrome 系浏览器与 1 倍屏线宽和深浅与原 `line` 一致。发丝线档的可见度（尤其深色 `#FFFFFF3D`）在 Safari 与 iOS 真机验收。
- 浮层内边距 6 → 4，菜单文字到面板边缘由 16 变为 14；DESIGN 间距细档表删除「浮层面板内边距 6」。
- 样式守卫新增发丝线 token 与「发丝线只配分隔色」的检查，Composer 圆角期望改为 32；对比度测试校验两档分隔色为半透明中性色、常规档与 `line` 同深；浏览器测试覆盖检测探针与档位切换。
- 设置页分组列表见下方补充决策。
- 当前规则以 [DESIGN](../DESIGN.md) 为准。

## 补充决策：设置页分组列表与跨平台取舍（2026-11-01）

评审中明确：Pi Reach 是网页应用，借鉴平台的规则而不照搬外观。取舍依次看全平台是否成立或能平稳退回、是否符合阅读优先与信息密度、是否有跨平台共识（iOS 26 与 Material 3 都这么做）、维护成本是否可控；现有规则不合理时直接推翻。

1. 设置页各分区改为分组列表：标题在上、`surface` 圆角 12 的分组、说明移到分组下方；页面底为新增别名 `--pwa-grouped-bg`（浅色 `panel`，深色 `bg`）。单选保留行首可见的单选圆点，不采用 iOS 的行尾对勾与隐藏 radio；操作仍是按钮，不改为彩色文字操作行。
2. 次级按钮改为无边框的 `tonal` 色调底：浅色下 `surface` 与 `bg` 同为白色，原先只靠 1px 细边识别。危险入口（`outline` 变体，语义不变）改为无边框的 `error-wash` 底与错误色文字。
3. 状态标签改为 `tonal` 底的胶囊，部分在线用运行轻底；「最新」浮动入口改为胶囊；Toast 圆角 22，与其圆形关闭按钮同心。行内按钮保持 8，不做胶囊。
4. 用户消息气泡圆角 8 → 16。
5. 底部电脑选择面板上沿圆角 16，贴屏幕的下沿为直角；侧栏、移动导航与阅读器 Drawer、设置页仍按 ADR-20261028 为直角。底部弹出的非全屏面板带上沿圆角是 iOS 与 Android 的共同做法。
6. 不采纳：毛玻璃材质（PWA 长列表的 `backdrop-filter` 性能成本、各平台效果不一）、连续曲率圆角（Safari 支持未核实）、顶栏渐隐（内容不在顶栏下方滚动）、所有按钮胶囊与设置分组加大到 20 以上（开发工具重信息密度）。

影响：新增 `tonal` 三档、`error-wash-hover`、`--pwa-radius-xl`（16）、`--pwa-radius-toast`（22）与 `--pwa-radius-pill`；专用圆角由样式守卫按选择器登记。对比度测试覆盖 `ink`、`secondary` 在 `tonal` 上与 `ink` 在悬停、按下档上 ≥ 4.5:1。

## 补充决策：滚动边缘改为内容渐隐（2026-11-01）

决策 3 实施后在桌面评审：会话主区是悬浮的圆角卡片，长会话停在底部时，标题区下的发丝线几乎常亮，横穿阅读列两侧留白，把卡片切成上下两块，在 Chromium 上还按 1px 显示，偏重。移动端观感可以接受，但两端应保持一致；输入区上沿与标题区下沿是同一类硬切，也应一并处理。

1. 决策 3 的发丝线改为内容渐隐：滚动容器离开顶部时，内容在顶栏下沿 24px（`--pwa-scroll-fade`）内由顶栏底色渐变到透明，桌面与移动一致，适用范围不变（会话主区、移动设置页、电脑选择 Drawer、工具与文件阅读器）。滚动状态仍由 `data-scroll-edge` 提供。
2. 消息列表底部在输入区上沿加常驻渐隐。列表上下留白不小于渐隐高度，停在边缘时只盖住留白，不新增「离开底部」状态；紧凑高度下留白不足，不加。
3. 渐变用顶栏或输入区伪元素上的纯色渐变，不用 `mask-image`：移动设置页顶栏位于自身滚动容器内，对容器加遮罩会连顶栏一起淡化；纯色渐变不额外占用合成层。会话标题区与消息列表之间夹着提示区，渐变挂在提示区下沿；不用列表内的 sticky 伪元素，因为 sticky 偏移从列表顶部留白之下算起，渐变会离开顶栏下沿（真机录屏中紧贴顶栏的一行被硬切）。
4. 与补充决策 6「不采纳顶栏渐隐」的关系：被否决的是让内容在半透明顶栏下方滚动的做法，前提「内容不在顶栏下方滚动」不变；本次顶栏仍为实色，只在滚动区边缘淡化内容，因此不需要改变布局或引入材质。

影响：渐变起点必须与顶栏底色一致。电脑选择 Drawer 头部原取 Mantine `body`（`bg`），深色下比面板 `surface` 深一档，改为 `surface`。浏览器测试按浅色与深色核对四处渐变起点色与顶栏底色一致、首条消息不被推开、紧凑高度下不加底部渐隐。iOS Safari 真机上长会话滚动的流畅度与渐隐观感待验收。
