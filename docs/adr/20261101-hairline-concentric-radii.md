# ADR-20261101: 发丝线分隔、滚动边缘与同心圆角

- 状态：已接受
- 日期：2026-11-01
- 覆盖：[DESIGN「嵌套、圆形与胶囊」](../DESIGN.md#嵌套圆形与胶囊)原有的「嵌套不递减」规则，以及 Composer 圆角 16、浮层面板圆角 8 与内边距 6；次级按钮「surface＋1px line」、危险入口「错误色轮廓」与状态标签「只用描边」的外观；[ADR-20261028](20261028-square-navigation-and-drawers.md) 中底部电脑选择 Drawer 的直角规则
- 后续调整：见[决策记录索引](20260518-closed-decisions.md#决策记录索引)。

> 原型清理（2026-11-13）：旧评审原型已从当前目录移除，下方链接固定到删除前提交的历史源码。原决策与后续取代关系保持不变，当前规则仍以 DESIGN 和后续 ADR 为准。

## 背景

[动效分层 ADR](20261031-motion-layers-ios-spring.md) 让内容与空间变化参照 iOS 弹簧之后，界面静态部分与 iOS 还有三处差异：

1. 装饰分隔全部是 1px 不透明 `line`，在 3 倍屏上是 3 个物理像素，落在 `bg`、`panel`、`message` 上浓淡不一。
2. 移动会话标题区与设置页固定顶栏没有分隔，内容滚到下方时被硬切；电脑选择 Drawer 头部又始终带分隔。
3. 小内边距下的嵌套圆角不同心：Composer 外框 16，底部半径 18 的圆形按钮比外角还圆；浮层面板 8 内放 8 的菜单行，原规则以「嵌套不递减」回避了公式算出的 2。

间距档位、gutter、阅读列宽与点击区已与 iOS 一致，不在本次调整范围。方案与对比原型见内部方案 [边框、分隔与圆角参照 iOS 的调整](../plans/active/20261101-ios-borders-spacing.md)。

## 决策

1. 新增 `--pwa-hairline` 与半透明中性色 `--pwa-separator`，分两档：默认 1px 配常规分隔色（浅色 `#0000001F`、深色 `#FFFFFF2E`，叠在 `bg` 上与原 `line` 同深）；首屏前实测浏览器画得出 0.5px 时改为 0.5px 配发丝线档（浅色 `#00000033`、深色 `#FFFFFF3D`）。Chromium 会把 0.5px 边框画成 1 个 CSS 像素，按屏幕密度直接启用会让 Chrome 系浏览器的线更重，因此只按实测结果切换。装饰分隔、浮层与 Composer 外框改用发丝线；输入控件轮廓、次级按钮、只靠描边成形的标签与图标块、选中描边、焦点与状态色边框保持 1px。
2. 列表行间分隔：有外框的容器左右对称缩进、不碰外框；无外框的分组按 iOS 只缩进左侧。
3. 固定顶栏只在下方滚动容器离开顶部时显示发丝线分隔。滚动状态由已有的全局滚动监听写入 `data-scroll-edge`，不另起监听。
4. 「嵌套不递减」改为「同心」：子表面到外缘的距离不大于 16 时，外圆角 = 内圆角 + 距离，只放大外圆角。浮层面板改为圆角 12、内边距 4；Composer 圆角改为 32。距离更大的 Modal 等表面不要求同心。

## 影响

- WebKit 高分屏（iOS、macOS Safari）上分隔与外框变轻；Chrome 系浏览器与 1 倍屏线宽和深浅与原 `line` 一致。发丝线档的可见度（尤其深色 `#FFFFFF3D`）在 Safari 与 iOS 真机验收。
- 浮层内边距 6 → 4，菜单文字到面板边缘由 16 变为 14；DESIGN 间距细档表删除「浮层面板内边距 6」。
- 样式守卫新增发丝线 token 与「发丝线只配分隔色」的检查，Composer 圆角期望改为 32；对比度测试校验两档分隔色为半透明中性色、常规档与 `line` 同深；浏览器测试覆盖检测探针与档位切换。
- 设置页分组列表见下方补充决策。
- 当前规则以 [DESIGN](../DESIGN.md) 为准。

## 补充决策：设置页分组列表与跨平台取舍（2026-11-01）

评审中明确：Pi Reach 是网页应用，借鉴平台的规则而不照搬外观。取舍依次看全平台是否成立或能平稳退回、是否符合阅读优先与信息密度、是否有跨平台共识（iOS 26 与 Material 3 都这么做）、维护成本是否可控；现有规则不合理时直接推翻。

1. 设置页各分区改为分组列表：标题在上、`surface` 圆角 12 的分组、说明移到分组下方；页面底为新增别名 `--pwa-grouped-bg`（浅色 `panel`，深色 `bg`）。单选保留行首可见的单选圆点，不采用 iOS 的行尾对勾与隐藏 radio；操作仍是按钮，不改为彩色文字操作行。
2. 次级按钮改为无边框的 `tonal` 色调底：浅色下 `surface` 与 `bg` 同为白色，原先只靠 1px 细边识别。危险入口（`outline` 变体，语义不变）改为无边框的 `error-wash` 底与错误色文字。
3. 状态标签改为 `tonal` 底的胶囊，部分在线用运行轻底；「最新」浮动入口改为胶囊；Toast 圆角 22，与其圆形关闭按钮同心。行内按钮保持 8，不做胶囊。
4. 用户消息气泡圆角 8 → 16。
5. 底部电脑选择面板上沿圆角 16，贴屏幕的下沿为直角；侧栏、移动导航与阅读器 Drawer、设置页仍按 ADR-20261028 为直角。底部弹出的非全屏面板带上沿圆角是 iOS 与 Android 的共同做法。
6. 不采纳：毛玻璃材质（PWA 长列表的 `backdrop-filter` 性能成本、各平台效果不一）、连续曲率圆角（Safari 支持未核实）、顶栏渐隐（内容不在顶栏下方滚动）、所有按钮胶囊与设置分组加大到 20 以上（开发工具重信息密度）。

影响：新增 `tonal` 三档、`error-wash-hover`、`--pwa-radius-xl`（16）、`--pwa-radius-toast`（22）与 `--pwa-radius-pill`；专用圆角由样式守卫按选择器登记。对比度测试覆盖 `ink`、`secondary` 在 `tonal` 上与 `ink` 在悬停、按下档上 ≥ 4.5:1。

## 补充决策：设置页单选改为行尾对勾，分隔线左右对称（2026-11-01）

真机评审认为：单选行同时有行首圆点和图标，信息重复，语言分组中「中文」「English」甚至共用同一图标；分组内行间线只缩进左侧、右端贴边，在圆角分组中显得不平衡。推翻上文补充决策第 1 条中「保留行首单选圆点、不采用行尾对勾」与正文决策第 2 条中「无外框分组只缩进左侧」：

1. 设置页单选行保留行首图标，去掉单选圆点；选中项在行尾显示 `accent` 对勾（与 iOS 一致）。原生 radio 透明铺满整行，读屏、方向键切换与表单语义不变，键盘聚焦时整行显示焦点轮廓。
2. 列表行间分隔统一左右对称缩进、不碰容器边缘：排队面板等有外框的容器各 12，设置页分组各 16。这是对 iOS 与 Material「只缩起始侧」惯例的有意偏离（见 [参照 iOS 的原则](20261101-ios-reference-structure-not-material.md)第 3 条）：圆角分组中对称留白更平衡，也与有外框容器的规则统一。

当前规则以 [DESIGN「设置页」](../DESIGN.md#设置页)为准。

## 补充决策：消息列表与输入框圆角重叠并渐隐（2026-11-02）

真机评审发现消息正文在输入框卡片上方约 10px 处被硬切，切口与卡片边框不对齐。此前把顶栏与输入区上沿一起改为内容渐隐后又整体撤销；本次只处理输入区一侧，顶栏仍用滚动后出现的发丝线：

1. 输入框卡片位于输入区最上方时，列表延伸到卡片上沿以下一个 Composer 圆角高度，自卡片上方 24 起画「透明 → 底色」渐变，正文从圆角两侧滑到卡片下方并淡出；列表底部留白同步加长，停在底部时内容不进入渐隐。
2. 卡片上方有排队面板、提示行或附件时不重叠，只在输入区上沿之上挂同样高度的渐隐：提示文字没有底色、附件之间有空隙，重叠会透出正文。紧凑高度下都不加。
3. 不让列表完整伸到输入区下方：输入区高度随草稿、排队、附件与提示变化，需要实时同步留白，并牵涉贴底跟随、「最新」入口与 iOS 键盘，风险过高。这也是在不使用玻璃材质的前提下（见[参照 iOS 的原则](20261101-ios-reference-structure-not-material.md)）对「内容在输入栏下方」的近似。

当前规则以 [DESIGN「组件规则」](../DESIGN.md#组件规则)的 Composer 条目为准。

## 补充决策：附件进入输入框卡片，排队消息收进卡片后方的抽屉（2026-11-05）

真机评审发现两处问题。一是上一节第 2 条只在输入框卡片位于最上方时让正文滑入卡片下方；有排队、提示或附件时，正文先淡出到底色，再隔一段空白才到面板，两种衔接不一致。二是附件与排队各有一套折叠规则与按钮，展开与收起都没有过渡。比较了四种结构后，选定下面的方案：

1. 附件属于待发送的草稿，放进输入框卡片内，位于文本框上方；卡片聚焦边框同时覆盖附件。附件以 72px 方块单行横排，桌面与手机一致，横向滚动、不折叠；方块上不显示文件名，改由 Tooltip 与读屏文字提供；上传进度改为方块中央带百分比的圆圈。
2. 排队消息已经发出，不进入卡片，收在卡片后方的抽屉里：抽屉左右各内缩 8，下沿压在卡片之后，自带附件只显示回形针计数。抽屉不再只露前几条、再用「还有 N 条」展开，所有条目在固定最大高度内滚动；两条以上时标题行整行可折叠整个列表，折叠后有未确认条目时标题行显示告警。
3. 提示行说明的是当前能否发送，放在卡片内顶部，不放进抽屉，以免和排队消息混在一起。提示与附件都在卡片内，因此最上方的不透明表面只有排队抽屉（圆角 16）和输入框卡片（圆角 32）两种，任何组合都能重叠衔接。上一节第 2 条的“不重叠、只挂渐隐”由此取消。
4. 输入区高度只在增减时一次到位，不逐帧过渡，这条取代原「输入区内的增减即时完成」：评审中试过提示行的高度过渡，但提示常在会话打开与历史前插时变化，逐帧改变输入区高度会拖慢时间线的锚点补偿，使「加载更多」被加载动画替换。动效改由位移与透明度承担：进入的元素滑出或淡入；离开的元素当场脱离布局、高度随即收回，副本在原位滑回或淡出后再移除，发送过渡期间也不例外，避免离开内容瞬间消失。排队抽屉从卡片背后滑出、滑回；抽屉内单条消息与单个附件方块淡入、原位淡出；移除最后一件附件时整行原位淡出后再收回高度；只有发送过渡中的交接（随消息提交的附件、期间结束的提示）直接移除，内容已由气泡承接，原位副本会在输入区回缩时叠到正文上。整段列表的展开与折叠由用户主动触发，按过程组折叠的规格过渡。

没有采用的方案：附件与排队各自一块独立面板，虽然结构统一，但同时出现时占去半屏，只有提示行时仍是旧衔接；三者都放进输入框卡片，会让已发出的排队消息看起来像草稿的一部分；三者合成一块抽屉，折叠后附件可能整组被藏起来，草稿与已发出的消息也混在同一个列表里。

评审原型见 [`docs/prototypes/20261104-composer-tray/`](https://github.com/yefengr/pi-reach/blob/2c4e9f635bfef87d46c915d65a43200ee2b4dd60/docs/prototypes/20261104-composer-tray/page.html)。当前规则以 [DESIGN「组件规则」](../DESIGN.md#组件规则)的 Composer 与会话附件条目和[「动效」](../DESIGN.md#动效)为准。
