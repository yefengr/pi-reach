# ADR-20260929: 桌面侧栏收展入口移至品牌行与标题区

- 状态：已接受
- 日期：2026-09-29

## 背景

[品牌刷新方案](../plans/active/20260925-pi-reach-brand-refresh.md)原规定桌面侧栏收展箭头位于垂直 40% 处：展开时在侧栏内部靠右，收起后停在主区左侧同一高度。

2026-09-29 的界面对照审查（S2）实测：1280×844 下按钮占 `x=212–256, y=338–382`，与本地历史行（`x=8–252`）右侧约 40×30px 重叠。按钮绝对定位于可滚动列表之上，点击重叠区会收起侧栏而不是打开该历史；列表长度和滚动位置不同，被覆盖的行也随之变化。横屏等矮视口下还会覆盖在线 Pi 行。

备选方案：

- 保留位置，列表右侧让出约 40px：所有会话名、历史名可用宽度从约 244px 降至约 204px，截断更多。
- 移到侧栏与主区交界外侧：不挤压列表，但占用主区左侧留白，窄桌面下靠近正文。
- 移到侧栏品牌行：与 ChatGPT、Claude.ai、Linear 等常见做法一致，完全离开列表区域。

## 决策

1. 展开时，收展箭头位于侧栏品牌行右端（与侧栏 `8px` 内边距对齐），与「Pi Reach」标识同一行。
2. 收起后，箭头停在会话标题区左端（距主区左缘 `8px`），与会话标题同一行；标题区左侧留白改为 `56px`（`8 + 44 + 4`）为按钮让位。
3. 箭头成对（`ChevronLeft`／`ChevronRight`）、无常态外框、`44px` 点击区、`220ms` 标准曲线水平移动等其余规则不变；移动端仍不显示该入口。

## 后果

- 收展入口不再与导航列表重叠，任何列表长度、滚动位置和矮视口下都不拦截导航行点击。
- 收起态会话标题比原先向右偏移 36px，这是由按钮推导出的局部尺寸，不计入间距档位。
- 覆盖品牌方案「工作区」中「中部偏上」与 DESIGN「垂直 40% 处」的描述；两处已同步更新。
