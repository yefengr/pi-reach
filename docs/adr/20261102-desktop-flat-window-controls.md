# ADR-20261102: 桌面平铺工作区与窗口控件融合

- 状态：已接受
- 日期：2026-11-02
- 后续调整：2026-11-03，[ADR-20261103](20261103-native-titlebar-floating-sidebar.md) 取代本文的窗口控件融合、贯通侧栏及交界分隔规则；桌面主区平铺、双行标题与消息／Composer 圆角继续有效。下文保留当时决策和验收背景，不作为恢复 WCO 的授权。

## 背景

桌面主区原为侧栏底色中的内嵌圆角卡片。它曾用轮廓区分侧栏和阅读区，但也带来四周的色带，以及品牌行与会话名首行之间的 8px 高度差。侧栏收起时，主区还需要同时改变外边距、圆角和安全区承担方式。

本次确认改为平铺工作区，并在支持的已安装桌面 PWA 中使用 Window Controls Overlay，让系统窗口控件与应用顶部共处一行。不采用横跨侧栏与主区的公共工具栏，导航和会话标题仍分别属于各自区域。

## 决策

1. 桌面侧栏内容宽度由 260px 调整为 280px，左安全区另计，为系统窗口控件、品牌与侧栏收展入口提供空间。侧栏继续贯通全高、无圆角、无阴影。
2. 桌面主区无论侧栏收展均贴边：外边距和外层圆角为 0，不加阴影。保留消息气泡、Composer、菜单等具体内容与操作表面的圆角，不把平铺理解为取消所有圆角。
3. 侧栏沿用 `panel` 底，主区沿用 `bg` 底。桌面交界增加 `var(--pwa-hairline) solid var(--pwa-separator)` 分隔，宽度与颜色复用现有检测和主题 token，不新增色值。移动导航不增加这条分隔。
4. 会话标题保留上下两行：名称在上，工作目录最后一级在下；标题区最小高 64px，首行沿用 48px 操作带，大字号允许自然撑高。品牌、侧栏收展入口与会话名首行对齐。桌面右侧只保留连接状态和刷新，不新增会话信息的替代入口；移动端原有信息入口保持。
5. manifest 以 `display_override` 声明 `window-controls-overlay`，保留 `display: standalone` 回退。是否启用应用避让由浏览器实际能力、可见状态、有效几何和桌面布局共同决定；全屏和移动布局不启用这项增强。
6. 顶部避让以浏览器报告的可用矩形为准，覆盖左侧和右侧窗口控件，不按平台名称推断、不固化原型里的像素占位。几何、尺寸、断点及全屏状态变化后重新计算，失效或卸载时清除旧状态。
7. 仅顶部空白区域用于拖动窗口；按钮、输入和可选择的标题文字不接管拖动。设置页、阅读器及其他顶边叠层也要避开系统控件，不改变原有 Portal、焦点和关闭规则。

## 替代关系

本记录取代 [ADR-20261010](20261010-desktop-inset-main.md) 关于桌面主区内嵌卡片、8px 外边距及其标题错位的规则，也取代 [ADR-20261011](20261011-collapsed-sidebar-flush-main.md) 关于仅收起时贴边及外壳插值的规则。保留侧栏收展偏好、焦点隔离和阅读位置保持；抽屉与页面的直角规则不变。

## 安装态验收补充

首次测试环境验收显示：浏览器的原生标题栏展开／合并开关正常，但合并态的原生控件背景与侧栏 `panel` 出现接缝，应用按 48px 首行排版也没有对齐较矮的原生标题带。原型将模拟红绿灯画在侧栏背景上，未体现浏览器的原生绘制边界；只验证左右避让不足以证明视觉融合。

据此补充第 3、4 条：仅融合态的原生标题带对应区域统一使用与 `theme-color` 一致的 `bg`，侧栏主体继续使用 `panel`；视觉内容按实际原生带中线对齐，44px 命中区独立保留且不得移出窗口。两列和控件归属不变，不引入公共工具栏。原生带过小、安全区或内容无法兼容时沿用局部下移回退，具体度量与反馈规则维护在 DESIGN。

## 后果与验证边界

- 收展侧栏只改变横向空间，主区不再切换卡片形态；阅读列和 Composer 的宽度上限不变。
- 普通浏览器和不支持 Overlay 的安装窗口仍使用新的平铺布局，只是不把应用内容融合进原生标题栏。
- 系统窗口按钮和浏览器自带的扩展按钮仍由浏览器绘制。页面不能将其隐藏，必须尊重实际占位。
- 自动化可以覆盖几何、生命周期、点击区和回退，不能证明真实安装窗口的原生绘制、拖动或控件交接；这些仍需安装态验收。

当前尺寸和组件使用规则统一维护在 [DESIGN](../DESIGN.md#布局与导航)。
