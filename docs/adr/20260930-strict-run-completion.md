# ADR-20260930: 只以 run_end 确认运行结束

- 状态：已接受
- 日期：2026-09-30

## 背景

[ADR-20260927](20260927-run-end-event.md) 引入了正式 `run_end` 事件，同时保留旧 Extension 和旧历史的完成推断：出现下一轮或 Pi 空闲时，PWA 可以把上一轮判定为结束。这会让实时交付缺失被展示层掩盖，也使实时与历史使用不同的完成依据。

本决策取消这些推断。实时与历史均只读取已收到的正式结束事件，不新增兼容路径。

## 决策

- 只有对应 `group_id` 的正式 `run_end` 能确认该轮结束，完成时间与状态均取该事件。
- `working=false`、后续一轮的正式事件或 partial、工具全部成功，均不能替代 `run_end`。`working` 仍用于运行状态、停止操作和后台完成提醒。
- 工具摘要沿用同组、展示相邻、至少两条成功工具及无同组流式内容的条件；不通过清空 partial 或放宽 scope、序号校验隐藏交付问题。
- Extension 在 SDK 消息持久化后按正式序号发布事件，并在本次运行的正式消息之后发布 `run_end`。session 或 branch 替换仍按现有 reset、同步与隔离规则处理。

## 影响

本决策覆盖 ADR-20260927 中没有 `run_end` 时的降级规则；事件 shape、`protocol_version: 2` 和 `working` 的整次运行语义不变。

缺少 `run_end` 的历史仍可阅读，但不显示推断的轮末完成时间，也不合并工具摘要。不迁移历史、不补造事件、不清空本地数据。断线后的正式历史恢复继续使用现有 `session_sync`，它不推断运行结束。

## 备选方案

保留旧数据推断或在前端补造结束状态均不采用：完成信号缺失时应修复事件交付，而不是通过展示规则掩盖问题。
