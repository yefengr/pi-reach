# ADR-20261105: 输入区浮于消息列表之上，连接与只读状态移入输入区

- 状态：已接受
- 日期：2026-11-05
- 覆盖：[ADR-20261101](20261101-hairline-concentric-radii.md) 补充决策「消息列表与输入框圆角重叠并渐隐（2026-11-02）」第 3 条，以及补充决策「附件进入输入框卡片，排队消息收进卡片后方的抽屉（2026-11-05）」第 4 条；[DESIGN「反馈呈现」](../DESIGN.md#反馈呈现)中连接提示条、标题区连接状态、局部错误条与安装提示的呈现位置
- 后续调整：见[决策记录索引](20260518-closed-decisions.md#决策记录索引)。

## 背景

附件移入输入框卡片、排队消息收进卡片后方的抽屉之后，输入区的高度仍随草稿、排队、附件与提示变化，消息列表的可视高度随之改变：提示或附件出现时卡片上沿瞬间跳动，抽屉进出时正文整块跳动，而抽屉的滑动仍在播放。为不拖慢时间线的锚点补偿，输入区高度只能一次到位，动画只能用位移与透明度。

主区顶部也有同类问题。连接提示条、局部错误条与运行时提示条都占布局，出现或消失时把正在阅读的正文推开；三者的底色、边框、图标与关闭方式各不相同。连接状态同时出现在标题区状态、提示条与恢复后的 Toast 三处；Toast 的位置跟随提示区下沿；矮窗口下还要逐条压缩提示条。

## 决策

### 输入区浮层

1. 输入区浮在消息列表之上，不再占用列表高度。列表底部留白随输入区实际高度同步，最后一条消息仍能完整滚到输入区上方。
2. 回看时（未停在最新输出处），抽屉、附件、提示进出，正在阅读的内容不动，被输入区盖住即可，正文从输入区下方穿过。
3. 停在最新输出处跟随时，输入区变高，内容随抽屉、提示的过渡逐帧贴底；不跟随会让排队抽屉挡住仍在流式输出的最新内容，下一次输出时还会一次性跳回底部。
4. 列表可视高度不再随输入区变化后，抽屉、提示行与附件行的增减改为高度过渡；草稿换行引起的增高仍一次到位，不让输入拖尾。

### 顶部提示

5. 主区顶部不再有占布局的提示条：连接提示条删除；局部错误改为标题区下方的浮动卡片；PWA 安装提示移到侧栏与移动导航底部、电脑入口附近；浏览器能力不支持的提示仍在应用壳顶层（此时没有工作区）。
6. 局部错误卡片与 Toast 同族：`surface` 底、浮层阴影加 `edge` 发丝线、Toast 圆角，只给错误图标着色，正文保持中性色，带圆形关闭按钮；文字换成两行时圆角改为 16。卡片持续显示，直到用户关闭或切换会话；与 Toast 同时出现时错误卡片在上、Toast 在下。卡片盖住列表顶部一条正文，列表顶部留白同步加长并补偿滚动位置，正文不动且仍能滚出来。
7. Toast 固定在标题区下方，不再跟随提示区下沿。

### 标题区

8. 标题区布局与底色不变，不改为浮层；正文仍不在标题区下方滚动，ADR-20261101 第一节补充决策第 6 条（不做顶栏渐隐）继续有效。
9. 标题区不再显示连接或退出状态，包括「已连接」「重新连接中…」「无网络」与「已退出」；桌面右侧只保留刷新应用，移动端只保留更多菜单。Relay 与 Extension 的详细状态仍在设置页查看。

### 输入区提示行

10. 连接问题与不能发送的原因统一放在输入框卡片顶部的提示行。输入框外观不变，只换提示文字：

    | 状态 | 提示行 | 能否输入 |
    | --- | --- | --- |
    | 断线 3 秒后 | 动态图标与「正在重新连接…」，不提供操作 | 能 |
    | 断线 10 秒后 | 「无法连接 Relay，正在自动重试…」与文字操作「立即重试」 | 能 |
    | 无网络 | 「网络不可用，恢复后自动重新连接」，不提供重试 | 能 |
    | Pi 已退出 | 「这个 Pi 已退出，会话记录已保存在本地历史」，不再提供「选择其他 Pi」 | 不能，占位文字为「无法发送消息」 |
    | 阅读本地历史 | 「这是本地保存的历史记录，只能阅读」 | 不能，占位文字同上 |

    3 秒内恢复的短暂断线不提示。只有动态图标使用表示进行中的运行色，提示文字与「立即重试」保持中性色。
11. 未打开会话（选择 Pi、等待快照或没有在线 Pi）时没有输入框，Relay 断线改在主区空态说明：图标、「无法连接 Relay」、带动态图标的「正在自动重试…」与「立即重试」按钮，沿用现有主区空态规格。
12. 原提示条的 `role="status"` 播报改由提示行与空态承担；不能输入的输入框补充只读语义。

## 没有采用的方案

- 连接提示改为不占布局的浮动卡片：正文不再被推开，但仍盖住顶部一条正文，连接状态仍在标题区与卡片两处重复。
- 标题区可点击的状态胶囊：可点的胶囊违反「行内按钮不做胶囊」，描边、字重与高度也不在现有档位内；移动端放不下原因说明。
- 标题区状态旁加「立即重试」按钮，或状态标签加弹出说明：都在标题旁放置带底色的控件，与标题争夺视线；前者丢失原因说明，且紧邻同为刷新含义的「刷新应用」。
- 断线时把「刷新应用」改为纯图标的重连入口：图标保持中性色后桌面几乎看不出变化，改用运行色又误用了「正在进行」的语义；移动端动态图标与刷新图标并排难以分辨。
- 跟随时也让内容不动：见决策第 3 条。
- 只浮起排队抽屉：抽屉同样会挡住列表底部，留白同样需要同步，复杂度接近整体浮起。

## 替代关系

- 取代 ADR-20261101 补充决策（2026-11-02）第 3 条「不让列表完整伸到输入区下方」。该条的风险判断（留白需随草稿、排队、附件与提示实时同步，并牵涉贴底跟随、「最新」入口与 iOS 键盘）仍是实现的验收重点，由分阶段实施与时间线视口集成测试承担。
- 取代 ADR-20261101 补充决策（2026-11-05）第 4 条「输入区高度只在增减时一次到位」中抽屉、提示行与附件行的部分；草稿换行仍一次到位。
- 取代 DESIGN「反馈呈现」中连接提示条、标题区连接状态、局部错误条与安装 `Alert` 的呈现位置，以及「实时与只读历史」中 Pi 退出时的标题区状态与「选择其他 Pi」入口。连接、局部错误与安装的状态所有者不变。

## 后果与验证边界

- 评审原型见 [`docs/prototypes/20261105-floating-composer-notices/`](../prototypes/20261105-floating-composer-notices/page.html)。
- 本记录只改变 PWA 呈现，不改变协议、Relay、Extension、连接重试策略或本地历史模型。
- 分阶段实施，详细范围与验收见[实施方案](../plans/active/20261105-floating-composer-and-notices.md)：先只改结构、不改观感，再改为高度过渡，最后重做提示。DESIGN 与 ARCHITECTURE 随各阶段的实现同步更新，未实现前仍以现有规则为准。
- 列表留白同步、跟随贴底、发送过渡、历史前插锚点、「最新」入口、iOS 键盘与安全区、矮窗口密度须逐项复核；验收沿用时间线视口集成测试，并以真机录屏为准。
