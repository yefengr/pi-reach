# 操作反馈与摘要阅读实施方案

本方案解决耗时操作没有及时反馈、受理被误当完成，以及长摘要直接铺在会话中的问题。交互依据为[操作反馈原型](../../prototypes/20261016-operation-feedback/README.md)，设计基线为 [DESIGN](../../DESIGN.md)。项目级状态以 [ROADMAP](../../ROADMAP.md) 为准；本文件记录实施设计与末尾验证结果；项目级完成状态以 ROADMAP 为准。

## 交付范围

| 操作 | 用户看到的反馈 | 完成依据 |
| --- | --- | --- |
| 压缩上下文 | 即时状态行、摘要阅读入口、失败或中性取消提示 | 本次远程调用的回调；公开压缩事件用于活动和正式摘要 |
| 分支摘要 | 会话中保留简短入口，长文进入阅读器 | 已保存的正式摘要条目 |
| 新建会话 | 保留旧内容，底部显示“正在新建会话…”；能确认创建成功后显示“正在打开新会话…” | 创建成功且目标会话连接、首屏数据就绪 |
| 模型／思考切换 | 原控件保留当前值，固定位置显示等待图标 | 操作回执及实际配置值 |
| 停止任务 | 原停止按钮显示等待图标，拒绝后恢复可用 | 目标 `group_id` 的正式 `run_end` |
| 模型／本地历史列表 | 区分加载、错误、成功为空；刷新保留已有条目 | 对应读取请求的结果 |
| 模型服务错误 | 简短安全说明；可靠详情或恢复建议进入阅读器 | 已确认的信息，不从错误字符串猜原因 |

不修改 Pi 本体或上游 Extension API，不读取私有运行对象、不猴子补丁、不截获内部事件。自动重试状态、次数、倒计时及耗尽反馈不在本次交付范围；不安排上游改造作为后续阶段。

普通回复、用户消息、工具详情、配对、附件、文件、历史、导航和既有连接恢复保持原职责。不清空或迁移旧历史，Relay 不承担新增业务状态。

## Pi 1.3.0 核对结论

2026-10-16 已将本机全局 Pi 从 1.0.4 升至 1.3.0，并请求重启恢复会话。恢复后复核 CLI 版本，使用新版公开 `DefaultResourceLoader` 在隔离目录加载已安装 Pi Reach 和开发重启扩展，命令、工具及事件注册成功。此验证没有触发 `session_start` 或真实模型请求，不代表完整业务兼容性验收。

仓库开发 SDK 已对齐到 1.3.0，对等依赖约束为 `^1.3.0`，根锁文件同步更新；Extension 的 Node.js 下限为 22.19.0。全局安装与仓库 SDK 是两个独立来源。

核对对象是 1.3.0 随包公开声明 `dist/core/extensions/types.d.ts` 和对应实现；实现源码仅用于确认事件时机，不作为私有 API 调用入口。

| 公开接口 | 已核实能力 | 使用边界 |
| --- | --- | --- |
| `ctx.compact({ onComplete, onError })` | 非阻塞触发；回调报告这次调用的结果 | `action_ok` 只表示受理，不能结束等待 |
| `session_before_compact`、`session_compact`、`session_compact_failed` | 提供触发原因、成功或失败、取消信息；`willRetry` 表示压缩相关的溢出恢复意图 | 自动压缩准备完成前没有公开开始事件，部分准备失败没有公开失败事件；不承诺全阶段可观测 |
| `newSession({ withSession })` | 返回取消状态，交接新会话上下文 | 新上下文就绪不等于 PWA 已拿到首屏；替换后不能继续使用旧 `ctx` |
| `setModel`、`getThinkingLevel`、`setThinkingLevel`、选择事件 | 可修改并读取实际配置；模型切换可能连带调整思考级别 | 不把请求值直接当最终值，不假设失败后配置一定没变 |
| `ctx.abort()` | 发起停止，公开返回类型仍为 `void` | 不证明停止已完成 |
| `agent_settled` | 整次运行及自动延续结束后触发，1.3.0 提供 `aborted` | 不能推出此前是否进入自动重试，更不能据此生成重试次数或倒计时；不替代现行 `run_end` 契约 |
| `after_provider_response` | 能提供响应状态与响应头 | 不是完整错误或重试生命周期；不直接透传响应头，也不把最近一次响应状态归给任意后续错误 |

`auto_retry_start/end` 与摘要重试事件仍属于会话内部通知，没有对应的公开 Extension 订阅入口。公开 SDK 的会话对象能力不能等同于已加载扩展可取得的上下文能力；本方案不另建 SDK 会话绕过此限制。

## 交互与实现约束

### 摘要和错误阅读器

`message-list.tsx` 当前对部分对象 payload 使用 `JSON.stringify`。改为按正式摘要类型提取 `summary`，兼顾已有字符串摘要；缺少摘要正文时显示简短兜底，不退回整个对象 JSON，也不展示内部 ID 或 `details`。

桌面阅读器位于右侧，手机全屏。复用 `tool-reader.tsx`、`use-reader-history.ts` 及现有叠层机制，只抽取真正重复的外壳。摘要保留原文语言和格式，不翻译或修改英文压缩指令。工具和文件阅读器的复制、返回、焦点恢复、阅读位置及滑动行为不得退化。

错误以固定安全说明和恢复建议兜底。只有来源可靠且经过明确字段筛选的详情才可展示；不凭关键词猜 HTTP 状态或错误码，不透传响应、凭据、请求正文或堆栈，不把截断称为脱敏。当前没有现场长错误样本，原型仅演示通用说明；实施时先验证安全兜底，再按可证实的数据决定详情内容。旧历史不批量改写，但新展示入口同样遵守安全提取规则。

### 新建会话

沿用 `/new` 和现有确认框。确认后保留旧会话内容，底部追加压缩同款 spinner 与“正在新建会话…”。不使用整页 loading、独立标题块或整页转场；`/` 保持原图标，不重复转圈。等待时禁止发送、附件发送和重复新建。

复用 `SessionNewBridge` 的调度与交接，在 `withSession` 中记录目标会话 ID。只有创建实际成功、PWA 收到对应目标的 `session_ready` 且必要首屏数据可用，才切换展示。目标 ready 与请求结果可能乱序，必须按目标 ID 汇合，而不是“下一个 ready 就算成功”。创建已确认但首屏尚未就绪时，才显示“正在打开新会话…”。

`clearSessionConnection()` 不应抹掉仍待确认的新建操作。旧连接关闭或 `session_replaced` 仅进入既有重连流程；连接恢复后证据不足则保留结果待确认，不自动再建一个会话。确定失败时解除等待并恢复原入口；不能把旧连接断开直接判断为创建失败。

### 模型与思考级别

复用模型／思考菜单和现有请求 pending，等待图标占据原箭头位置，保留当前值、悬停提示及读屏名称，避免布局位移。模型成功后回传实际模型和实际思考级别；单独调整思考时回传实际级别，不修改模型。

失败时解除等待，依照重新核实的实际状态呈现，不制造回滚。原型中“失败后原值不变”仅代表该示例的实际状态，不构成失败必然没有副作用的规则。可以复用公开选择事件同步本地操作，但不能把无关本地事件归给当前远程请求。

### 停止任务

复用原停止按钮及请求关联，等待期间防止重复提交。`cancelled` 只表示受理；拒绝或异常通过现有 `protocol_error.in_reply_to` 关联并恢复控件。最终只根据目标 `group_id` 的正式 `run_end` 区分已中断、自然完成或错误。

发送停止时固定目标轮次，服务端验证目标仍适用，避免晚到的请求误停下一轮。若自然结束先于停止回执到达，后续迟到回执不得把已结束轮次重新置为等待，也不得影响新轮次。遵守[严格运行结束决策](../../adr/20260930-strict-run-completion.md)。

### 压缩上下文

用户主动触发后立即进入局部等待；现有 `handleSessionCompact()` 的受理回执保留其语义，最终结果由该次 `ctx.compact()` 的 `onComplete/onError` 关联回原请求。公开 hooks 用于压缩活动、成功摘要、失败和取消状态，不把任意本地压缩成功绑定到当前远程请求。压缩成功会推进 leaf，活动终态沿用开始作用域先结束活动，再发布新 leaf 的正式摘要。远程 `onError` 仅提供 `Error`，无法可靠区分本次取消与失败时，解除等待并给出中性“压缩未完成，也可能已取消”提示；不解析错误文本或绑定无关本地 hook 来伪造取消依据。

手动、阈值与溢出恢复的触发原因来自公开字段；对自动压缩只展示收到公开事件后的状态。成功摘要继续走正式 timeline，回调和事件不能造成重复摘要或重复提示。取消使用中性色，错误提示与摘要入口不重复堆叠。断线或超时显示结果待确认，不自动重发压缩。

### 列表加载

模型列表与本地历史读取分别维护初始、加载、成功和错误状态，只有成功返回空数组才显示空态。刷新保留已有条目，失败保留条目并提供重试入口。复用 `useDelayedVisibility` 的 300ms 延迟与显示后至少 500ms；用户主动发起的操作反馈不套用该延迟。

继续使用现有设备、会话 generation 与卸载隔离，避免旧请求写回新列表。保留模型菜单层级、返回项、提供方、名称、ID 和选中标记，不增加原正式界面没有的搜索框。

## 最小跨端改动

复用现有 pending、action 回执、请求 ID、bridge 和 hooks，按各操作补充必需的数据：模型／思考实际值、新建目标会话标识、压缩最终结果关联，以及停止目标轮次的校验。具体字段由实施时统一定义在 `packages/protocol/` 的严格 schema 中，再同步全部直接消费者；本文不预先冻结未验证的字段命名。

发送成功、服务端受理和业务完成分别判断。保留 channel、session、device、generation 等现有作用域隔离，忽略迟到、重复和不匹配回包。错误与正常回执使用相同关联要求。

不建立通用反馈订阅、全量状态快照、请求结果缓存、恢复轮询或通用工作流引擎。复用已有重连、握手和历史同步；证据不足时明确结果待确认，不建立跨进程重启的请求追溯系统。

新跨端功能要求配套 PWA／Extension，不为本次功能增加旧端能力探测或多套降级逻辑。发布前仍需核实严格 schema 下的混合版本影响，按[部署约定](../../DEPLOYMENT.md)先 PWA、后 Extension，并向使用者明确配套升级要求。

## 验收要求

- 受理、完成与失败：慢回执、发送拒绝、取消、超时、断线，均有合理反馈；没有成功证据时不宣称成功，不重复发送有副作用的操作。
- 关联与时序：切设备／会话、旧 generation、重复与晚到回包隔离；新建结果与 ready 两种顺序；停止与自然结束交错、晚停止不能影响下一轮。
- 真实配置：模型切换导致思考级别调整，思考请求被能力限制，本地选择事件与远程回执交错，均显示最终实际值。
- 压缩：远程与本地触发、失败及取消、回调与成功事件去重；自动准备阶段不可观测的边界不被伪装为完整反馈。
- 展示：字符串与对象摘要、正文缺失、安全错误兜底；首次加载不误显示空态，刷新失败保留条目。
- 阅读器：工具／文件旧行为、复制、Escape、浏览器返回、焦点和滚动位置、Portal、导航与阅读器交接；使用[叠层验证技能](../../../.agents/skills/validate-mantine-stacked-overlays/SKILL.md)。
- 视觉与设备：桌面和窄屏、浅深色、44px 目标、控件几何稳定、输入法和软键盘；iOS／Android 真机证据单独记录，不能以桌面窄视口代替。

共享协议修改后先构建协议包；Extension 行为修改按子项目要求执行 `pnpm verify`，跨端范围按根规则扩大验证。PWA 运行相关类型、lint、Node 与直接受影响的浏览器测试，不以无用例通过代替验证。文档执行 `pnpm check:docs`，最终执行 `git diff --check`。提交、推送、部署和发布不包含在本次授权中。
