# PWA 桌面与移动 UI 规范方案

> 已完成并归档（2026-10-10）。第 1–19 节是评审通过时的目标规则与实施计划，保留为背景；当前规则以 [DESIGN](../../DESIGN.md) 为准，实施结果、验证证据与未覆盖风险见[实施结束记录](#20-实施结束记录)。事项状态以 [ROADMAP](../../ROADMAP.md) 为准；效果图见 [调整前后对比](../../prototypes/20261009-pwa-ui-spec/page.html)（原型状态：已确认）。
>
> 2026-10-09 两轮评审的取舍与处理见[第 19 节](#19-评审记录)；实施时“拟”条目均按文中目标落地，差异见第 20 节。

## 1. 目标与范围

为 Pi Reach 的桌面与移动 PWA 建立可执行的 UI 规则，覆盖页面边距、元素间距、按钮和输入尺寸、圆角、边框、颜色、字体以及响应式例外。规范需要让不同页面在相同内容关系下采用相同取值，同时保留导航、对话和阅读器各自的密度需求。

桌面与移动共用视觉基础，分别定义布局和操作密度，不维护两套独立品牌风格。桌面侧重阅读效率和布局稳定；移动侧重触控、单列阅读、安全区与键盘避让。桌面布局也可能运行在触屏平板或横屏手机上，不能仅按视口宽度缩小点击区域。

范围包括工作区、导航侧栏、设置页、启动页、空状态与骨架屏，以及配对、重命名、确认弹窗、电脑选择面板、菜单、提示条与通知、工具与文件阅读器、Composer、附件与发布文件卡片。

本方案不改变导航结构、产品功能、协议、配对流程、信息所有权、焦点和历史返回规则；不引入字体、图标库或新组件库；不重做品牌色或动效方向；不放开移动端页面缩放；也不授权提交、发布或部署。

## 3. 取值、术语与适用规则

- 本文尺寸单位均为 CSS px，不是物理像素。安全区按下文“安全区归属”由贴边的布局层负责，不逐容器叠加。
- 宽高默认使用 `border-box` 口径，包括边框和内边距；阅读列另行注明为实际内容宽度。
- 表格中的尺寸是默认或最小值，不是要求文本在所有环境下都固定高度。长文案和桌面浏览器缩放时，容器可增高，不裁剪文字。
- 明确的组件例外优先于通用规则；没有例外时，依次使用组件规则、内容关系间距、通用档位。
- 同一间隔只由一个布局层负责。父容器使用 gap 后，子元素不得叠加同方向 margin，除非该 margin 有独立语义。
- 不因为统一规范而机械替换所有相同数字。4px 圆角、4px 间距和 4px 光学偏移不是同一种 token。

按钮术语统一如下，后文不混用：

| 术语 | 对应实现 | 说明 |
| --- | --- | --- |
| 实体按钮 | Mantine `Button` 的 `filled`、`default`／`light`、`outline` 变体 | 有底色或边框的按钮，包括主按钮、次级按钮与危险入口 |
| 文字按钮 | Mantine `Button` 的 `transparent` 变体 | 透明底、强调色文字，例如“返回工作区”“查看本地历史” |
| 图标按钮 | `ActionIcon` 与同规格原生按钮 | 只显示图标，必须有可访问名称 |

单一布局断点保持不变：视口宽度 ≥ 768px 为桌面，< 768px 为移动。支持 hover 与是否启用触控反馈根据设备能力判断，不直接等同于布局断点。宽度 ≥ 768px 的横屏手机进入桌面布局，因此桌面规则同样必须处理左右安全区与矮窗口。

除宽度断点外，现有实现还有一个高度维度：应用壳可见高度 ≤ 600 时进入矮窗口密度，≤ 450 时为极矮窗口（见第 6 节）。

### 安全区归属

原则：安全区只由实际贴住该屏幕边缘的布局层负责，同一边只计算一次。贴边层的背景延伸进安全区、内容内缩；子层继承父层已扣除的位置，不再叠加。不贴边的居中叠层与屏幕边缘的距离取 `max(基础留白, 对应安全区)`，不相加。

宽度口径：侧栏 260、阅读器 720、移动导航 320 都是内容宽度，不含安全区；设置页 640 与阅读列 680 位于已扣除安全区的区域内，同样不含安全区。

| 布局层 | 负责的边 | 口径 |
| --- | --- | --- |
| 桌面侧栏（展开） | 左、上、下 | 面板总宽 260＋左安全区，安全区内以 `panel` 填充 |
| 桌面主区（侧栏展开） | 右、上、下 | 左侧不贴屏幕，不加左安全区；阅读列右侧 gutter＋右安全区，顶栏右侧 8＋右安全区 |
| 桌面主区（侧栏收起） | 左、右、上、下 | 左侧改为贴边：展开入口 8＋左安全区，标题区左侧 56＋左安全区，阅读列左侧 gutter＋左安全区 |
| 移动主区 | 左、右、上、下 | gutter 16＋各侧安全区；顶栏左右 4＋各侧安全区 |
| 设置层 | 左、右、上、下 | 由设置层滚动容器内缩左右安全区；内部 640 容器及其 20／16 内边距不变，不再叠加 |
| 桌面右侧阅读器 Drawer | 右、上、下 | 面板总宽 720＋右安全区，不超过可用视口；内容内缩右安全区 |
| 移动全屏阅读器 | 左、右、上、下 | 顶栏与正文的左右按移动主区口径 |
| 移动导航 Drawer | 左、上、下 | 面板总宽 `min(320px + 左安全区, 85vw)`，内容内缩左安全区 |
| 移动底部 Drawer | 左、右、下 | 内容内缩左右安全区，底部沿用现有补偿 |
| 运行时提示条 | 左、右（位于应用壳顶层、横跨全宽） | 两侧 gutter＋各侧安全区 |
| 居中 Modal、Popover、Menu、Toast | 不贴边 | 与屏幕边缘最小距离取 `max(基础留白, 对应安全区)` |

## 4. 桌面端布局

| 项目 | 目标规则 | 与现状关系 |
| --- | --- | --- |
| 主内容左右边距 | 20；只在主区实际贴边的一侧叠加安全区（见“安全区归属”） | 已确认补充左右安全区；现状只有运行时提示条处理了左右安全区 |
| 会话阅读列 | 实际内容最大宽 680，居中；外侧另留主内容边距 | 沿用 |
| Composer | 与会话阅读列同宽、同一左右对齐线 | 沿用 |
| 设置页 | 容器最大宽 640，含左右各 20 的内边距；左右安全区由设置层滚动容器负责，不计入 640；宽度不足时占满可用宽度 | 明确现有尺寸口径 |
| 设置页顶部 | 32＋顶部安全区 | 沿用 |
| 设置页分区 | 间隔 32 | 沿用 |
| 设置页底部 | 48＋底部安全区 | 沿用 |
| 常驻侧栏 | 内容宽 260，可完全收起；面板总宽 260＋左安全区，安全区以 `panel` 填充 | 宽度沿用；安全区为新增 |
| 顶栏 | 内容区高 48，上方另叠加顶部安全区 | 沿用；桌面浏览器放大文字时可增高 |
| 顶栏右侧 | 图标按钮距边缘 8＋右安全区 | 安全区为新增 |
| 工具／文件阅读器 | 右侧 Drawer，内容目标宽 720，面板另加右安全区，总宽不超出可用视口 | 沿用方向，窄窗口与横屏需验收 |
| Composer 底部 | 留白为 `max(16px, 底部安全区)` | 沿用，不将 max 改成相加 |

左右安全区通过公共 token（拟 `--pwa-safe-left`、`--pwa-safe-right`）叠加，不在各组件重复写 `env()`；无安全区时取 0，桌面浏览器外观不变。

设置页标题、说明、表单和版本列表使用同一内容左缘；按钮的负外边距仅可用于让文字按钮内容与该左缘对齐，不得扩大到普通卡片。

桌面顶栏以文字开头时左侧使用 20；右侧图标按钮距边缘 8。收起侧栏后的展开入口沿用现有专门布局（标题区左侧 56，贴边时另加左安全区），标题避让该入口，不套用普通文字开头规则。导航品牌与列表内容左缘按现有 16 对齐（见第 13 节的待核对项）。

## 5. 移动端布局

| 项目 | 目标规则 | 与现状关系 |
| --- | --- | --- |
| 主内容左右边距 | 16＋各侧安全区（移动主区左右都贴边） | 沿用基础值，补充安全区边界 |
| 会话阅读列与 Composer | 最大内容宽 680，通常占满扣除边距后的宽度 | 沿用 |
| 设置页 | 容器最大宽仍为 640，含左右各 16 的内边距；左右安全区由设置层负责 | 明确口径，不因进入移动布局取消上限 |
| 设置页顶栏 | 固定在滚动内容之外或 sticky；下方首个分区间隔 32 | 沿用现有布局 |
| 设置页底部 | 48＋底部安全区 | 沿用 |
| 导航 | 左侧 Drawer，面板总宽 `min(320px + 左安全区, 85vw)`，内容内缩左安全区 | 宽度沿用；安全区为新增 |
| 工具／文件阅读器 | 全屏，顶栏不随正文滚走；四边由阅读器自身避让 | 沿用 |
| 表单与普通卡片组 | 默认单列 | 补充通用规则，不改变附件等领域布局 |
| Composer | 使用现有软键盘与安全区补偿，不额外重复扣减 | 保持现有机制 |

移动顶栏内容区高 48；顶部安全区叠加在上内边距。以返回或菜单按钮开头时，按钮距左缘 4、按钮与标题间隔 4；右侧图标按钮距边缘 4。标题 18/600、左对齐，常规情况下单行省略，完整信息可在正文或现有信息弹层查看。

宽代码、表格和 diff 在自身区域横向滚动，不能撑宽页面。非必要的文本截断不用于正文、表单标签或操作名称。

移动端继续保留 viewport 的 `maximum-scale=1, user-scalable=no`，本方案不放开页面缩放（已确认）；图片阅读器保留自身的双指缩放。是否放开移动端缩放作为后续候选另行评估。

这是对现状的保留，作为已接受的限制记录：

- 低视力用户在移动端无法用页面缩放放大 13px 元数据、代码和路径，存在可访问性风险。
- 部分浏览器会忽略该限制（如 iOS Safari 默认仍允许双指缩放，主屏模式下的行为待真机核对），因此布局仍不得依赖“页面一定不会被缩放”。
- 桌面浏览器 200% 验收不能代表移动端的文本放大能力已经覆盖。

## 6. 矮窗口密度

现有实现按应用壳实际可见高度切换密度，软键盘弹出时同样生效；阈值以 [use-keyboard-viewport.ts](../../../pwa/src/lib/pwa/use-keyboard-viewport.ts) 的具名常量为准，本文不重复维护数值来源。

| 模式 | 触发 | 已有调整 |
| --- | --- | --- |
| 常规 | 可见高度 > 600 | 按本文其他章节 |
| 矮窗口 `short` | 可见高度 ≤ 600 | 消息列表上下留白 24／88 → 8；连接提示条去掉上外边距与纵向内边距；运行时提示条纵向内边距 6、说明仅供读屏；Toast 外边距 2、正文最多 2 行 |
| 极矮窗口 `very-short` | 可见高度 ≤ 450 | 在矮窗口基础上，有局部 Toast 时 Composer 纵向内边距压缩为 4 |
| 宽矮窗口 `wide-compact` | 可见高度 ≤ 600 且宽度 ≥ 600 | 运行时提示条改为单行横排 |

矮窗口规则：

- 只压缩纵向留白、提示条和非关键说明；不缩小 44 点击区域、字号、左右边距和安全区。
- 视觉隐藏的说明仍须对读屏可达，不能直接移除。
- 新增的纵向留白须说明在矮窗口下是否压缩；固定高度的新组件须在 450 高度下验收。
- 矮窗口下的连接提示条图标 13 是现有例外，拟统一为 16（见第 16 节 P10）。

## 7. 间距体系

### 7.1 基础档位

通用间距明确为以下档位，并通过用途约束避免“有很多档位但不知道该选哪个”的问题。

| 数值 | 默认用途 |
| --- | --- |
| 4 | 强关联文字，例如标题与说明、输入框与辅助信息 |
| 8 | 图标与文字、相邻操作、单选卡片之间、表单标签与输入框 |
| 12 | 紧凑卡片内边距、紧凑内容组 |
| 16 | 常规卡片内边距、完整表单项之间、内容到主操作、移动主内容边距 |
| 20 | 桌面主内容边距，不作为通用元素间隔 |
| 24 | 桌面弹窗内边距、桌面弹窗正文与底部操作之间 |
| 32 | 页面大分区之间 |
| 48 | 页面底部留白或明确的大区域分隔，不用于普通表单项 |

### 7.2 按内容关系选值

| 内容关系 | 桌面 | 移动 | 说明 |
| --- | --- | --- | --- |
| 分区标题 → 说明 | 4 | 4 | 两者视为同一标题组 |
| 标题／说明组 → 分区主要内容 | 16 | 16 | 元数据小列表允许专门例外 |
| 表单标签 → 输入框 | 8 | 8 | 已确认：公共标签 6 → 8；清除重命名字段的叠加间距 |
| 输入框 → 帮助或错误信息 | 4 | 4 | 错误与帮助有多个块时也按关系组织 |
| 完整表单项 → 下一表单项 | 16 | 16 | 帮助与错误属于前一表单项，不单独计数 |
| 普通卡片 → 下一卡片 | 12 | 12 | 不覆盖会话消息、附件等领域列表 |
| 单选卡片之间 | 8 | 8 | 沿用设置页 Mantine Stack 的 xs |
| 相邻独立操作按钮 | 8 | 8 | 顶栏紧凑布局见专门规则 |
| 一般内容 → 表单主操作 | 16 | 16 | 已确认：设置表单与配对表单 gap 12 → 16 |
| 弹窗正文 → 底部操作区 | 24 | 16 | 已确认：确认弹窗与重命名弹窗在移动端均为 16 |
| 弹窗底部操作按钮之间 | 8 | 8 | 移动纵排时为纵向间隔 8 |
| 页面大分区之间 | 32 | 32 | 不因移动布局将其缩小 |

表单项间距指前一项最后一块可见内容与后一项标签之间的距离，不是两个输入框边缘之间的距离。新增提示时布局可增长；进度卡片等有稳定高度要求的组件单独定义保留空间。

重命名字段现状：`.pwa-rename-field` 的 grid gap 8 与公共标签 margin-bottom 6 叠加，浏览器实测标签到输入框为 14；该字段自有的 `line` 边框、`panel` 底和 `opacity: 0.55` 禁用态被优先级更高的公共输入样式覆盖，实际不生效。实施时删除这些失效声明，由公共输入样式统一负责。

### 7.3 允许的专门例外

| 场景 | 保留或单独处理的规则 |
| --- | --- |
| 顶栏按钮与标题 | 间隔 4，不强套独立按钮间隔 8 |
| 工具状态行 | 行间距 6，沿用阅读密度 |
| 导航行与双行文字 | 行与行间隔 2、行内双行文字间隔 2，属于导航密度 |
| 设置版本列表 | 标题组与列表间隔 8，行间距 12，属于紧凑元数据 |
| Composer | 保留领域专用的 10/12 内边距与操作区 gap 6，不按普通卡片一刀切 |
| 消息列表底部 | 88，用于浮动“最新”入口避让，不是通用间距 |
| 主区空状态顶部 | `clamp(48px, 24dvh, 260px)`，不是固定分区间隔 |
| 行内代码与工具箭头 | 允许 1 的局部内边距或光学校正，不推广为间距档位 |
| 移动 Modal 上内边距 | 20，与关闭按钮的负外边距配合，不推广为通用间隔 |
| 对齐左缘的文字按钮 | 设置页返回、配对方式切换的左右内边距 8，配合负外边距让文字与内容左缘对齐 |
| “最新”浮动按钮 | 左右内边距 12，浮层专用 |
| 表单与卡片中的其余 2/6/10 | 已有取值先核对用途；有理由则登记例外，无理由再调整 |

规则不是“禁止非四倍数”，而是要求每个非通用值有明确用途。异常值不得仅以“视觉上差不多”为理由新增。

### 10.1 圆角

### 10.2 边框与阴影

| 类型 | 规则 |
| --- | --- |
| 装饰分隔线 | 1px line |
| 卡片边界 | 需要明确承载时使用 1px line，不要求所有内容都有框 |

### 10.3 焦点

常规控件使用 2px accent 轮廓，offset 为 0；图标按钮轮廓对应 36px 视觉圆，按当前 44px 点击区域内缩绘制。程序聚焦的标题沿用专门规则，不强行套用输入控件样式。焦点样式不增加布局占位，也不依赖阴影。

关闭叠层后的有效回焦、Escape 最上层关闭、Portal 和单层遮罩继续遵循 DESIGN 及现有测试；本方案不另建叠层行为契约。叠层层级目前以 DESIGN 的顺序和少量 z-index 字面量实现，本方案不做 token 化，作为后续候选。

## 17. 后续落地方式

方案已于 2026-10-09 评审通过，事项状态见 [ROADMAP](../../ROADMAP.md)。DESIGN 只描述已实现的现状，因此不在实施前整体改写：每个实施批次在同一提交中把该批已落地的规则及例外同步进 DESIGN，并写明替代了哪些旧描述；全部落地前，本方案是目标规则的依据，不双写当前 token。

随后按“盘点 → 验证机制 → 分批实施”执行：

1. 盘点所有直接消费者，按页面、公共控件、导航、提示类、业务卡片和叠层分类。逐项记录当前尺寸、目标尺寸和保留理由，不能只扫描 Mantine props，也要检查 CSS 内部间距、原生按钮、命中区域和多层叠加的间距。
2. 在现有 pwa-theme.css 中按语义增加确有复用价值的间距、尺寸和左右安全区 token。Mantine spacing 的 xs/sm/md/lg/xl 映射至 8/12/16/24/32 档位；圆角继续使用既有 token。20 为页面 gutter，不机械塞入 Mantine 通用档位。
3. 公共 theme 保持组件默认值，业务 CSS 负责布局和领域状态。不恢复只转发 props 的组件包装，不建立第二套 Button API。
4. Tailwind 只保留 preflight 与入口职责，业务组件不使用 Tailwind 间距、颜色和圆角工具类。`globals.css` 中 `@theme inline` 的旧别名（如 `--surface` 实际指向 `panel`）当前没有消费者，实施时删除，避免与 `--pwa-*` 语义 token 混淆；`--maxw` 随提示条宽度口径一起移除。
5. 先处理公共控件与页面容器（含安全区 token），再处理设置页、导航、对话、输入区与提示类，然后处理叠层和阅读器，最后加入防回归检查。共享样式每批都检查断点两侧和矮窗口，不能只验证当前页面。
6. 防回归检查以 Node 测试实现，不引入新的 lint 工具。首期只是 CSS 静态守卫，不是完整的 UI 一致性验证：
   - 范围：扫描 `pwa/src` 下的 CSS；禁止 `pwa-theme.css` 之外出现十六进制色值。
   - 例外绑定到具体选择器与属性（如 `.pwa-message-list` 的底部留白 88），不做全局数字放行；新增例外须同时更新白名单与 DESIGN。
   - 只检查 px 长度：按属性分组校验，间距类属性对照通用档位，边框与轮廓宽度单独允许 1／2／3；百分比、视口单位、时间、无单位值和 0 不纳入。负值必须登记为对齐或光学例外。`calc()`、`clamp()`、`max()` 等表达式内的 px 字面量逐个校验，也可按选择器与属性整条登记。
   - 不覆盖：TSX 中的 Mantine `size`／`gap` 等 props、内联 `style`、图标尺寸和 `pi-reach-theme.ts` 字面量；也无法判断数值是否选对了语义 token。这些由实施批次的盘点与行为测试负责，是否扩展到 TSX 另行评估。
7. 收口时核对 DESIGN 已覆盖全部落地规则；方案结束后按项目约定归档并记录未覆盖风险，再更新 ROADMAP 状态。

以下事项不在本方案实施范围内，建议另行登记为候选：

- 评估放开移动端页面缩放（需回归手势、安全区、软键盘补偿和图片阅读器缩放）。
- 叠层 z-index token 化。
- 防回归守卫扩展到 TSX（Mantine props、内联样式与 theme 字面量）。
