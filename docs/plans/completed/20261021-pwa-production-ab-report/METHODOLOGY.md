- 每个场景各4对，轮次顺序AB、BA、AB、BA，单一browser顺序运行，fresh context，不同场景不合并成一个收益百分比。
- 主指标是固定输入完成前后的累计主线程任务占用时长（CPU工作量代理），不是回放的墙钟耗时，也不是OS精确线程CPU时间。CDP Performance.getMetrics前后差：TaskDuration/ScriptDuration/LayoutDuration/RecalcStyleDuration（原始字段明确标为秒，统计转ms），LayoutCount/RecalcStyleCount。窗口墙钟用CDP Timestamp差，只描述测量/调度范围，不当吞吐主指标。TaskDuration不是整机CPU%或能耗。
- 首尾采样之外，在Worker finish消息收到后、正式事件注入前，通过一次Playwright binding取得活动边界CDP指标；随后才注入formal/run_end。分别记录活动期、结束保存/静置尾部及总CPU，三者代数校验。该固定探针会给正式注入增加少量跨CDP等待，另存finishReceivedAt/activityBoundaryAt/finalDeliveredAt，不把该等待掩饰为产品延迟。
- 长任务：PerformanceObserver longtask，计数/总长/最大长（标准约50ms以上），startMs统一为相对本次计量开始的毫秒。不把正常为0或低毫秒idle的相对波动解读为收益/退化。
- 内存：前置full GC后baseline、窗口末值、测后GC retained值及差；不是峰值/泄漏证明，包含真实页面和共同探针状态。内存读取/GC不在活动CPU窗口里，最后结果验证读IDB发生在窗口后；窗口内为完成门禁可能查询IDB，次数记录。
- 计量尾部：最后partial计划结束后200ms发送正式正文和run_end，至少等500ms；确认N+2正式事件和run_end已落盘，并且最后DOM mutation距今≥250ms才结束。最多额外15秒，防止把未保存/未消化工作当优化。墙钟窗口因此可能不同；总CPU包含真实完成工作及少量门禁读开销，活动/尾部CPU分列，空转墙钟不称CPU开销；不得只因窗口长短判性能。
- 延迟：MutationObserver回调内直接读取最新完整序号作为DOM提交时刻；另外保留下一rAF覆盖时刻，二者不混用。对追加内容以最大完整序号推定前缀覆盖，最终逐项验证全部序号1..N。记录worker计划/实际发送、主线程接收、DOM覆盖；分别报告计划→DOM和接收→DOM的每轮p50/p95，中位数按轮聚合。rAF只是附加呈现就绪代理，不是像素或端到端模型响应。
- 流式可观测门禁：测前确认正文容器在被观察root内；活动样本必须存在正式注入前的DOM推进、content mutation、无进度回退。记录覆盖帧数、推进次数/秒、每次推进覆盖帧数和相邻推进间隔；相邻间隔排除0→首次推进等待，首次推进时刻另存。“formal前已显示全部帧”是质量结果，不作为丢弃过载基线的条件；不得把降低刷新节奏写成纯粹每次渲染提速。
- 完整性：全部帧数量、JSON字符数和FNV-1a32输入指纹匹配确定生成器，savedText逐字符等于期望并另存SHA256，最后正式run_end、DOM全部序号与final标记、source frame counters、无外网/浏览器错误都要通过。指纹不是密码学安全证明；提交代码及生成器hash另存。
- 探针不可避免含共同少量开销（JSON.stringify/FNV、observer/rAF、结束持久化门禁），不宣称已扣除。CPU指标包括这些开销；重复和AB/BA减轻但不消除系统/JIT/缓存噪声。
- pilot只验证方法，全部排除正式统计。已保留入口未注入、旧500ms尾窗未等到run_end的失败；修正后hard case 300/long/tool均完成。从v2开始每次运行写带UTC时间的独立runs文件，latest JSON只是副本，失败attempt不被新运行覆盖；正式采样结束显式断言48样本矩阵。正式脚本冻结后任何更改都需重跑受影响样本，不能静默选样。
