# PWA 会话状态（Pi 状态栏信息）方案

- 日期：2026-11-18
- 用途：供实施代理据此实现；本文不是当前实现说明，也不代表已获实施授权。
- 项目级状态：见 [BACKLOG](../../BACKLOG.md#pwa-会话状态)，不在本文另设状态表。
- 视觉稿：[`docs/prototypes/20261118-session-status/page.html`](../../prototypes/20261118-session-status/page.html)，桌面常驻卡片、移动右侧抽屉与扩展状态的呈现已经评审确认；原型数据为合成样例，手势只模拟跟手与过半提交。
- 当前规则来源：[DESIGN「布局与导航」](../../DESIGN.md#布局与导航)、[「移动端滑动」](../../DESIGN.md#移动端滑动)与[「组件规则」](../../DESIGN.md#组件规则)。本方案与其中若干条款冲突，修改清单见第 9 节，须先获授权，并在实现的同一 Pull Request 中同步。

## 1. 背景与目标

Pi 在终端底部有一条状态栏，显示上下文占用、累计用量与费用、当前分支等信息。PWA 目前看不到这些内容：远程使用时，用户不知道上下文是否快满、这个会话已经花了多少钱。

目标是在 PWA 中查看 Pi 自带的这部分状态，并允许其他扩展按 Pi Reach 定义的约定，把自己的状态显示在同一处：

- 桌面：主区右上角常驻一张只读卡片。
- 移动：右侧抽屉，点按顶栏右侧图标或在会话区左滑打开。原有的「会话信息」弹层并入抽屉。
- 默认只显示 Pi 自带的状态；有扩展按约定上报时，才出现扩展的条目。

## 2. 范围与非目标

| 范围 | 说明 |
| --- | --- |
| 共享协议 | 新增状态订阅请求与状态快照帧；能力不足的旧 Extension 以错误回复，不改握手 |
| Extension | 计算上下文、用量、费用与分支；接收其他扩展按约定上报的状态；向已订阅的页面推送快照 |
| PWA | 桌面卡片与阅读列让位，移动抽屉与左滑手势，各状态的呈现 |
| 公开文档 | 协议说明、扩展状态约定（供扩展作者适配） |

非目标：

- 不读取未适配扩展通过 `setStatus` 写入终端的文字。SDK 目前只在替换整个终端状态栏时才交出这份数据，接管终端状态栏副作用过大；只读接口另向上游提需求，见第 11 节。
- 不重复显示模型与思考级别：输入区的模型标签已经显示。
- 离线会话（本地历史、已退出的 Pi）不显示状态。保留退出时最后一份状态作为候选，见第 11 节。
- 卡片与抽屉不提供操作。「压缩上下文」仍从输入区进入。
- 不改变 [Relay 的传输边界](../../adr/20260518-closed-decisions.md#安全与运维)：状态沿既有 TLS 链路传输，`ct` 是 Protocol v2 JSON 的 Base64，不是应用层端到端加密。Relay 实现不解码、不记录、不持久化 `ct`，但 Relay 运营方技术上可以读取内容。

## 3. 已确认的设计决策

以下取舍在原型评审中确认，实施时不再重新讨论：

| 主题 | 决策 |
| --- | --- |
| 桌面形态 | 常驻卡片，不提供折叠按钮；宽度不够时隐藏 |
| 宽度策略 | 阅读列让位：主区放不下居中的阅读列和卡片时，正文与输入区一起左移到刚好让出卡片；左移到 gutter 仍放不下才隐藏卡片 |
| 移动形态 | 右侧抽屉；会话区左滑打开，右滑、遮罩、关闭按钮、Escape 与系统返回关闭；右滑打开导航保持不变 |
| 上下文呈现 | 不用进度条；百分比前放一个与文字同号的小饼图（细外框加扇形，不用带圆头的弧线，避免看成加载转圈） |
| 上下文提醒 | 始终与 Pi 终端一致：未舍入的占用比例超过 70% 标「偏高」（运行色），超过 90% 标「将满」（错误色），恰好等于临界值时不提醒；平时饼图为中性色。Pi 未公开这两个阈值，档位由 Extension 按终端规则计算后下发，PWA 不自行判档 |
| 占用未知 | 刚压缩后只显示虚线外框，不显示数值或问号；说明行只写「窗口 200k · 自动压缩」 |
| 信息布局 | 平铺：上下文 → 用量与费用 → 未指定位置的扩展条目 → 会话。桌面与移动顺序一致 |
| 会话分组 | 桌面只有分支（会话名与目录已在标题区）；移动为会话名、电脑名、工作目录、分支。电脑名不带运行状态 |
| 扩展条目 | 不设「扩展」标题；扩展可指定放入上下文、用量或会话块，未指定的放在用量与会话之间的无标题块 |
| 离线 | 不显示状态；桌面不出现卡片，移动抽屉只保留会话分组和一行说明 |
| 连接中断 | 不隐藏卡片，保留最后一份状态原样显示，不另加标注；连接问题由输入区提示行说明，重连后以新订阅的首份替换 |
| 费用为 0 | 照常显示 `$0.000`，不隐藏费用行 |

## 4. 显示内容与数据来源

| 内容 | 显示格式与口径 | 来源 |
| --- | --- | --- |
| 上下文占用 | `42.0%`；说明行 `84k / 200k · 自动压缩`。百分比由 `tokens / window` 计算，与 Pi 终端一样保留一位小数，饼图填充限制在 0–100%，显示数字仍反映实际比例；提醒档位见第 3 节，由快照的 `level` 决定 | `ctx.getContextUsage()` 的 `tokens` 和 `contextWindow`；刚压缩、尚无新的有效模型回复时 `tokens` 为 `null` |
| 自动压缩开关 | 「自动压缩」或「自动压缩已关闭」 | `pi.getSettings().compaction?.enabled`，缺省为开启。终端设置里的切换会写入设置；PWA 在下次状态计算时读取，时机见第 7 节 |
| 输入、输出、缓存读写 | `1.2M`、`48k` 等；按整个会话累计，包括其他分支，不因压缩清零 | 遍历 `ctx.sessionManager.getEntries()`，与 Pi 终端同口径：累计 usage 条目、assistant 消息、带 usage 的工具结果、分支摘要及压缩条目。按公开数据结构自行累加，用夹具与终端口径对照 |
| 缓存命中率 | `87.5%`；整个会话的累计命中率，按 token 加权，与上面几行累计值口径一致，不是各次请求命中率的平均 | 由同一组累计值计算：累计 cacheRead ÷（累计 input＋累计 cacheRead＋累计 cacheWrite）。各服务商的口径已由 Pi 模型库统一为 `input` 不含缓存部分，公式对所有服务商成立 |
| 最近缓存命中率 | `92.4%`；只看最近一次请求，与终端的 `CH` 数值一致 | 与终端一样，取会话记录中最后一条 assistant 消息的 cacheRead ÷（input＋cacheRead＋cacheWrite） |
| 费用 | `$1.284`；为 0 时也显示 `$0.000`。首期不标「订阅」，也不传订阅字段。该数字是 Pi 会话累计估算，不是账单实付金额 | 同上累加的 `usage.cost.total`；公开 SDK 的 OAuth 判断不等于终端的订阅判断 |
| 分支 | 等宽字体单行，过长省略 | Extension 读取当前会话工作目录的 Git HEAD（含 worktree）；分离 HEAD 显示 `detached`，不在仓库内或读取失败时不显示该行 |
| 扩展条目 | 名称＋文字 | 第 6 节的约定 |

两行命中率与终端显示 `CH` 的条件一致：会话累计没有任何缓存读写时都不显示；最近一次请求的分母为零时只隐藏「最近缓存命中率」。

用量缩写沿用 Pi 终端分档：小于 1000 原样显示，小于 1 万保留一位小数加 `k`，小于 100 万取整加 `k`，小于 1000 万保留一位小数加 `M`，其余取整加 `M`。费用保留三位小数。

## 5. 协议

### 5.1 订阅而非握手声明

旧 Extension 严格解码 `session_hello`，在其中加字段会使旧版握手失败。因此不改握手，改为会话就绪后单独订阅：

1. PWA 收到匹配当前连接的 `session_ready` 后，前台页面发送 `session_status_subscribe`（基于 `channelRequest`：`channel_id`、`session_id`、`leaf_id`，加请求 `id`）。Extension 复用 ready-only 校验，按 Relay 认证的 Owner 与 `channel_id` 登记；请求的 `leaf_id` 可引用本次 hello 后同分支的祖先，普通追加不使订阅失效。
2. 请求 `id` 同时是本次 `subscription_id`。同一 Owner、同一 channel 只保留最近一次订阅。每次成功订阅都回复完整首份快照，即使内容与缓存或其他标签页相同；之后按订阅定向推送。PWA 仅接收当前连接、channel、session 和订阅匹配的首份及后续快照，首份还必须匹配 `in_reply_to`。快照的 `leaf_id` 仅表示计算时的 tip：它可以先于 PWA 的正式时间线到达，不用它做相等过滤、推进时间线或触发重连。
3. 真正切分支、换会话、断开连接或重新 hello 时，相关端立即废止旧订阅；PWA 清除旧快照和计时器，在新的 ready 后用不同请求 `id` 重新订阅。即使切走后回到同一 `leaf_id`，旧订阅的帧也不得恢复显示。Extension 在分支／会话失效时先取消待发送的旧快照，再发送既有 `reset`／`bye`；撤销 Owner 权限、解除绑定、重载或退出时清除其订阅。
4. 订阅按 channel 持有 30 秒租约。首份确认后，PWA 在前台每 10 秒复用 `ping`／`pong`；同一 channel 上已发出的有效工具详情心跳也可续租，不另发重复心跳。Extension 只续尚未到期且作用域已校验的订阅，不因 `ping` 创建订阅。页面隐藏后会话状态不主动发心跳；回到前台在当前 ready 连接上用新请求 `id` 重新订阅，取得新首份（已确认旧版的当前 ready 除外）。关页或崩溃不用依赖卸载回调，旧订阅到期停止推送，不影响同一 Owner 的其他 channel。
5. 发送失败、首份快照 10 秒内未到或收到其他匹配的 `protocol_error`，只显示「暂时无法获取状态」，停止本次订阅的计时器并忽略迟到回复。`pong` 本身不证明租约仍存在：PWA 从最近一次已确认的订阅或心跳的发送时刻算续租截止，超出截止的 `pong` 不恢复旧订阅。前台订阅若一个心跳周期内未收到匹配回复，或暂停到可能过期，在同一 ready 连接上重新订阅一次；若失败，等下次恢复前台或重新握手，不循环重试，也不触发主会话重连。
6. 旧 Extension 无法解码新帧，按现有处理回复 `protocol_upgrade_required`。PWA 在通用错误分发前单独消费与当前订阅请求匹配的这一错误，显示「扩展版本较旧」，同一 ready 期间不重试。旧 PWA 不订阅；同一 Owner 有新旧标签页时，消息仍用 `target_channel_id` 隔离，支持该既有定向过滤的旧页面会在严格解码前跳过不属于自己的帧。

### 5.2 状态快照帧

`session_status`（Extension → PWA，定向）：

```text
protocol_version: 2, type: "session_status", target_channel_id
session_id, leaf_id, subscription_id, in_reply_to?（仅首份，等于 subscription_id）
status:
  context:  { tokens: int ≥ 0 | null, window: int > 0, auto_compact: boolean,
              level: "normal" | "high" | "full" | null } | null
  usage:    { input, output, cache_read, cache_write: int ≥ 0,
              cost: finite number ≥ 0,
              cache_hit_rate_session: number(0–100) | null,
              cache_hit_rate_latest: number(0–100) | null }
  branch:   string | null
  extensions: [{ key, label, text, tone?: "warning" | "error",
                 section?: "context" | "usage" | "session" }]
```

- 每份有效快照整体替换，不写入时间线或本地历史。后续快照不依赖中间帧；重连后以新订阅的首份为准。
- 按共享协议严格校验：未知字段与未知枚举值 fail closed。扩展上报中无法识别的 `section` 在 Extension 侧先归为「未指定」，不发送该字段。
- 字符串与数组设上限：`branch` 256，扩展 `key` 64、`label` 12、`text` 160，按共享 schema 的字符串长度口径校验；条目最多 12 条。显示文字超出时在 Extension 侧截断，超长 `key` 整条忽略，避免截成相同身份。
- `context` 为 `null` 表示尚无模型或无法计算，PWA 不显示内置上下文行；显式放入上下文块的扩展条目仍可显示。
- `level` 由 Extension 按 Pi 终端规则计算：未舍入的占用比例超过 90 为 `full`，超过 70 为 `high`，其余为 `normal`；`tokens` 为 `null` 时 `level` 为 `null`。阈值只在 Extension 维护，与 Pi 终端同步调整。
- 帧类型、字段与兼容规则写入 [Protocol v2](../../reference/protocol/protocol-v2.md)，与[工具摘要能力](../../reference/protocol/protocol-v2.md#工具摘要与按需详情)并列；同步[错误与兼容策略](../../reference/protocol/protocol-v2.md#错误与兼容策略)中订阅失败的处理。

## 6. 扩展状态约定（公开接口）

其他扩展通过 Pi 提供的共享事件通道 `pi.events` 自愿发布适合远程查看的状态。上报不是本地 `setStatus`：文本会发给已授权且已订阅的远程页面，并经过 Relay（见第 2 节）。扩展作者不得上报凭据、令牌或只允许本机查看的内容；Pi Reach 不尝试从自由文本中识别秘密。未安装 Pi Reach 时，消息没有接收方，不会出错。

### 6.1 频道与载荷

| 频道 | 方向 | 载荷 |
| --- | --- | --- |
| `pi-reach:status` | 扩展 → Pi Reach | `{ version: 1, key, label, text?, tone?, section? }`；不带 `text` 表示清除该条 |
| `pi-reach:status-request` | Pi Reach → 扩展 | `{ version: 1 }`；请求适配方重发当前状态 |

事件通道不给后加入的监听者补发历史消息，扩展加载顺序又不确定，所以 Pi Reach 在会话启动与重载后广播一次 `status-request`，适配方收到后重发自己的当前状态。适配示例：

```ts
const show = (text?: string) => {
  ctx.ui.setStatus("ci-watch", text); // 终端状态栏照旧
  pi.events.emit("pi-reach:status", { version: 1, key: "ci-watch", label: "CI", text, section: "session" });
};
pi.events.on("pi-reach:status-request", () => show(current));
```

### 6.2 Pi Reach 的处理规则

- `version` 不是 1 或载荷格式不对：忽略这条消息。
- 文字清理：去掉终端颜色码与控制字符，换行与制表符压成空格，合并连续空格并去掉首尾空格；清理后为空视为清除。
- `label` 与 `text` 按第 5.2 节截断；超长 `key` 不截断。超过条数时按 `key` 排序保留前 12 条。
- `tone` 只接受 `warning`、`error`，其他值忽略。
- `section` 只接受 `context`、`usage`、`session`，未提供或无法识别时归为未指定，不丢弃条目，以便以后新增块时旧版 Pi Reach 仍能显示。
- 同一 `key` 后到覆盖先到，与终端 `setStatus` 的语义一致。
- 名称与所在块中 Pi 自带的名称重复（例如在用量块里也叫「费用」）时忽略该条，避免冒充内置数字。
- Pi 重载或退出时清空全部扩展条目，与终端状态栏一致。
- 扩展条目随状态快照节流推送，见第 7 节。PWA 按纯文本渲染，不执行 Markdown、HTML 或链接；内容不写日志。

### 6.3 公开文档

新增面向扩展作者的参考文档 `docs/reference/extension-status.md`：频道、载荷、处理规则、放置规则与示例。它属于公开文档，只描述 Pi Reach 本身，可链接协议文档。

## 7. Extension 实现要点

- 新增独立的状态模块：订阅登记、快照计算、节流与扩展条目表；`index.ts` 已接近单文件上限，只做事件接线。
- 计算时机：收到订阅、`turn_end`、`agent_end`、`model_select`、`session_compact`、`session_compact_failed` 与扩展上报更新。`message_end` 可能早于 SDK 写入会话记录，不能用它确认用量已入账；首期用 `turn_end`／`agent_end` 读回，不逐 token 计算。`session_start` 与 `session_tree` 先废止旧订阅，新作用域在收到订阅时重算。
- 节流：同一会话最多每 500ms 计算一次，窗口内有更新时合并到窗口末尾，确保最后一次变化不会丢失。窗口内同一作用域、且未收到更新的缓存可用于首份快照；窗口结束后的新订阅重新计算。一次计算可回复多个待处理的订阅。首份始终带请求关联；之后只在 `status` 变化时向各有效订阅推送，`leaf_id` 单独前进不触发推送。发送前再次确认订阅与计算作用域仍有效，失败或过期不得记作已成功推送。
- 用量累加可以缓存已处理的条目数，只在增加时补算；会话切换或树导航时整体重算。
- 分支与自动压缩设置在每次计算时读取，不常驻监听、不轮询。若在 Pi 空闲时切换设置或从外部切 Git 分支，已开页面可能保留旧值，直到下次计算事件或重新订阅；打开移动抽屉或续租本身不请求刷新。
- 没有有效订阅时不计算、不发送；仍接收扩展上报以保留当前状态。会话启动与重载后广播 `pi-reach:status-request`。

## 8. PWA 实现要点

### 8.1 桌面卡片

- 位置：主区标题区下方右侧，宽 248，右侧对齐标题区操作带并避让右安全区；浮层卡片样式（`surface`、`edge` 发丝线、`shadow-float`、圆角 12）。只读、不可聚焦，内容随快照替换，不加入场动画。
- 内容：小标题「会话状态」，之后按「上下文 → 用量与费用 → 未指定位置的扩展条目 → 分支及会话块扩展条目」，块间以 `separator` 发丝线分隔；扩展文字单行省略，`title` 显示全文。扩展条目与 Pi 自带的行使用相同的名称与数值样式（含等宽数字），不按来源区分。
- 阅读列让位：按主区实际宽度（侧栏可调宽、可收起）计算。所需主区宽度为阅读列 680＋卡片 248＋卡片右距＋卡片与正文间距＋gutter，原型取值约为 976，侧栏默认展开时对应窗口约 1268。宽于居中所需时正文仍居中。时间线、输入区、「最新」入口，以及标题区下方的局部错误与 Toast，都按同一偏移居中，避免压到卡片。
- 动效：收起或展开侧栏导致偏移变化时，沿用侧栏收展的时长与曲线；拖动窗口时直接跟随，不加过渡。卡片显隐只做淡化。
- 何时不出现：未打开会话、本地历史、Pi 已退出。连接中断或重连期间不隐藏，保留最后一份快照原样显示，不另加标注，连接问题由输入区提示行说明；重连后以新订阅的首份替换。在线等待首份快照时显示「正在获取状态…」，识别为旧 Extension 时显示更新提示，其他订阅失败显示「暂时无法获取状态」。移动抽屉使用同一状态，只替换实时数据区域，会话分组保留；Pi 退出或打开本地历史时不显示旧数值。
- 与 [ADR-20261018](../../adr/20261018-reader-drawer-only.md) 的关系：工具、文件等详情仍只在阅读器 Drawer 打开，桌面阅读器覆盖状态卡片。卡片只读、没有焦点或宿主迁移；移动会话状态抽屉不是另一种详情阅读器。

### 8.2 移动抽屉

- 右侧 Drawer，宽 `min(320px, 85vw)`，四角直角，底色 `grouped-bg`，分组为设置页同款 `surface` 圆角 16 列表；头部为 48 首行，标题「会话状态」与关闭按钮。
- 入口：顶栏右侧原「信息」图标改为打开抽屉，可访问名称为「会话状态」；原会话信息弹层删除，其内容（完整会话名换行、等宽只读路径字段、电脑名）移入抽屉末尾的会话分组，路径字段规则保留。
- 分组顺序：上下文 → 用量（下附「本会话累计，压缩后不清零。」）→ 未指定位置的扩展条目（无标题分组）→ 会话。扩展短文字与名称同行，放不下时换到名称下方左对齐，按实际宽度判断；样式与 Pi 自带的行相同。
- 手势：会话区左滑跟手打开，抽屉上右滑关闭，复用现有投影停点、手势排除与阻断叠层检查。非 standalone 时不接管距屏幕右缘 24px 内起手的左滑，避免抢占浏览器前进手势（待真机核对）。跟手预览不压入 history、不抢焦点、不锁滚动；提交才进入正式打开态，回弹不留下叠层状态。
- 互斥：会话状态、移动导航、阅读器、设置页及其转场不同时激活；已有工作区叠层或转场时，点按和滑动都不能打开状态抽屉。抽屉打开或退出期间拦住其他工作区入口。若路由切换要求退出工作区，先结束状态抽屉及其历史记录，再交接给新层，不把一次退出误作第二次页面返回。
- 叠层：Portal 到 `.pwa-root`，复用 `navigation` 层级和 `scrim`。打开时启用焦点陷阱和滚动锁，只压入一条不改变 URL 的历史记录。若既有流程弹出上层 Modal，遮罩只显示最上层的一份；Back、Escape、遮罩及右滑不得穿透关闭底层，Back 被上层接管时保留抽屉记录供下一次使用。系统原生返回转场不叠加一次退出动画。主屏 PWA 的状态栏背景条在状态抽屉成为顶层时取 `grouped-bg`，被其他层覆盖时沿现行取色规则。
- 关闭及跨断点：关闭按钮、已提交的右滑、遮罩、Escape、系统返回走同一关闭入口，撤回或消费本抽屉的一条 history，不重复 `back()`。切桌面时关闭抽屉或取消未提交的预览，不把抽屉迁移为卡片。退出后若焦点已丢失才回到可用的顶栏状态图标；入口因断点变化而不存在时，回到可聚焦的桌面工作区标题，不抢上层叠层或其他控件已取得的有效焦点。
- 涉及叠层、焦点与手势，按 [overlay 验证技能](../../../.agents/skills/validate-mantine-stacked-overlays/SKILL.md)验收。

### 8.3 上下文饼图

- 自绘 SVG，尺寸 `1em`，与百分比同号：外框 `secondary` 细线，扇形按占用比例从 12 点方向顺时针填充；颜色与标签按快照的 `level`：`normal` 为 `secondary`，`high` 为运行色，`full` 为错误色；占用未知时外框为虚线、无扇形。
- 饼图只是示意，`aria-hidden`；读屏读百分比和标签文字。状态不只靠颜色：偏高、将满另有文字标签。
- 这是 Lucide 之外的自绘图形，需在 DESIGN 图标规则中登记为例外。

## 11. 后续与候选

- **上游只读接口**：已于 2026-11-18 向 Pi 上游提出读取扩展状态文字（或订阅其变化）的只读接口，见 [earendil-works/pi#12298](https://github.com/earendil-works/pi/issues/12298)；上游对新贡献者的 issue 默认自动关闭，待维护者复查。接口可用也不代表本地状态适合远程发布；若考虑接入，须另行决定授权与默认范围，不自动转发未适配扩展的文字。
- **保留退出时的最后状态**：Pi 退出后继续显示内存中最后一份快照并标注「Pi 退出时的状态」，刷新或切换会话后消失。改动小，未纳入首期。
- **本地历史保存状态**：需要改本地历史存储，且可能显示过时数字，不建议。

## 13. 风险

- **刷新延迟**：空闲时外部切分支、终端切换自动压缩，不保证已打开的页面即时更新，见第 7 节；连接中断期间卡片显示的也是断线前的最后状态。
- **阈值跟随**：Pi 的提醒阈值写在终端渲染代码中、未公开；升级 Pi 时需核对阈值是否变化并同步 Extension。
- **扩展条目滥用**：第三方扩展提供自由文本，长度、条数、同名规则和节流只能减少干扰，不能保证内容可信或无敏感信息，见第 6 节。
- **布局联动**：阅读列偏移影响所有以阅读列居中的元素，遗漏会造成压到卡片；验收按第 8.1 节清单逐项检查。
