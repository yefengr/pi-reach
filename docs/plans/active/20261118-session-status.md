# PWA 会话状态（Pi 状态栏信息）方案

- 日期：2026-11-18
- 用途：供实施代理据此实现；本文不是当前实现说明，也不代表已获实施授权。
- 项目级状态：见 [BACKLOG](../../BACKLOG.md#pwa-会话状态)，不在本文另设状态表。
- 视觉稿：[`docs/prototypes/20261118-session-status/page.html`](../../prototypes/20261118-session-status/page.html)，桌面常驻卡片、移动右侧抽屉与扩展状态的呈现已经评审确认；原型数据为合成样例，手势只模拟跟手与过半提交。
- 当前规则来源：[DESIGN「布局与导航」](../../DESIGN.md#布局与导航)、[「移动端滑动」](../../DESIGN.md#移动端滑动)与[「组件规则」](../../DESIGN.md#组件规则)。本方案与其中若干条款冲突，修改清单见第 9 节，须先获授权，并在实现的同一 Pull Request 中同步。

## 1. 背景与目标

Pi 在终端底部有一条状态栏，显示上下文占用、累计用量与费用、当前分支等信息。PWA 目前看不到这些内容：远程使用时，用户不知道上下文是否快满、这个会话已经花了多少钱。

目标是在 PWA 中查看 Pi 自带的这部分状态，并允许其他扩展按 Pi Reach 定义的约定，把自己的状态显示在同一处：

- 桌面：主区右上角常驻一张只读卡片。
- 移动：右侧抽屉，点按顶栏右侧图标或在会话区左滑打开。原有的「会话信息」弹层并入抽屉。
- 默认只显示 Pi 自带的状态；有扩展按约定上报时，才出现扩展的条目。

## 2. 范围与非目标

| 范围 | 说明 |
| --- | --- |
| 共享协议 | 新增状态订阅请求与状态快照帧；能力不足的旧 Extension 以错误回复，不改握手 |
| Extension | 计算上下文、用量、费用与分支；接收其他扩展按约定上报的状态；向已订阅的页面推送快照 |
| PWA | 桌面卡片与阅读列让位，移动抽屉与左滑手势，各状态的呈现 |
| 公开文档 | 协议说明、扩展状态约定（供扩展作者适配） |

非目标：

- 不读取未适配扩展通过 `setStatus` 写入终端的文字。SDK 目前只在替换整个终端状态栏时才交出这份数据，接管终端状态栏副作用过大；只读接口另向上游提需求，见第 11 节。
- 不重复显示模型与思考级别：输入区的模型标签已经显示。
- 离线会话（本地历史、已退出的 Pi）不显示状态。保留退出时最后一份状态作为候选，见第 11 节。
- 卡片与抽屉不提供操作。「压缩上下文」仍从输入区进入。
- 不改变 Relay 职责：状态内容在端到端加密的载荷中传输，Relay 不解码、不记录。

## 3. 已确认的设计决策

以下取舍在原型评审中确认，实施时不再重新讨论：

| 主题 | 决策 |
| --- | --- |
| 桌面形态 | 常驻卡片，不提供折叠按钮；宽度不够时隐藏 |
| 宽度策略 | 阅读列让位：主区放不下居中的阅读列和卡片时，正文与输入区一起左移到刚好让出卡片；左移到 gutter 仍放不下才隐藏卡片 |
| 移动形态 | 右侧抽屉；会话区左滑打开，右滑、遮罩、关闭按钮、Escape 与系统返回关闭；右滑打开导航保持不变 |
| 上下文呈现 | 不用进度条；百分比前放一个与文字同号的小饼图（细外框加扇形，不用带圆头的弧线，避免看成加载转圈） |
| 上下文提醒 | 占用 ≥ 70% 标「偏高」（运行色），≥ 90% 标「将满」（错误色），阈值与 Pi 终端一致；平时饼图为中性色 |
| 占用未知 | 刚压缩后只显示虚线外框，不显示数值或问号；说明行只写「窗口 200k · 自动压缩」 |
| 信息布局 | 平铺：上下文 → 用量与费用 → 未指定位置的扩展条目 → 会话。桌面与移动顺序一致 |
| 会话分组 | 桌面只有分支（会话名与目录已在标题区）；移动为会话名、电脑名、工作目录、分支。电脑名不带运行状态 |
| 扩展条目 | 不设「扩展」标题；扩展可指定放入上下文、用量或会话块，未指定的放在用量与会话之间的无标题块 |
| 离线 | 不显示状态；桌面不出现卡片，移动抽屉只保留会话分组和一行说明 |

## 4. 显示内容与数据来源

| 内容 | 显示格式 | 来源 | 实施前核对 |
| --- | --- | --- | --- |
| 上下文占用 | `42%`；说明行 `84k / 200k · 自动压缩` | `ctx.getContextUsage()`：`tokens`、`contextWindow`、`percent`；压缩后 `tokens` 为 `null` | — |
| 自动压缩开关 | 「自动压缩」或「自动压缩已关闭」 | `pi.getSettings()` 中的压缩设置 | 终端里临时切换的开关是否反映在设置中；不反映时首期只显示设置值，并在本文记录差异 |
| 输入、输出、缓存读写 | `1.2M`、`48k` 等 | 遍历 `ctx.sessionManager.getEntries()` 累加 usage，与 Pi 终端状态栏一致：包括 usage 条目、assistant 消息、带 usage 的工具结果，以及分支摘要与压缩条目 | SDK 未导出累加函数，需自行实现，并用夹具与终端结果对比 |
| 缓存命中率 | `87.3%` | 最近一次 assistant 请求的 cacheRead ÷（input＋cacheRead＋cacheWrite），与终端相同 | 名称是否改为「最近缓存命中率」，在 DESIGN 同步时确定 |
| 费用 | `$1.284`；订阅时加「· 订阅」 | 同上累加的 `cost` | 终端用内部的模型运行时判断订阅，扩展只能用 `ctx.modelRegistry.isUsingOAuth(model)` 近似；口径不一致时首期不标订阅 |
| 分支 | 等宽字体单行，过长省略 | Extension 自行读取工作目录的 Git HEAD（含 worktree）；不在仓库内时为空，不显示该行 | — |
| 扩展条目 | 名称＋一行文字 | 第 6 节的约定 | — |

数字格式与终端一致：小于 1000 原样显示，小于 1 万保留一位小数加 k，小于 100 万取整加 k，其余保留一位小数加 M。费用保留三位小数。

## 5. 协议

### 5.1 订阅而非握手声明

旧 Extension 严格解码 `session_hello`，在其中加字段会使旧版握手失败。因此不改握手，改为会话就绪后单独订阅：

1. PWA 收到 `session_ready` 后发送 `session_status_subscribe`（基于 `channelRequest`：`channel_id`、`session_id`、`leaf_id`，加请求 `id`）。
2. 新 Extension 回复第一份 `session_status`（带 `in_reply_to`），之后状态变化时向该 channel 定向推送（带 `target_channel_id`，不带 `in_reply_to`）。
3. 旧 Extension 无法解码新帧，按现有处理回复 `protocol_upgrade_required`。PWA 只把这个针对订阅请求的错误解释为「扩展版本较旧」，显示更新提示，不重试、不影响会话其他功能。
4. 旧 PWA 从不订阅，新 Extension 不会向它发送新帧，不存在旧页面收到未知帧的问题。

订阅随 channel 存在：同一 channel 重新 `session_hello`（切换会话、重连）时，Extension 丢弃该 channel 的旧订阅，PWA 在新的 ready 之后重新订阅。

实施前核对：PWA 现有的 `protocol_upgrade_required` 处理是否会全局提示刷新页面；需要改为按请求 `id` 区分，订阅失败只进入「扩展版本较旧」状态。

### 5.2 状态快照帧

`session_status`（Extension → PWA，定向）：

```text
session_id, leaf_id, in_reply_to?（仅首份）
status:
  context:  { tokens: int ≥ 0 | null, window: int > 0, auto_compact: boolean } | null
  usage:    { input, output, cache_read, cache_write: int ≥ 0,
              cost: number ≥ 0, subscription: boolean, cache_hit_rate: number(0–100) | null }
  branch:   string | null
  extensions: [{ key, label, text, tone?: "warning" | "error",
                 section?: "context" | "usage" | "session" }]
```

- 每次发送完整快照、整体替换，不做增量，丢帧或重连后不会错乱。
- 按共享协议的严格校验：未知字段与未知枚举值 fail closed。扩展上报中无法识别的 `section` 在 Extension 侧先归为「未指定」，不上线。
- 字符串与数组设上限：`branch` 256，扩展 `key` 64、`label` 12、`text` 160 个字符，条目最多 12 条；超出时在 Extension 侧截断或丢弃，不让整帧失败。
- `context` 为 `null` 表示尚无模型或无法计算，PWA 隐藏上下文块。
- 帧类型、字段与兼容规则写入 [Protocol v2](../../reference/protocol/protocol-v2.md)，与[工具摘要能力](../../reference/protocol/protocol-v2.md#工具摘要与按需详情)并列；同步[错误与兼容策略](../../reference/protocol/protocol-v2.md#错误与兼容策略)中订阅失败的处理。

## 6. 扩展状态约定（公开接口）

其他扩展通过 Pi 提供的共享事件通道 `pi.events` 与 Pi Reach 通信。适配方不依赖 Pi Reach：未安装 Pi Reach 时，消息没有接收方，不会出错。

### 6.1 频道与载荷

| 频道 | 方向 | 载荷 |
| --- | --- | --- |
| `pi-reach:status` | 扩展 → Pi Reach | `{ version: 1, key, label, text?, tone?, section? }`；不带 `text` 表示清除该条 |
| `pi-reach:status-request` | Pi Reach → 扩展 | `{ version: 1 }`；请求适配方重发当前状态 |

事件通道不给后加入的监听者补发历史消息，扩展加载顺序又不确定，所以 Pi Reach 在会话启动与重载后广播一次 `status-request`，适配方收到后重发自己的当前状态。适配示例：

```ts
const show = (text?: string) => {
  ctx.ui.setStatus("ci-watch", text); // 终端状态栏照旧
  pi.events.emit("pi-reach:status", { version: 1, key: "ci-watch", label: "CI", text, section: "session" });
};
pi.events.on("pi-reach:status-request", () => show(current));
```

### 6.2 Pi Reach 的处理规则

- `version` 不是 1 或载荷格式不对：忽略这条消息。
- 文字清理：去掉终端颜色码与控制字符，换行与制表符压成空格，合并连续空格并去掉首尾空格；清理后为空视为清除。
- 长度与条数按第 5.2 节截断；超过条数时按 `key` 排序保留前 12 条。
- `tone` 只接受 `warning`、`error`，其他值忽略。
- `section` 只接受 `context`、`usage`、`session`，未提供或无法识别时归为未指定，不丢弃条目，以便以后新增块时旧版 Pi Reach 仍能显示。
- 同一 `key` 后到覆盖先到，与终端 `setStatus` 的语义一致。
- 名称与所在块中 Pi 自带的名称重复（例如在用量块里也叫「费用」）时忽略该条，避免冒充内置数字。
- Pi 重载或退出时清空全部扩展条目，与终端状态栏一致。
- 扩展条目随状态快照节流推送，见第 7 节。内容不写日志。

### 6.3 公开文档

新增面向扩展作者的参考文档 `docs/reference/extension-status.md`：频道、载荷、处理规则、放置规则与示例。它属于公开文档，只描述 Pi Reach 本身，可链接协议文档。

## 7. Extension 实现要点

- 新增独立的状态模块：订阅登记、快照计算、节流与扩展条目表；`index.ts` 已接近单文件上限，只做事件接线。
- 重新计算的时机：`session_start`、`message_end`（带 usage 的 assistant 消息）、`turn_end`、`agent_end`、`model_select`、`session_compact` 与 `session_compact_failed`、`session_tree`（切换分支会改变上下文），以及扩展上报到达时。
- 节流：同一会话最多每 500ms 计算一次并且只在快照内容变化时发送；流式输出期间不逐 token 计算，与终端在回复结束时更新一致。
- 用量累加可以缓存已处理的条目数，只在增加时补算；会话切换或树导航时整体重算。
- 分支：每次计算时读取 HEAD，无需常驻文件监听；读取失败按「不在仓库内」处理。
- 没有订阅的 channel 时不计算、不发送。
- 会话启动与重载后广播 `pi-reach:status-request`。

## 8. PWA 实现要点

### 8.1 桌面卡片

- 位置：主区标题区下方右侧，宽 248，右侧对齐标题区操作带并避让右安全区；浮层卡片样式（`surface`、`edge` 发丝线、`shadow-float`、圆角 12）。只读、不可聚焦，内容随快照替换，不加入场动画。
- 内容：小标题「会话状态」，之后按「上下文 → 用量与费用 → 未指定位置的扩展条目 → 分支及会话块扩展条目」，块间以 `separator` 发丝线分隔；扩展文字单行省略，`title` 显示全文。
- 阅读列让位：按主区实际宽度（侧栏可调宽、可收起）计算。所需主区宽度为阅读列 680＋卡片 248＋卡片右距＋卡片与正文间距＋gutter，原型取值约为 976，侧栏默认展开时对应窗口约 1268。宽于居中所需时正文仍居中。时间线、输入区、「最新」入口，以及标题区下方的局部错误与 Toast，都按同一偏移居中，避免压到卡片。
- 动效：收起或展开侧栏导致偏移变化时，沿用侧栏收展的时长与曲线；拖动窗口时直接跟随，不加过渡。卡片显隐只做淡化。
- 何时不出现：未打开会话、本地历史、Pi 已退出。等待首份快照时显示「正在获取状态…」，旧 Extension 时显示更新提示。
- 与 [ADR-20261018](../../adr/20261018-reader-drawer-only.md) 的关系：阅读器仍是唯一的右侧 Drawer，打开时覆盖卡片。卡片只读、没有焦点或宿主迁移，宽窄切换只是显隐，不重新引入分栏阅读的复杂度。

### 8.2 移动抽屉

- 右侧 Drawer，宽 `min(320px, 85vw)`，四角直角，底色 `grouped-bg`，分组为设置页同款 `surface` 圆角 16 列表；头部为 48 首行，标题「会话状态」与关闭按钮。
- 入口：顶栏右侧原「信息」图标改为打开抽屉，可访问名称为「会话状态」；原会话信息弹层删除，其内容（完整会话名换行、等宽只读路径字段、电脑名）移入抽屉末尾的会话分组，路径字段规则保留。
- 分组顺序：上下文 → 用量（下附「本会话累计，压缩后不清零。」）→ 未指定位置的扩展条目（无标题分组）→ 会话。扩展短文字与名称同行，放不下时换到名称下方左对齐，按实际宽度判断。
- 手势：会话区左滑跟手打开，抽屉上右滑关闭，复用现有投影停点判定与阻断叠层检查；与导航抽屉互斥。非 standalone 时右缘 24px 内起手的左滑不跟手，避免与浏览器前进手势冲突（与左缘规则对称，待真机核对）。
- 叠层：Portal 到 `.pwa-root`，遮罩 `scrim`，打开时压入一条历史记录，系统返回只关闭抽屉；Escape 只关闭最上层，关闭后焦点回到顶栏图标。主屏 PWA 的状态栏背景条在抽屉打开时取 `grouped-bg`。
- 涉及叠层、焦点与手势，按 [overlay 验证技能](../../../.agents/skills/validate-mantine-stacked-overlays/SKILL.md)验收。

### 8.3 上下文饼图

- 自绘 SVG，尺寸 `1em`，与百分比同号：外框 `secondary` 细线，扇形按占用比例从 12 点方向顺时针填充，平时 `secondary`，偏高为运行色，将满为错误色；占用未知时外框为虚线、无扇形。
- 饼图只是示意，`aria-hidden`；读屏读百分比和标签文字。状态不只靠颜色：偏高、将满另有文字标签。
- 这是 Lucide 之外的自绘图形，需在 DESIGN 图标规则中登记为例外。

### 8.4 文案与国际化

新增中英文文案：会话状态、上下文、偏高、将满、窗口、自动压缩、自动压缩已关闭、输入、输出、缓存读取、缓存写入、缓存命中率、费用、订阅、本会话累计，压缩后不清零、正在获取状态…、扩展版本较旧的提示、离线说明。

## 11. 后续与候选

- **上游只读接口**：向 Pi 上游提出读取所有扩展状态文字（或订阅其变化）的只读接口。接口可用后，Pi Reach 也能显示未适配扩展的状态；同一 `key` 两边都有时，以约定上报的为准。是否提出、由谁提出待维护者确认。
- **保留退出时的最后状态**：Pi 退出后继续显示内存中最后一份快照并标注「Pi 退出时的状态」，刷新或切换会话后消失。改动小，未纳入首期。
- **本地历史保存状态**：需要改本地历史存储，且可能显示过时数字，不建议。

## 13. 风险

- **口径偏差**：订阅判断、自动压缩开关、缓存命中率的口径可能与终端不同，见第 4 节核对项；不一致时宁可少显示，不显示误导数字。
- **扩展条目滥用**：条目文字由第三方扩展提供，可能很长、频繁变化或与内置名称相似；由长度、条数、同名规则与节流约束，内容不写日志。
- **布局联动**：阅读列偏移影响所有以阅读列居中的元素，遗漏会造成压到卡片；验收按第 8.1 节清单逐项检查。
- **旧页面**：已加载的旧页面不会订阅，不受影响；刷新到新版后，若 Extension 仍是旧版，只显示更新提示。
