# PWA 视觉精修与阅读体验设计方案

- 日期：2026-10-18
- 用途：明确下一轮设计评审的目标、候选方向、顺序和验收边界，不增加产品功能。
- 候选事项入口：[BACKLOG](../../BACKLOG.md#pwa-uiux-与动效后续演进)。本文不独立维护项目级事项状态，也不代表已经排期。
- 当前设计真源：[DESIGN](../../DESIGN.md)。候选设计经评审、实际实现和验证后，才按交付范围更新现行规范。
- 授权边界：本次仅编写方案；不据此修改产品代码、生成原型、调整正式默认值或执行提交、推送、部署。

## 1. 目标与推荐方向

让 Pi Reach 在静止时更清晰、长读时更安静、操作时更有层次。重点是现有界面的精修，而不是重新换肤、复刻整套组件或让更多元素运动。

推荐顺序：

1. **边界与表面**：先确认哪里需要轮廓，哪里可以靠底色和留白分组。
2. **排版与密度**：改善结论、过程、操作和元数据的主次，以及中文、路径和命令的混排。
3. **骨架与局部滚动提示**：在不改变加载时钟和真实状态的前提下，优化等待与溢出的表达。
4. **页面／会话动效**：最后按具体问题评审，不把修改现有转场当作必交付项。

每项候选都允许得出“保留现状”的结论。不能仅凭代码存在某条边框、某个圆角或某个时长，就认定当前设计有问题。

## 3. 范围与保持项

### 3.1 本轮只讨论的设计范围

- 现有页面和组件的表面、边框、阴影、圆角、间距及视觉主次。
- 现有文字内容的字号角色、换行、截断、对齐与阅读宽度使用。
- 现有控件在不同容器和输入方式下的视觉密度。
- 现有加载占位、局部溢出提示和必要的状态交接动效。
- 用现有真实组件做设计对照的方法与验收标准。

### 3.2 不随本轮调整的基础

保留[中性底色与雾蓝主色决策](../../adr/20261001-neutral-surfaces-mist-blue.md)、系统字体、状态色语义、单一图标语言和既有布局模型。不加入新字体、图标库、动画库或新的产品设置。

正文与输入保持现行 16px 基准，元数据不低于现行 13px 下限；操作目标至少 44px。可以精修视觉底、间距和对齐，不能靠缩小文字、点击区域或降低对比度制造紧凑感。完整参数继续引用 DESIGN，不在此维护平行 token 表。

本轮不新增产品能力，不改协议、配对、身份、持久化和连接流程；也不以视觉改造为由更改工具分组、运行结束判断、文件获取、消息投递或用户展开选择。

页面返回、手势、焦点、阅读锚点、历史恢复和异步结果的所有权保持现有机制。若候选效果必须改变这些契约，停止该候选，另行说明影响并取得授权。

## 4. 候选清单与优先级

| 编号 | 顺序 | 设计问题 | 对照方向 | 不作为目标的做法 |
| --- | --- | --- | --- | --- |

| T1 | 其次 | 正文、过程信息、元数据和操作是否争抢注意力？ | 用现有文字角色、字重和留白建立主次 | 缩小正文、增加大量字阶、进一步淡化全部次级文字 |

## 5. 具体设计方向

### 5.1 V1：边界与表面

先按“阅读画布、次级承载、主要操作表面、浮层”识别角色，再判断轮廓强度。已有 Composer、浮层和模态的层次规则作为起点，不扩展为普通消息逐条加阴影。

- 优先检查确认框操作区、文件卡片、菜单内分组和阅读器工具栏。外框与内部控件同时描边时，先确认是否表达了不同交互对象。
- 若内部仅需说明内容归属，可比较 ghost、轻底或单向分隔；独立输入字段、需要辨识的操作和危险确认不能机械去掉边界。
- 浅色可以用有限投影辅助浮层归属；深色优先核对明度和边缘强度，不把加深阴影或白色内环当作统一答案。
- 装饰分隔可以轻，承担控件识别或键盘焦点的轮廓仍须满足 DESIGN 的对比度约束。
- 不让卡片在鼠标扫过时普遍上浮，不增加持续发光或背景模糊。

验收重点是“主次更容易辨认”，不是边框数量更少。候选如导致可点击与只读内容难区分，应保留原版。

### 5.2 V2：圆角、内缩与间距

比较相邻曲率和内部留白的关系，不将所有矩形改成同一种圆角。

- 内部控件的圆角应与外容器及内缩距离协调；“内半径接近外半径减去内缩”只作视觉检查，不作为强制公式。
- 标题、正文、说明和操作组继续按现有间距 token 组织，避免同时增加父级 gap 与子级 margin。
- 同类卡片和浮层中的内容起点、图标槽及操作边缘应有可解释的对齐关系。
- 贴屏一侧、全屏面板和安全区继续服从当前几何，不为了圆角在屏幕角上露出下层。
- 不用裁切容器掩盖溢出、切掉焦点轮廓或压缩真实点击区。

### 5.3 T1：排版、对齐与阅读节奏

先固定现有字体、字号和阅读列宽度，通过角色分工改善阅读，不从缩小字号开始。

- 以一轮完整对话检查“用户请求 → 正式回复 → 思考／工具过程 → 结果与元数据”的扫描顺序；不改变默认折叠和用户选择。
- 检查中文长段落、英文模型名、等宽路径和命令并排时的基线、行高与主次。光学校正只作用于确有偏差的图标角色，不给所有 SVG 统一负偏移。
- 标题和长名称按角色选择换行或省略；关键完整信息仍须可获取，不把截断用于隐藏错误原因或必要操作。
- 长路径和连续字符串应安全折行，不撑破容器；原始命令、代码和复制内容不因视觉换行被改写。
- 正文继续舒适阅读，代码与表格保留各自横滚；不为了统一外观强制所有内容采用同一行长和换行方式。
- 时间与计数沿用等宽数字；状态切换保留固定图标槽，不让文字更新推动操作。

### 5.4 T2：视觉密度与容器适配

菜单已具备细指针与触控密度区分，本轮只检查尚有具体问题的消费者，不再造一套全局紧凑模式。

- 候选场景包括长模型列表、导航元数据、阅读器工具栏和窄工作面板。
- 先移除重复说明或无效空白，再评估是否需要按容器收短次级文字；不隐藏发送、停止、关闭、取消和失败后的必要动作。
- 视觉底可以更紧凑，实际命中区域仍至少 44px、互不重叠。两行标题和长名称按内容撑高，不能按单行高度裁掉。
- 存在粗指针的混合设备按可触控条件验收，不因窗口宽而切成仅鼠标可用的尺寸。
- 200% 缩放、短横屏与软键盘场景下仍可完成操作，不能通过缩小文字或移除安全区通过检查。

### 5.5 L1：骨架形态与加载交接

保留现行“超过 300ms 才显示、出现后至少保持 500ms”的防闪机制；约 1.5 秒的呼吸循环作为对照基线。不得混淆动画周期、显示门槛与最短展示时间。

- 保留按消息布局形成的占位结构，检查长短行比例、用户消息块与阅读列位置，不增加复杂的伪内容。
- 先试验降低视觉强度的呼吸；必要时与单条窄扫光比较。循环 1.8–2.2 秒仅为评审起点，不是拟直接采用的新默认值。
- 实际内容达到可展示条件，且既有最短展示条件满足后，即按原状态链交接，不额外等待一轮动画结束。
- 不重置列表、草稿或阅读状态来制造平滑效果，也不在后台补齐、流式增量和历史前插时重播整屏加载。
- 页面隐藏、元素离屏和系统减少动态效果时继续静止；文字状态与真实业务时钟不暂停。

### 5.6 L2：局部滚动边缘

先从一个长菜单的滚动内容区验证，再决定是否扩展。不预先给附件、表格、阅读器和正文统一添加。

- 渐隐只表示该方向还有内容；无溢出、触顶或触底时移除相应边缘，内容和尺寸变化后重新判断。
- 可从 12–20px 的轻边缘做对照，不要求固定渐变档数，也不以复杂算法作为设计收益。
- 固定标题、底部操作、滚动条与键盘焦点不进入淡化范围。若无法保证，缩小适用区域或放弃候选。
- 不让正文末行长期变淡，不用渐隐掩盖截断或错误，不取代原生滚动条。
- 无相应浏览器能力或系统减少动态效果时，可以直接不显示该装饰；滚动、选择和操作照常可用。

### 5.7 M1：页面与会话动效的有限复核

当前设置页与 Drawer 已采用约 200ms 的覆盖模型，会话新内容已有约 240ms 淡入。它们不是待补功能，也没有仅因本方案而失效。

只有在前述静态评审后，仍发现可复现的空白、闪变或不协调交接，才单独提出一个动效对照。

- 优先比较实际问题处的时序与透明度交接，不把“更快”或“更多弹性”作为目标。
- 不引入整页弹簧、逐字模糊、用户文字飞入气泡或历史消息逐条入场。
- 流式 token、Markdown 重排、代码高亮和历史补齐不重播进入动画；快速改选仍只保留最后目标。
- 减少动态效果在打开期间变化也要立即生效；业务结果和资源清理不能等待视觉动画成功。
- 若必须改变跟手、返回、焦点或卸载契约，退出本方案范围，先做独立评估。

## 6. 评审方式与场景

优先复用开发环境的真实组件展厅 `/app/ui-states`，保留历史对照入口，不建立另一套脱离正式样式的完整组件样例。当前展厅实现见 [ui-states.tsx](../../../pwa/src/dev/ui-states.tsx)。需要补充受控状态或候选切换时，先单独确认该批开发范围；本次文档授权不包含这些改动。

每组先保存当前版，再提供一个候选；同一轮固定内容、字体、视口和主题，只改变一个设计变量族。先看静止画面，再按常速交互；慢放仅用于检查过程，不延长复制反馈、加载门槛或业务超时。

| 场景 | 主要观察项 |
| --- | --- |
| Composer、长模型菜单 | 外内轮廓、圆角关系、聚焦、完整名称、窄容器和点击区域 |
| 含长文与工具过程的完整对话 | 正文主次、混排、状态槽位、用户折叠选择和阅读位置 |
| 附件／文件的获取、成功与失败 | 文件名和元数据位置、操作稳定性、局部反馈，不重设计获取流程 |
| 设置表单、确认框与菜单交接 | 分组层次、主次操作、危险识别、Tab、Escape 和回焦 |
| 工具／文本阅读器及宽窄迁移 | 工具栏密度、正文可读性、选区、滚动与焦点保留 |
| 会话加载、只读历史和长菜单溢出 | 骨架交接、边缘开关、首次与增量内容的区别 |

受影响场景至少覆盖明暗主题、中文／英文、长名称／长路径、宽桌面、窄面板、手机与短横屏。视觉改动检查桌面 200% 缩放；输入密度改动另验细指针、粗指针和混合输入；动效改动另验初始及运行中减少动态效果。按影响选择交叉组合，不机械穷举所有场景。

评审记录包含：候选编号、组件与版本、单一变量、截图或录制条件、用户取舍、理由、验证范围和未覆盖项。每项可以“采用候选”“保留现状”或“补证后再议”，不预填用户偏好，不由浅色桌面结论推导深色或真机也已通过。

## 8. 验收与停止条件

| 风险面 | 验收要求 |
| --- | --- |
| 视觉主次 | 对照能说明哪一层更清晰；必要的控件边界、危险识别与键盘焦点未减弱 |
| 文字与主题 | 保持 DESIGN 对比度底线；中文长文、混排、长名称与缩放下可读，无非预期页面横滚 |
| 触达与容器 | 关键操作始终可达，目标至少 44px 且不重叠；触控不依赖 hover，焦点不被裁切 |
| 布局与阅读 | 不丢草稿、展开选择、正文选区与阅读锚点；状态变化不造成无意义挤动 |
| 异步与加载 | 成功只来自真实结果；骨架防闪、复制反馈和文件就绪时序不被演示动画改写 |
| 叠层与返回 | 受影响的 Portal、单层遮罩、最上层 Escape、回焦、滚动锁和 Back 继续遵守既有契约 |
| 动效与资源 | 连续开关、反向、禁用、卸载和运行中减动正确落态；无迟到动画、残留遮罩或持续离屏循环 |
