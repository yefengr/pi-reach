## 背景与目标

本轮实施前，工具主列表已经主要展示工具名、命令／路径与状态，完整参数和输出在点击后阅读；底层却仍随正式事件和历史恢复传输完整工具内容。用户没有查看详情，也会承担大段文件正文、日志、Diff 和图片 Base64 的传输、解析与缓存成本。

第一层修复解决了持续有进展的历史请求被过早判定超时，以及恢复期间的发送门禁问题。它不减少数据量，也不承诺提速。本方案进一步让传输方式与查看方式一致：

> 日常只同步工具摘要；打开详情后获取那次调用的内容。运行中继续实时跟随，关闭后停止向该页面发送详情更新。模型思考与回复正文的流式链路保持不变。

## 范围与非目标

本方案同时覆盖工具准备、运行、完成后的实时同步，以及历史恢复和旧缓存读取。优化的是发送给 PWA 的展示数据，不改变工具实际执行、模型收到的工具结果或 Pi 原始会话的保存方式。

本方案不包括：

- 删除原会话、丢弃图片、清空浏览器历史，或用空参数／空结果冒充轻量记录。
- 将模型思考或助手回复正文改为点击后加载，或降低它们现有的流式体验。
- 永久保存、完整回放每一次工具中间更新，或另建完整工具结果数据库、图片文件库。
- 为 Relay 增加内容存储、图片服务器，或要求电脑另开 HTTP 下载服务。
- 改变本地只读历史的数据来源，后台连接远端补详情，或自动寻找其他 Pi 进程。
- 改变配对、授权、消息投递确认、正式历史顺序、分支替换和只以 `run_end` 确认本轮结束的语义。

## 两条数据链路

### 常规时间线：只传工具摘要

Extension 在源头生成轻量正式记录，实时与历史使用一致的摘要表示。摘要至少要表达：

- 稳定事件身份、所属会话／轮次、时间和顺序。
- 工具名称、操作类型、有界的命令／路径／读取范围／搜索词摘要。
- 准备、运行、成功、失败和中断状态。
- 可定位那次原始调用的详情引用，以及详情可用性。

摘要从工具名称和必要参数提取，不新增模型调用；未知工具保守概括。完整文件正文、修改内容、日志、Diff 和图片不进入常规工具记录。

摘要需要总大小预算，不能只限制单个字符串，让大量字段、嵌套对象、长命令或 heredoc 绕过限制。不能先为全部历史构建、复制并序列化完整大结果，再在发送前删除字段。

### 详情链路：打开时获取，运行中定向更新

- 未打开详情时，主列表仍接收摘要与状态；进入视口、悬停或展开过程组不触发详情获取。
- 打开已完成的调用时，优先复用有效的最终详情缓存，否则按引用获取原始记录。
- 打开运行中的调用时，获取当前参数与可用预览，并接入后续实时更新。首次快照与后续更新的衔接不能留下丢失窗口，也不能重复追加快照内容。
- 阅读器保持打开时，只向有权查看该调用的对应 channel 发送详情更新；不能为一个阅读器继续向所有页面广播完整结果。
- 关闭、换选其他调用、切会话、失去权限或断连时，解除该页面的详情订阅并停止新增详情发送。已在途的过时响应不能覆盖当前阅读选择。
- 工具完成且阅读器仍打开时，自动获取、校验并展示正式结果；未打开时不自动下载最终详情。手动刷新只作为失败、断线后的补救，不是正常观看方式。

详情状态与工具状态独立。至少要区分未获取、加载中、运行预览、最终结果、失败和不可用；未获取不等于工具没有输出。详情加载失败、超限或被回收，只影响阅读器，不能改变工具成败、本轮结束判定或发送就绪。

## 完整详情从哪里来

### 已完成：Pi 原始会话

Extension 经 `SessionManager` 读取那次调用对应的原生记录：调用参数来自模型消息中的结构化工具调用，结果来自对应的工具结果消息。现有历史恢复已经使用这些记录；本轮新增的是按引用获取单次详情的接口，不是新的权威数据来源。

详情引用必须绑定足够的 runtime、会话、分支和事件作用域，不能只凭工具调用 ID 查询，也不接受任意本机文件路径。普通消息提交造成的 leaf 推进，不应无故使仍属于合法分支的旧详情失效。

“完整”以 Pi 当时实际保存且按现有规则允许展示的内容为准：

- 不重新执行工具，不读取后来变化的文件，也不让模型重新生成结果。
- 工具当时已截断、原始记录已缺失的内容，不能凭空恢复；明确提示受限或不可用。
- 图片 Base64 如果仍在原始结果中，即使没有独立图片文件，也可从该记录获取；不能只靠已经截断或带 omitted 占位的旧展示事件反推原件。
- 现有参数隐藏规则同样适用于详情接口，尤其不能借完整参数暴露 `publish_file` 的本机源路径。

### 运行中：已有生命周期状态与有界预览

当前参数来自工具调用／执行生命周期，输出预览来自工具更新事件。原始会话文件不保证保存每一次实时更新，不能假设重读文件就能得到全部运行中输出。

为支持中途打开阅读器，需要在 Extension 端管理可获取的当前预览，复用已有预览截断与更新语义。该能力不能变成额外保存完整工具过程的缓存：

1. 只为仍活跃的调用保留最新一份有界预览，新快照覆盖旧快照，不累计保存每一帧。新增预览缓存不复制保留完整大参数、图片 Base64 或最终大结果；优先复用已有调用状态。
2. 同时约束单调用大小、全部预览合计大小和保留数量。达到预算时，限制或回收未查看预览并明确标记；不能阻塞工具执行，也不能把预览受限误报成执行失败。
3. 正式结果已经可读取后释放对应预览，不能在最终记录尚未可用时提前清空唯一可见状态；取消、会话切换等终止路径也要清理。
4. 预览被回收且无法恢复时，显示当前不可用，继续等待后续更新或最终结果，不伪造一份完整快照。
5. 复用节流与有界发送，避免每次更新复制或序列化整段大对象。缓存额度不等于整个进程的内存上限，还须测量临时副本、SDK 原有状态及发送队列带来的峰值。

2026-11-08 冻结首版资源预算如下。它们是本轮实施输入，数值真源见[共享协议常量](../../../packages/protocol/src/session/schema.ts)，不是整个进程或手机的内存峰值承诺：

| 资源 | 本轮冻结边界 |
| --- | --- |
| 结构化摘要 | 每字符串最多 512 个 code unit，摘要对象编码后不超过 4 KiB |
| 运行预览 | 每调用编码后 64 KiB；全进程合计 512 KiB、最多 8 份，只保留最新状态 |
| 活跃详情订阅 | 每 channel 至多 1 份，全进程最多 16 份；运行期间每 10 秒续租，30 秒失联过期 |
| 单次正式详情 | 编码后最多 8 MiB，超限返回明确不可用，不截成假的完整结果 |
| 详情发送队列 | 16 MiB，计入 Base64 与底层 WebSocket 等待发送的数据，不借此阻塞思考／回复 |
| PWA 最终详情缓存 | 文档合计 16 MiB、最多 64 份，按使用情况回收；预览不作为最终结果入缓存 |

预算检查避免先分配完整超大 JSON；[有界 JSON 计数](../../../packages/protocol/src/session/json-budget.ts)将编码字节计数与完整序列化分开。仍需测量编码临时副本、SDK 既有状态、传输队列和浏览器渲染的实际峰值。

## 过程区中的流式内容分别处理

| 内容 | 已核对的行为与方案边界 |
| --- | --- |
| 模型思考与回复正文 | 来自独立的助手流，保持现有同步和流式展示，不纳入工具详情裁剪。 |
| 工具参数生成 | 已有准备阶段的预览、节流和截断。主列表只更新必要摘要；打开详情后保留现有参数预览更新。 |
| 标准 `read` 的文件结果 | 核对的标准实现主要在读取完成后返回结果，不是逐行向 PWA 推送文件内容；阅读器打开时自动展示最终结果，不要求手动刷新。 |
| `bash` 或自定义工具的运行进展 | 按实际工具更新事件持续提供预览；打开详情时实时接收，关闭后停止向该页面发送详情。自定义工具的具体输出以其实际行为为准。 |

实时查看与永久回放不是同一项能力。正式历史保存的是工具最终返回的记录，并不保证包含每一条中间进度。保留实时体验，不意味着新增无限增长的运行日志库。

## 字节预算与分页范围

首版沿用现有历史分页、游标、条数限制、窗口累计字节上限及单帧／分片上限，不新增更细的目标预算分页优化。

需要分开处理三件事：

| 内容 | 本方案取舍 |
| --- | --- |
| 已有窗口和传输保护 | 保留。思考、长回复、大段用户输入等非工具事件仍可能较大，不能只按条数估算体积。 |
| 更小目标预算与首屏分页策略 | 暂缓。工具详情移出常规同步后，测量剩余窗口体积、首次可见时间和完整恢复时间，再决定是否单独优化。 |
| 详情大小、分片、预览和缓存预算 | 独立设置。不能把大数据从时间线移到详情接口后就不设边界，也不能超限后退回全量历史补发。 |

分片只拆开发送，不减少一次请求的总量；细拆更多分页也可能增加往返和恢复复杂度。工具详情分离与后续分页优化的收益应分别计量。

## 协议、缓存与兼容

原有严格 schema 要求工具事件携带参数／结果，不能直接删字段或填空值冒充摘要。本轮在[共享 schema](../../../packages/protocol/src/session/schema.ts)中增加显式 `representation: "summary"`、结构化摘要与 `tool_ref`；旧 inline 记录仍可解码。详情引用使用 assistant 调用的稳定原生 marker／entry 身份及工具调用 ID，请求另带轮次与会话／分支作用域；不能只靠工具调用 ID 查找结果。

[详情帧](../../../packages/protocol/src/session/frames.ts)使用独立的打开／关闭请求，以及定向 chunk／error 响应。每份更新是带单调 revision 的当前快照；分片沿用现有上限，最终片携带总字节数和 SHA-256。PWA 在当前阅读选择下校验完整后替换正文，不按更新次数追加日志。两端接入与本地验证证据见下文；兼容 UX 和设备验收仍单列，不仅凭共享定义存在判定完成。

详情请求和订阅必须关联到 Owner、channel、runtime、会话、分支与当前阅读选择。复用现有请求关联、分片、完整性校验和取消机制，不引入平行的通用下载系统。重连时补当前状态，不承诺回放所有中间帧。

PWA 正式时间线与详情缓存分别管理。详情缓存有总量和回收边界，并区分运行预览与最终结果；不能把预览当作最终缓存。旧缓存中已有的完整内容继续可读，不因收到摘要而被静默抹除；旧记录的截断／省略标记也要保留，不能把它们误认成完整详情。

本轮冻结的兼容行为如下：

| 组合 | 行为 |
| --- | --- |
| 新 PWA + 新 Extension | 启用轻量工具记录、按需详情与阅读期间的实时更新。 |
| 新 PWA + 旧 Extension | 兼容旧完整事件，但不声称已经获得体积优化。 |
| 旧 PWA + 新 Extension | 服务端拒绝无能力 hello，不发送新工具记录或回退混发完整结果。已加载的旧 JavaScript 只能显示通用错误，无法补上专用升级文案，刷新并实际加载新版 PWA 后才能正常协商；用户已明确接受此 U1 边界，不声称旧页面已具备专用刷新提示或无感兼容能力。 |

新 PWA 先发送原样 hello，以兼容旧 Extension；新 Extension 对未声明能力的 hello 返回明确的刷新升级提示，不登记就绪。新 PWA 仅对当前 hello 的该响应补发一次声明 `tool_details: 1` 的 hello，成功后由 ready 回显能力。新工具摘要按已协商 channel 定向发送，避免同一 Owner 的旧页面因扇出收到新工具格式。

主动关闭即取消订阅并停止使用该选择的数据，不等待阅读器退出动画。已经发送的在途数据不能撤回，迟到响应必须丢弃。服务器在已知断连、权限变化和作用域重置时清理；同 Owner 的其他页面仍在线时，单 channel 的未被观察失联由上述有限租期兜底，不能把主动关闭推迟到租期结束。

发生协议变更时仍遵循先发布 PWA、后发布 Extension 的既有流程；本次 PR 授权不包含正式应用发布或 Extension npm 发布，功能分支 staging 部署按仓库流程另行确认。

## 保持的边界

- 正式事件身份、顺序、连续序号及分支替换的原子校验与持久化语义保持正确。详情数据不能插成第二份正式工具事件。
- 只有必要的轻量正式历史完成校验与持久化后才进入发送就绪；详情下载与订阅不进入发送门禁。提前显示部分内容仍不等于恢复完成。
- 模型思考、助手回复和明确交付给用户的文件／图片沿用现有链路；工具执行成功不等于整轮已经结束。
- 本地只读历史不暗中建立远端连接。Pi 离线时，摘要与有效缓存可读，未获取或已回收的详情明确不可用，不自动寻找其他进程。
- Relay 只转发外层帧，不解码、记录或持久化 `ct`。当前 `ct` 是 JSON 的 Base64 封装，不是应用层端到端加密数据，传输保护依赖 TLS。
- 日志、基准报告和测试输出不包含本地源路径、凭据、配对码、消息正文或图片 Base64；自动化夹具使用明确标注的隔离合成数据。

## 实施顺序与验收

以下为已经获得授权的实施顺序，不是已完成工作清单；实际结果必须以代码和验证证据核对：

1. **冻结契约。** 确认摘要与引用、授权／分支校验、快照与实时更新衔接、订阅释放、全部资源预算、旧缓存合并和兼容策略。
2. **轻量主链。** 工具准备、运行、完成与历史恢复统一使用有界摘要；沿用现有分页与字节保护，避免完整事件仍被旁路广播。
3. **按需详情。** 接入原始记录读取、打开期间的实时更新、终态切换、加载／失败／取消、缓存及各类清理路径。
4. **正确性与收益验收。** 自动化验证相关契约，再以同条件基线及手机真机补证；只有轻量化后仍有证据表明分页是瓶颈，才另行评估细化分页。

关键验收标准：

- 从未打开详情时，详情获取请求与详情正文更新为零；进入视口、展开过程组、历史恢复和切回会话不偷偷预取。
- 新模式的常规工具记录不含完整大参数、结果正文或图片 Base64；同数量调用的常规同步量不再随原始大结果等比例增长。
- 打开运行中详情后能持续看到真实更新，标准 `read` 完成后自动显示结果；思考和回复正文的流式行为不退化。
- 关闭确认后停止新增详情发送；换选、取消、断连、权限变化和切分支时，迟到响应不能覆盖新选择，首次快照与后续更新不丢失衔接、不重复追加。
- 预览保有量在单调用、全局和数量预算内，不随更新次数或历史长度无限增长；正式结果可用后与各类终止路径均正确清理，受限只影响预览。
- 详情失败、超限或不可用不改变工具状态、正式历史、`run_end` 或发送门禁。旧完整缓存、截断记录、Pi 重启和离线行为明确且无静默丢失。

测量常规传输文本与解码字节数、请求／分片数量、首次可见时间、完整恢复时间、详情打开与更新延迟、Extension 和浏览器内存峰值及缓存复用。工具详情分离以第一层修复后的同条件基线比较；后续分页评估以轻量化后的结果判断，不混算收益。

覆盖文本、大参数、长日志、图片及单个大结果，并包含并行工具、慢网络、中途停滞、关闭／重开阅读器、取消、重连、切会话／分支、旧缓存和原记录不可用。自动化之外仍需 iOS／Android 真机补证，桌面移动视口不能代替设备验收。

相关历史参考：[2026-10-21 PWA 生产编译性能 A/B 报告](../completed/20261021-pwa-production-ab-report/README.md)保留流式显示与渲染优化前后的主线程工作量、DOM 显示延迟、JS 堆参考，以及原始结果、构建证明与复现方法。它比较两个历史版本的受控生产编译回放；与下文工具载荷／按需详情的合成比较具有不同基线和测量范围，不能混算收益，也不代表当前版本、手机能耗或真机验收结果。
