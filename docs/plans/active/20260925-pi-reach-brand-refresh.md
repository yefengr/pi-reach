# Pi Reach 品牌刷新方案

本方案定义 Pi Reach 界面与主题的重构目标：品牌、工作区结构、配色、设计基础层及其所需的协议补充。它描述的是目标状态，不是当前 PWA 的实现；2026-09-27 已获准按「分阶段实施」落地，各部分落地时取代 [DESIGN](../../DESIGN.md) 的相应部分，并按「实施边界」同步其他长期文档。产品能力与用语边界见 [CONTEXT](../../CONTEXT.md)。设计值不以现有 CSS、Mantine 色阶或原型组件为边界，实施时再建立适配关系；所有数值仍须按「资产与验收」在真实页面和设备上验收，未通过的组合修正后再写入设计真源。各项结论的评审出处见文末「评审记录」。

## 品牌

- 产品名保留 **Pi Reach**，正式界面支持中文和英文，规则见「双语排版与语言选择」。
- Logo 使用「桥」的无角标微圆角版：重新绘制的单色几何 π，以一体化横梁、柔和的外侧端点和延伸的右腿形成识别；不使用右上方块或圆点。方案 B「路径」不再推进。「Pi Reach」字标随 Logo 以 SVG 提供。
- favicon 与安装图标使用固定钢雾蓝底、白色「桥」标识，浅深界面共用同一图标。
- 色彩使用 Pi Reach 自有的「钢雾蓝」；B「海雾蓝」不采用。PiRoam B2 的中性承载、蓝色用于交互的原则仅作方向参考，不沿用其色值。
- 蓝色负责主操作、链接、焦点和选中；页面与长篇对话以中性色承载。在线、运行中、完成、错误与离线必须同时有文字或图形提示，不能只靠颜色区分。

## 工作区

- 布局为「导航常驻」：桌面侧边并列呈现已配对电脑、在线 Pi 与本地历史，主区用于连续阅读；移动端为单栏会话与导航入口。
- 内容边界为「开放阅读」：在线 Pi／本地历史分组、长消息和工具记录以留白与对齐组织，不为每个分组或助手消息加边框与分隔；用户消息轻底、工具输出表面和设备选择器等必要边界保留。信息密度为「紧凑」，具体数值见「设计基础层」。
- 工具执行状态行不使用横向分割线：保留命令、完成／运行等文字与图形状态，以行间留白和对齐区分。
- 桌面工作区不设全局顶栏，侧栏贯通工作区高度；会话标题区承载当前会话、连接状态和刷新入口，侧栏收起时这些信息仍可见。不照搬参考截图中的项目路径栏或额外环境面板。
- 桌面侧栏收起后主区占满可用宽度，阅读列和输入区保持各自宽度上限并随主区重新居中，不固定在展开态的屏幕坐标。
- 桌面侧栏收展使用成对的左右箭头，按钮无常态外框：展开时折叠箭头位于侧栏品牌行右端，收起后在会话标题区左端保留展开入口（2026-09-29 由原「中部偏上」调整，见 [ADR-20260929](../../adr/20260929-sidebar-toggle-placement.md)）。侧栏收起时不在会话标题旁重复显示 Pi Reach 标识。
- 工作区中无框的纯图标按钮（侧栏收展、刷新、会话更多、输入区「＋」等）按「设计基础层」的无框图标按钮规则呈现；圆形高亮不套用到实心发送按钮、带文字入口或有边框的控件。
- 移动工作区顶栏不显示 Logo；菜单图标与当前会话名共同构成可点击导航入口，无入口外框。悬停和键盘聚焦时只在图标周围显示圆形反馈，不为标题铺整块底色；入口保持 `44px` 点击高度。
- 查看完整会话名：导航列表、侧栏与移动顶栏中的会话名保持单行截断（桌面悬停以 `title` 显示全名）。会话「更多」菜单（顶栏或会话标题区右侧）顶部设只读信息区，下方才是操作项：完整会话名（`14px`／`600`，换行不截断）、工作目录完整路径（等宽 `12px`／`secondary`，可换行、可选中复制）、电脑名 · 状态（运行中或空闲，`12px`／`secondary`）。本地历史会话同样提供「更多」菜单，只含信息区、不提供操作；桌面与移动端一致。
- 桌面与移动端的设置均为独立页面，不保留工作区侧栏，提供返回进入前界面的入口。移动设置页不沿用工作区顶栏，不显示 Logo 和连接状态；正文顶部以单行无框返回箭头（`44px` 点击区域；可访问名称随来源为「返回导航」或「返回工作区」）与「设置」标题呈现，不分上下两行，也不另设固定顶栏。此移动结构不套用到桌面。
- 从已展开的移动导航进入设置，返回时恢复原来展开的导航、选中项和滚动位置；从工作区进入，返回原工作区并保留会话／历史、草稿与阅读位置。页内返回与浏览器／系统后退遵循同一恢复规则。
- 设置页焦点：进入后焦点落在页面标题「设置」上（可接收程序焦点、不在 Tab 顺序中），再按 Tab 到返回按钮；浏览器标签页标题改为「设置 · Pi Reach」，返回后恢复。返回时焦点回到进入设置的入口（导航或桌面侧栏中的设置入口）。刷新或直接打开 `/app/settings` 时不强制移动焦点。

### 设置页路由

- 设置页使用子路径 `/app/settings`，桌面与移动一致。进入设置时 `pushState` 一条记录：URL 表示当前页面，该记录的 history state 保存来源（工作区或已展开的移动导航）及恢复所需状态（导航展开、选中项、滚动位置等）；草稿与阅读位置沿用各自既有的保存方式。
- 页内返回与浏览器／系统后退都回到上一条历史记录，并按 history state 恢复来源。页内返回不另建新记录，避免后退时再次进入设置。
- 刷新或直接打开 `/app/settings` 时停留在设置页；此时没有来源状态，返回进入默认工作区，并用 `replaceState` 补一条工作区记录，保证返回后再按后退不会离开应用或回到设置。
- 在工作区按浏览器前进时重新进入设置页，以正常进入动效呈现。
- 未识别的 `/app/*` 子路径显示默认工作区并把 URL 改回 `/app`，不显示 404。
- 实施前提：nginx 为 `/app/*` 回退到应用入口（保留现有 `/`、`/app/` 的重定向）；Service Worker 为 `/app/*` 的导航请求回退到已预缓存的 `/app`，保证离线和安装后打开子路径可用。manifest 与 Service Worker 的 `scope` 已为 `/app`，按前缀匹配已覆盖子路径，无需改动。须以自动化测试覆盖在线刷新、离线打开和已安装 PWA 打开 `/app/settings`。
- 产品路由约定由「唯一产品路由为 `/app`」改为「产品路由均位于 `/app` 下」。

### 动效

- 桌面侧栏收展使用 `220ms` 轻量过渡。
- 移动导航正常开关从左侧轻量进出，`240ms`。移动独立设置页使用 `200ms` 整页水平推入／返回，不是抽屉，不以淡入淡出代替左右滑动：从工作区进入时工作区向左离场、设置页从右滑入；从已展开导航进入时以当前可见导航为离场视图，不先播放导航关闭动画，也不闪回工作区。返回时反向显示进入前的视图，不擅自关闭导航。
- 导航与设置页的衔接采用状态恢复而非保持叠层：从导航进入设置时，导航叠层随推入转场直接关闭（不单独播放关闭动画），其展开状态、选中项和滚动位置记入该历史记录的 state；设置页期间不存在导航遮罩和焦点限制。返回时按记录以展开态呈现导航，随 `200ms` 返回转场滑入，不另行播放 `240ms` 导航打开动画；焦点落在导航中进入设置的入口上。
- 桌面与移动端的居中 Modal 统一轻量进出：单层遮罩淡入、弹窗轻微位移并淡入，进入约 `180ms`，退出反向约 `140ms`。范围包括新建会话、删除配对、清除本地数据的确认，以及配对和重命名弹窗；只统一整个弹窗的进出，不给扫码／连接或保存等内部状态额外套动画，不改变确认、取消、Escape、遮罩关闭、异步阻止关闭或焦点返回规则。侧边 Drawer、移动导航和 Popover 保持各自的动效，不套用居中弹窗位移。
- 工具行与思考正文的手动展开／收起使用轻量高度伸缩，内容略微位移并淡入／淡出，箭头同步转向；进入约 `160ms`，退出约 `120ms`。只在用户切换展开状态时播放；已展开的流式输出即时更新，不对新增内容反复播放动画。
- 退出与卸载（适用于居中 Modal、工具行与思考正文等需在退出动画后卸载的内容）：关闭开始时焦点立即返回来源控件，不等动画结束；退出期间该内容不可交互（`inert`，不接收指针与键盘）。动画中途再次触发时从当前位置反向，不排队、不从头重播。退出动画结束后卸载，并以时长加 `50ms` 的超时兜底，防止过渡结束事件未触发时内容滞留；开启减少动态效果时按淡化时长卸载。工具收起期间照常接收流式输出，但不再渲染到正在收起的区域。
- 减少动态效果：只跟随系统的 `prefers-reduced-motion: reduce`，应用内不另设开关。开启时取消所有位移、缩放与高度伸缩（侧栏收展、移动导航、设置页推入／返回、Modal 位移、工具与思考展开），统一改为约 `100`–`150ms` 的透明度淡化；设置页此时以交叉淡化代替水平滑动，这是「不以淡入淡出代替左右滑动」的唯一例外。箭头转向直接切换。加载指示器、运行中状态图形等表达状态的动画照常运行。以全局媒体查询统一实现，不为各组件单独维护降级逻辑。
- 动效曲线见「设计基础层」。

中性层级约束（后续调色须保持）：

- 文字只保留 `ink`、`soft-ink`、`secondary` 三级，不设 `muted`。`secondary` 须在全部中性底（`bg`、`surface`、`panel`、`message`、`hover`、`neutral-active`、`disabled-bg`、`accent-wash`）上达到 4.5:1，列表行悬停或选中后小字不必换色。
- `hover` 对其所在底（`bg`、`panel`、`surface`）至少 1.10:1，`neutral-active` 对 `hover` 至少 1.08:1；`accent-wash` 对 `panel` 至少 1.14:1，且其上 `accent` 仍达 4.5:1。`accent-wash` 与 `hover` 亮度相近，靠色相与 `accent` 文字区分。
- `disabled-bg` 不得与 `hover` 同值；禁用态不能看起来像悬停。
- 凡落在 `code-bg` 上的强调色、状态色和定位图形（深色主题代码块、配对扫描框），无论页面明暗，均使用深色主题版本；浅色主题代码块位于 `panel` 上，使用浅色版本。

### 状态色

在线使用 `accent`；「任务完成」才使用绿色。配对等待、重连及工具运行使用琥珀色；配对失败、消息／工具错误及危险操作使用红色；离线与只读历史分别用中性文字和独立文案表达，不用绿色或红色暗示可操作。状态在列表、提示和按钮中均保留文字或图标，不能只依赖颜色。

| 状态角色 | 浅色文字／图标 | 浅色轻底 | 深色文字／图标 | 深色轻底 |
| --- | --- | --- | --- | --- |
| 完成 | `#347953` | `#EAF3EC` | `#95CBA8` | `#26392E` |
| 运行中／重连 | `#90611F` | `#F9F2E6` | `#DFBA77` | `#3D3528` |
| 错误／危险 | `#AE463E` | `#F8ECEA` | `#EFA39B` | `#422F30` |
| 离线／不可用 | `secondary` | `panel` | `secondary` | `panel` |

在彩色**实心**状态按钮上，浅色用白字，深色用 `#172638` 深字；普通提示优先使用「状态文字＋轻底」，正文仍用 `ink`。危险实心按钮悬停／按下分别采用浅色 `#973B34`／`#82312C`、深色 `#F4B2AC`／`#F8C4BD`，文字沿用上述明暗前景；非实心危险按钮沿用状态轻底。实心危险按钮仅用于确认弹窗的最后一步，按钮层级见「设计基础层」。

### 场景用法

| 场景 | 浅色 | 深色 | 不得混淆的含义 |
| --- | --- | --- | --- |
| 首次启动、未配对、无在线 Pi | `bg`／`surface` 承载，`accent` 标识可执行主操作 | 对应深色角色 | 「未配对」不等于「离线」；不能暗示可启动 Pi |
| 配对扫描与等待／失败／成功 | 扫描框用 `code-bg` 中性底和深色 `accent`（`#A9C3E6`）定位；等待用运行色，失败用错误色，成功用完成色 | 对应深色角色 | 扫描视频不得加品牌色蒙层；状态写清下一步 |
| 在线 Pi、正在工作、已完成工具 | 在线入口用 `accent`；运行用琥珀色；完成用绿色 | 对应深色角色 | 「已连接」不等于「已完成」 |
| 消息、只读历史与空态 | 内容阅读区用 `bg`；用户消息用 `message`；历史用 `panel` 与文字标识，禁用发送 | 对应深色角色 | 本地只读记录不伪装成在线会话，小字用 `secondary` |
| 选中会话、设置项、命令入口 | `accent-wash`＋`accent`；非选中项用 `ink`，悬停用 `hover` | 对应深色角色 | 焦点另以 2px 强调色轮廓表达，不只靠浅底 |
| 正常按钮、次级按钮、禁用 | 主操作用 `accent`＋`on-accent`；次级操作用 `surface`＋`ink`，悬停用 `hover`、按下用 `neutral-active`；禁用用 `disabled-bg`＋`secondary` | 对应深色角色 | 禁用必须有原生 disabled／不可操作语义，不靠透明度或颜色猜测 |
| 连接告警、消息错误、删除配对 | 状态文字＋对应轻底；危险实心按钮用错误色和白字 | 对应深色角色；危险实心按钮用错误色和深字 | 错误说明影响与可执行下一步；普通断线不一律上红色 |
| Markdown、代码及 diff | 普通正文用 `ink`，引用用 `soft-ink`；行内代码用 `panel`＋`accent`；成段代码用 `panel`＋浅色语法色 | 成段代码用 `code-bg`＋深色语法色 | 代码块与工具输出同底；语法色须在各自代码底上达到 4.5:1 |
| 工具执行原文 | `panel`＋`ink`＋`secondary`；状态符号用浅色的完成／运行及 `accent` | `code-bg`＋`code-ink`＋`code-muted`，状态符号使用深色版本 | 与成段代码块同底；工具输出为原始文本，不做语法高亮 |
| 独立设置页、配对弹窗、遮罩 | 页面与弹窗内容用 `surface`；弹窗单层遮罩用 `scrim`；浮层阴影使用 `shadow-color` | 对应深色角色 | 堆叠叠层不叠加遮罩至不可辨，内容与焦点仍可见 |
| 安装图标与浏览器外观 | 浏览器主题色跟随 `bg`；单色标识与安装图标背景分别适配 | 对应深色角色 | 图标深浅底、maskable 安全区和系统色须实机验收 |

语法色随代码底取对应主题版本：浅色主题代码块与工具输出在 `panel` 上，使用浅色状态色与 `accent`；深色主题在 `code-bg` 上使用深色版本。配对扫描框在两种主题下都是 `code-bg` 深底，不能使用浅色 `accent`（在浅色 `code-bg` 上仅 2.52:1）。

### 对比度

按上述色值计算，浅色 `secondary` 在各中性底上最低为 `neutral-active` 4.64:1，其次 `accent-wash` 4.88:1、`hover` 5.02:1；深色 `secondary` 最低为 `neutral-active` 5.48:1。中性层级上，浅色 `hover` 对 `bg`／`panel`／`surface` 为 1.18／1.11／1.25:1，`accent-wash` 对 `panel` 为 1.14:1；深色 `hover` 对 `panel` 为 1.20:1，`disabled-bg` 对 `hover` 为 1.16:1。状态色在各自轻底上浅色依次为完成 4.63:1、运行 4.82:1、错误 4.85:1；深色依次为 6.67:1、6.57:1、6.18:1。彩色实心按钮的最小值为浅色完成 5.24:1、深色错误 7.57:1。浅色 `control-line` 对 `panel` 为 3.21:1，深色对 `surface` 为 3.66:1，普通 `line` 只作装饰。代码正文在浅色 `panel` 代码底上为 12.72:1，在深色 `code-bg` 上为 15.59:1；各语法色见「代码高亮」表。浅色工具输出在 `panel` 上使用 `ink`／`secondary`／完成／运行／`accent`，对比分别为 12.72:1、5.57:1、4.67:1、4.77:1、5.26:1。浅色主操作白字对 `accent` 为 5.91:1，深色深字为 8.49:1；选中项的 `accent` 对 `accent-wash` 分别为 4.61:1、6.10:1。扫描框使用的深色 `accent` 对浅色／深色 `code-bg` 为 8.24／9.71:1。

这些数字仅覆盖列出的**不透明纯色组合**，并未证明透明遮罩、叠层重叠、图像、强光、字体粗细、浏览器控件或所有文案字号符合要求；实屏验收范围见「资产与验收」。

## 双语排版与语言选择

- 设置中提供「跟随浏览器」（默认）、「中文」、「English」三项。选择「中文」或「English」后在当前浏览器记住（存储键沿用 `pi-reach-` 前缀，如 `pi-reach-language`），后续访问以此为准；选回「跟随浏览器」即清除手动选择。
- 跟随浏览器时按 `navigator.languages` 顺序匹配，第一个中文或英文条目决定结果；任何中文区域（含 `zh-CN`、`zh-SG`、`zh-TW`、`zh-HK`、`zh-MO` 及 `zh-Hans`／`zh-Hant`）均显示简体中文，其余语言显示英文。
- 切换立即生效，不刷新页面；同步更新 `<html lang>`（中文为 `zh-CN`，英文为 `en`）；日期、相对时间与数字格式跟随界面语言。焦点留在语言选项上，进行中的连接、发送与配对不受影响。
- 切换只影响应用自有界面文案（操作、状态、错误提示与可访问名称），不翻译也不改写用户或 Pi 的消息、电脑与会话名称、历史原文、路径或命令；电脑名、命令与路径在两种语言中保持原样。
- 应用界面按统一产品术语与通行表达翻译，不逐项送审。
- 长会话名在空间不足时省略显示，`title` 属性保留完整名称；窄屏下重连提示与按钮允许换行。

### 叠层与反馈

| 项目 | 规则 |
| --- | --- |
| 叠层顺序 | 自下而上：页面 → 固定元素（移动顶栏、输入区、连接提示条）→ Drawer（移动导航、工具详情阅读器、移动电脑选择，带遮罩）→ Modal（配对、重命名、确认，带遮罩）→ 浮层（Popover、Menu，无遮罩，点外部关闭）→ Toast（最顶层，无遮罩，不拦截操作）。浮层显示在打开它的那一层之上；遮罩始终只有一层，叠加新的带遮罩层时遮罩移至最上层之下，不加深。Escape 与点击遮罩只关闭最上层；焦点限制在最上层内，关闭后回到下一层中的触发控件。Toast 不抢焦点、不受焦点限制，以 `aria-live` 播报 |
| Toast／通知 | 只用于一次性全局反馈（已复制、设置已保存、连接已恢复、有新版本）；「有新版本」显示带可点击「刷新」按钮的 Toast，点击后执行 PWA 更新刷新，不沿用持久提示条。表单、消息、会话的错误留在原处说明影响与下一步，不用 Toast。桌面与移动均在顶部居中、顶栏或会话标题区下方。`surface` 底、第 1 级浮层阴影＋`line` 边框、圆角 `8`、最大宽 `400`；状态图标＋单行文字，可选一个文字按钮与关闭按钮。仅不带操作的成功／普通提示 4 秒后自动消失，悬停或聚焦时暂停计时；带操作（包括「有新版本」）、错误及需处理的提示不自动消失。同一时间只显示一条：新提示替换旧的普通提示，当前为错误时新普通提示排在其后。以进入／退出曲线从上方轻微滑入淡入，减少动态效果时只淡化 |
| 加载 | 结构已知的列表与消息区（侧栏在线 Pi、打开会话）用 `hover` 色骨架屏，按真实布局排 2–3 行，完成后原位替换不跳动；向上加载更早消息时在列表顶部显示小型加载指示并保持阅读位置；按钮操作用按钮自身加载态；连接与重连在会话标题区以运行色状态文字＋动态图形呈现，不遮挡内容；等待 Pi 首段回复时在回复位置显示「Pi 正在思考…」状态行，内容到达即替换。300ms 内完成不显示加载态，加载态出现后至少显示 500ms。骨架屏以约 1.5 秒周期明暗呼吸，不用横扫高光，减少动态效果时静止。不用全屏加载遮罩和顶部进度条 |
| 空状态 | 见下方「空状态」 |

## 交互流程

### 首次配对

配对机制见[配对协议](../../reference/protocol/pairing.md)：电脑端在 Pi 中运行 `/pi-reach pair` 生成 8 位配对码及二维码；Relay 有默认地址，首次使用无须先填写。

1. **首次打开**：主区显示「未配对」空状态，说明中直接给出 `/pi-reach pair` 命令及复制按钮，主操作「开始配对」。侧栏（移动端为导航）只显示电脑选择入口，状态为「未配对」。
2. **配对弹窗**：表单类 Modal（宽 `480`），提供扫码、上传二维码图片、手动输入三种方式。移动端默认扫码，桌面默认显示配对码输入框；其余方式以文字按钮置于下方。之后配对其他电脑时，从电脑选择入口进入同一弹窗。
3. **手动输入**：单个输入框，自动转大写，允许 `-` 与空格；输满 8 位有效字符后自动提交。
4. **扫码**：切换到扫码时才请求摄像头权限；被拒绝时说明原因并切回手动输入。
5. **连接中**：弹窗内显示运行色「正在连接电脑…」，输入与按钮暂不可用。
6. **成功**：关闭弹窗，直接进入该电脑上生成配对码的 Pi 会话，并以 Toast 提示「已与〈主机名〉配对」（主机名取自 `pair_ok.hostname`）。
7. **失败**：错误显示在弹窗内输入框下方，不用 Toast；保留已输入内容，焦点回到输入框。

失败文案（示例，实施时按统一术语调整）：

| 情况（协议错误码） | 文案 |
| --- | --- |
| 配对码不存在（`unknown_code`、`token_unknown`） | 配对码无效，请核对后重试。 |
| 配对码已过期（`expired_code`、`token_expired`） | 配对码已过期，请在 Pi 中重新运行 `/pi-reach pair`。 |
| 配对码已被使用（`token_consumed`） | 这个配对码已被使用，请重新生成。 |
| 电脑上的 Pi 已退出或重启（`stale_target`） | 电脑上的 Pi 已退出或重启，请重新生成配对码。 |
| 尝试次数过多（`rate_limited`） | 尝试次数过多，请稍后再试。 |
| 无法连接 Relay | 无法连接 Relay，请检查网络，或在设置中确认 Relay 地址。 |
| 其他（`internal_error`） | 配对失败，请重新生成配对码后再试。 |

### 在线 Pi 的呈现与切换

沿用[架构](../../ARCHITECTURE.md#pwa-活动选择与历史)中的活动选择原则：以当前选中的电脑为范围；0 个在线 Pi 时不尝试唤醒，1 个时自动选中，多个时保留用户明确选择，不按目录或名称猜测；阅读本地历史时暂停自动选择。

| 情况 | 主区 | 侧栏／移动导航 |
| --- | --- | --- |
| 0 个 | 「没有在线的 Pi」空状态 | 一行小字「没有在线的 Pi」 |
| 1 个 | 自动选中并进入会话 | 显示该项，处于选中态 |
| 多个，之前的选择仍在线 | 保持在该会话 | 列出全部，该项选中 |
| 多个，没有可沿用的选择 | 「选择一个 Pi」：标题为「有 N 个在线的 Pi」，下方列出全部，点击进入；移动端同样在主区选择，不强制打开导航 | 列出全部，均不选中 |

在线 Pi 列表行：第一行为会话名（未命名时显示「未命名会话」）；第二行为工作目录最后一级 · 状态，运行中用运行色文字＋动态图形，空闲显示「空闲」。不显示模型名。

切换规则：

- 点击列表中另一项立即切换，无需确认；输入区草稿按会话分别保留。
- 有新的 Pi 上线时不自动切换，只在列表中新增一项。
- 处于「没有在线的 Pi」空状态时，有 Pi 上线即自动进入（符合 1 个时自动选中）。
- 阅读本地历史时暂停所有自动选择。
- 从侧栏顶部的电脑选择入口切换电脑，之后按上述 0／1／多个规则处理。

### 连接变化

1. **浏览器与 Relay 断线**（网络断开、Relay 重启）：自动重连，会话内容保持显示；会话标题区显示运行色「重新连接中…」。输入区可继续输入，但发送不可用，下方提示「连接恢复后才能发送」（产品不提供离线发送队列）。断线超过 10 秒时，主区顶部出现连接提示条「无法连接 Relay，正在重试…」及文字按钮「立即重试」。恢复后提示条消失；仅在提示条出现过时以 Toast 提示「连接已恢复」。
2. **当前会话的 Pi 退出**：会话内容保留在原位，不自动跳转；标题区状态变为中性色「已退出」；输入区位置替换为说明「这个 Pi 已退出，会话记录已保存在本地历史。」，有其他在线 Pi 时附文字按钮「选择其他 Pi」。侧栏在线列表移除该项，会话出现在本地历史。同一目录再启动的 Pi 是新实例，不自动接续，按「有新的 Pi 上线」处理。
3. **Pi 在电脑上切换到新会话**（如执行 `/new`）：主区跟随 Pi 当前会话，旧会话留在本地历史；新会话开头以一行居中的 `secondary` 小字标出「Pi 已切换到新会话」，不用 Toast。
4. **发送过程中断线**：沿用现有投递状态，待发送消息下方显示「发送中」；无法确认送达时显示「投递状态未知」及「重试」按钮。状态行统一为 `12px`／`secondary`。

### 本地只读历史

沿用现有规则：历史只保存在当前浏览器，只读，不远程接续；标题优先用已保存的会话名，缺失时回退到消息摘要；按最后活动时间排序；只有删除配对或清除本地数据时才删除，不提供单条删除。

- **侧栏「本地历史」分组**：只列当前电脑的记录，按最后活动时间倒序。每行第一行为会话名（或消息摘要），第二行为时间：今天显示时刻（如 `17:43`），昨天显示「昨天」，更早显示日期（如「9 月 24 日」）；行内不重复标注「只读」。先显示最近 20 条，末尾以文字按钮「显示更早的记录」每次追加 20 条。
- **打开历史**：主区按正常消息样式显示（含轮末时间）；会话标题区在会话名上方以中性色小字标出「本地历史 · 只读」；输入区位置替换为 `panel` 底说明条「这是本地保存的只读记录，不能继续对话。」，若该会话对应的 Pi 此刻在线（同一会话），附文字按钮「回到在线会话」。
- **退出历史**：阅读历史期间暂停自动选择；点击在线 Pi 或「回到在线会话」即退出。

### 会话切换

- **滚动位置**：首次打开某会话时停在底部最新内容；同一次访问中切回已看过的会话时，恢复离开时的阅读位置。
- **切换动效**：主区内容直接替换，不做滑动或淡入；加载超过 300ms 时按「加载」规则显示骨架屏。
- **移动端**：在导航中选中会话后，导航以 `240ms` 收起，再显示该会话。
- **焦点**：桌面切换后焦点留在侧栏刚选中的项上，可继续用方向键浏览、按 Tab 进入主区；移动端切换后不自动聚焦输入区，避免弹出键盘遮挡内容。
- **快捷键**：本轮不提供快速切换快捷键。
- **后台完成提醒**：非当前查看的在线 Pi 由运行中变为空闲（按「协议前提」第 2 条，`working` 以整次运行计算）时，其侧栏行在会话名右侧显示直径 `6px` 的 `accent` 圆点，并附仅读屏可见的「有新回复」；打开该会话后圆点消失。移动端任一在线 Pi 有提醒时，顶栏菜单图标右上角显示同样的圆点。提醒只保存在当前页面内存中，刷新后清除；不依赖额外协议字段。

### 工具详情阅读器

- **会话内预览**：工具行展开后最多显示 12 行，超出部分在底部渐隐，下方左侧提供文字按钮「查看全部（共 N 行）」打开阅读器。
- **容器**：桌面为右侧 Drawer，宽 `720`，左侧会话在遮罩下仍可见；移动端全屏。从右侧滑入，进入 `240ms`、退出 `200ms`，使用进入／退出曲线；减少动态效果时改为淡化。
- **关闭**：关闭按钮、Escape、点击遮罩（桌面）。打开时以 `pushState` 压入一条不改变 URL 的历史记录，系统返回键与浏览器后退关闭阅读器，而不是离开当前会话。
- **标题区**：一行为工具名（`600`、`ink`）加命令或操作名称（等宽字体、最多两行），与会话内工具行同一读法；右侧依次为状态标签（图标＋文字，状态色）、「复制全部输出」与关闭两个图标按钮。（2026-09-29 按布局、视觉与交互调整的 D9 修订，原为「第一行状态与命令、第二行工具名」。）
- **内容区**：出错时顶部先显示错误色轻底的错误信息框；输出底色与会话一致（浅色 `panel`、深色 `code-bg`），带 `secondary` 行号，长行自动换行（会话内代码块仍横向滚动）；协议标记截断时末尾显示「输出过长，已截断」；运行中的工具实时更新，停在底部时跟随滚动，向上回看时不跟随。
- **焦点**：打开时焦点落在标题上；关闭后回到「查看全部」按钮，会话阅读位置不变。

## 协议前提

以下协议补充是上述规则的实施前提，已获准修改协议：

1. **本轮结束事件**：扩展在 Pi 一次运行结束（`agent_end`）时，发出并持久化一条带 `group_id`、`timestamp` 与结束状态（完成／中断／出错）的时间线事件，实时推送与历史回放一致。PWA 以此判断一轮是否结束并显示轮末时间。缺少该事件的旧历史按以下规则降级：出现后续一轮即视为前一轮已结束；最后一轮在不处于运行状态时取该轮最后一个事件的时间。
2. **运行状态按整次运行计算**：endpoint 元数据的 `working` 改为跟随 `agent_start`／`agent_end`，而不是 Pi 内部每次模型调用的 `turn_start`／`turn_end`，避免在工具调用之间短暂变为未运行，导致「运行中」状态和轮末时间闪烁。

决策、字段与兼容性见 [ADR-20260927 本轮结束事件与整次运行状态](../../adr/20260927-run-end-event.md)：事件类型为 `run_end`，`protocol_version` 仍为 2；严格 schema 下旧版 PWA 会拒绝该事件，发布须先部署 PWA 再发布 Extension。

## 分阶段实施

阶段按依赖排序，每个阶段结束时应用可正常使用、可独立验证。事项与当前阶段的状态只在 [ROADMAP](../../ROADMAP.md) 维护，本节不记录进度。

### 通用规则

- **一次到位**：每个阶段直接实现本方案的最终规则，不做过渡样式；尚未进入的部分保持现状，允许阶段之间暂时新旧并存。
- **文档随落地同步**：阶段完成时，把已落地规则写入 [DESIGN](../../DESIGN.md) 的对应章节并删除被取代的旧规则；未落地部分继续以 DESIGN 现有内容为准。路由与协议的长期文档在对应阶段更新。
- **验收值回写**：实屏或测试中发现数值不合格时，先修正本方案，再写入代码与 DESIGN，不在代码中静默偏离。
- **验证**：每个阶段执行受影响子项目的 `typecheck`、`lint`、测试和 `git diff --check`；改动全局样式或布局时，在 `767`／`768px` 两侧及 `390`、`1440px` 宽度下检查浅色与深色；涉及 Modal、Drawer、Menu、Popover 时按项目 overlay 验证技能验收。
- **提交与发布**：每个阶段单独提交，提交和推送各自取得用户授权。实施期间不推送到线上：不发布 Extension npm 包、不部署线上 PWA；Extension 以 `pnpm pack` 在本机打包安装，PWA 在本机运行验收。2026-09-30 经用户授权，Extension 0.0.1 已发布到 npm；发布前核对线上 PWA 已支持 `run_end` 及全部协议帧与事件类型。
