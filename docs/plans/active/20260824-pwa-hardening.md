# PWA 加固与真实设备验收

本文件集中维护可由多个事项复用的设备环境、通用检查和证据记录方式，项目级状态只在 [ROADMAP](../../ROADMAP.md) 维护。专项方案保留各自独有的场景与结束条件；一次操作可以支撑多个事项，但必须说明实际覆盖了哪些检查，不能把通用 smoke 当作所有事项的验收。

## 当前依据与剩余边界

Serwist、离线应用壳和同源多标签连接控制已有实现，来源为当前源码。后续 Protocol v2 和 endpoint 模型替代了早期 room、本地无限历史以及 partial 持久化假设，不能继续按这些旧规则重新实施。

当前结构、业务存储和缓存边界以 [ARCHITECTURE](../../ARCHITECTURE.md) 为准；协议以 [PROTOCOL](../../reference/protocol/README.md) 为准。当前设计基线见 [DESIGN](../../DESIGN.md)。本文只组织验收，不新增支持平台、产品行为或发布条件。

| 范围 | 现有依据 | 仍需确认 |
| --- | --- | --- |
| 应用壳、静态资源和 Worker 生命周期 | [`sw.ts`](../../../pwa/src/app/sw.ts)、[`vite.config.ts`](../../../pwa/vite.config.ts) | 真实设备安装、断网冷启动、版本切换与恢复 |
| 本地业务数据与连接恢复 | [`db.ts`](../../../pwa/src/lib/pwa/db.ts)、[`PwaApp`](../../../pwa/src/components/pwa/pwa-app.tsx) | 移动浏览器权限、系统挂起与实际存储行为 |
| 当前桌面/浏览器自动化基线 | 当前测试配置 | Chromium viewport 不能替代真实 iOS/Android 设备证据 |

以上代码与历史记录不是本轮重新运行测试的结果。未取得真实设备、浏览器版本和操作证据前，不宣称移动端验收完成。

## 设备验收范围

延续原方案的浏览器范围：Chrome/Edge 桌面端、Chrome Android、最近两个版本的 iOS Safari。iOS Chrome 至少进行功能兼容 smoke；只有另行明确将其安装路径列为正式支持能力时，才增加对应发布门槛。

| 环境 | 模式与检查重点 |
| --- | --- |
| iOS Safari | 浏览器标签页与添加到主屏幕后 standalone 分别记录；覆盖安装、缓存壳的离线启动、键盘、安全区、前后台恢复和系统边缘返回 |
| Android Chrome | 浏览器标签页与安装后 standalone 分别记录；覆盖普通／maskable 图标、离线启动、键盘和恢复；手势专项区分系统手势导航与三键导航 |
| iOS Chrome | 网页访问、Service Worker／IndexedDB 能力、扫码权限及实际添加到主屏幕行为；结果只作为上述兼容 smoke |
| 桌面 Chrome／Edge | 保留桌面关键流程；实屏明暗、短窗口和焦点检查按受影响事项执行，不以桌面结果替代移动设备 |

没有某种设备、模式或系统配置时，明确记录未覆盖，不把同一设备的标签页结果外推为 standalone，也不把 Android 三键导航外推为手势导航。

## 通用设备检查

下列编号供专项方案引用，不另设项目状态表。按原事项范围选择适用项；不要求每个专项重复执行整张表。

| 编号 | 操作与需要观察的结果 | 适用范围与边界 |
| --- | --- | --- |
| T1 安装与入口 | 在真实设备上检查添加／安装、图标普通与 maskable 裁剪、standalone 启动；直接打开和刷新 `/app/settings`，区分在线和已缓存壳的离线入口 | 安装与品牌事项共用。favicon 16／32px 清晰度仍需真实浏览器检查；安装成功不代表图标和子路径均通过 |
| T2 离线与本地数据 | 联网取得正式历史后断网冷启动，检查已缓存壳与正式历史可读，发送及在线操作禁用；恢复联网并核对当前电脑／Pi 的连接 | 使用 device／endpoint 范围内的 pairing，不操作旧 Room 模型；不要求离线发送或恢复未持久化的 partial。IndexedDB 不可用时检查实际错误及恢复提示，不以临时身份替代成功路径 |
| T3 Worker 与版本切换 | 区分后台安装、更新提示和用户主动刷新，观察草稿、流式状态及多标签连接的实际处理 | 不通过强制刷新掩盖中断；版本混跑、旧 Extension 联调等专项兼容要求仍由对应方案验收 |
| T4 权限与配对 | 摄像头授权、拒绝后改用已有输入入口、扫码与配对后进入目标 Pi；使用事先确认的测试身份 | 权限和配对关键流程共用；不对真实配对资料执行未授权清除 |
| T5 键盘与安全区 | 竖屏、横屏、旋转及适用的平板宽度下打开／收起键盘，检查输入与操作可达、底部跟随与回看位置；检查顶／底和横屏左右安全区、设置页及叠层溢出 | 以当前 [DESIGN](../../DESIGN.md#布局与导航) 的显示模式、键盘与安全区规则为准，不重验已被取代的视口补偿或固定顶栏假设；原设备的单帧滚动异常另取专项证据 |
| T6 后台与恢复 | 切后台、锁屏或系统挂起后返回前台，记录链路恢复与当前正式内容、本地数据的实际表现 | 不要求后台 WebSocket 持续在线或浏览器后台可靠执行；消息投递、运行结束与文件取回的正确性仍按专项方案检查 |
| T7 手势与原生滚动 | 从内容中部起滑，检查应用手势、纵向阅读、嵌套横向滚动、普通点按和系统返回可共存 | 两代手势共用[联合真机验收](20261007-follow-finger-swipe.md#联合真机验收)；其中的表面、提交／回弹、焦点、系统边缘与中断场景不能由通用操作替代 |

## 执行前提与记录

开始实际验收前另行确认测试环境、真实设备、浏览器 profile、Pi 身份、操作范围和模型用量。本文不是启动服务、执行模型调用或发布生产的授权。

验收记录至少包含：

- 设备、操作系统与浏览器版本，以及普通网页或 standalone 模式；手势场景另记 Android 导航方式和 iOS 起手位置；
- 受测提交／构建、经过脱敏的环境说明和操作步骤；
- 对应的通用编号、专项方案与具体场景，每项结果、失败复现条件、必要截图或日志；
- 临时身份、profile、服务与测试数据的清理结果。

一次设备操作同时覆盖品牌、手势或加固事项时，只保留一份证据，在各方案中引用并注明覆盖范围；未实际执行的专项不能顺带写为通过。输入和相关环境未变、覆盖仍有效的已有证据可复用，记录其适用范围和未覆盖项，不为凑记录重放有副作用的流程。

截图、日志和一次性证据放在 `.pi/tmp/`，长期方案只保留脱敏结论和必要引用，不写二维码、token、身份私钥或真实业务消息。本次文档合并没有新增任何设备验收结果。

## 完成与停止条件

原方案的移动发布门槛保留：自动化验收通过，且至少一台真实 iOS 设备与一台真实 Android 设备的关键流程通过。没有真实设备时，只能声明实际取得的自动化或 Chromium 证据，并明确移动端未验证。

完成前先核对受影响的当前自动化基线，再补齐设备记录。若遇到浏览器能力限制、行为缺陷或必须改变产品边界的问题，先报告事实并确认后续范围；本项不能顺带引入 Push、账号、离线队列、原生客户端或新主题。

收口顺序：将仍有效的支持边界同步到长期文档，归档本验收方案，最后更新 ROADMAP。归档前不得用“核心代码已有实现”替代尚缺的设备证据；其他事项仍按各自的结束条件独立收口。
