本文不独立维护项目级事项状态；事项状态仍以 [ROADMAP](../../ROADMAP.md) 为准。当前产品设计与架构分别见 [DESIGN](../../DESIGN.md) 和 [ARCHITECTURE](../../ARCHITECTURE.md)。本方案明确提出替代部分旧规则，但在获准实施、完成验证并同步长期真源前，不能把目标设计写成已经存在的生产行为。

## 一、目标、范围与基线

### 1.1 目标

将目前分开维护的 Thinking 独立折叠、工具组折叠、工具组头排队轮播、Thinking 图标槽伸缩与 Working 独立显隐，整理成一套一致的思考与工具过程展示。

最终应做到：

1. 同一轮中相邻的 Thinking 与工具按实际展示顺序放在同一组。
2. 只有一层总折叠，子项没有折叠箭头。
3. 执行中默认展开，收到正式 `run_end` 后自动收起；与手动阅读的优先级按 R01、R04 冻结。
4. 收起时直接展示当前工具或 Thinking，不使用“执行过程”固定标题。
5. 状态图标固定在左侧，不推动标题横向移动。
6. 明细与组头、正文同字号。
7. 保留现有主题、字体、扁平消息流和详情阅读器风格。
8. 状态交接不重排消息、不重建已有行、不重复播放入场。
9. 自动折叠、Working 交接与现有滚动协调器协作。
10. 将已有发送闪帧、回跳作为明确回归项，不假定重构后自然消失。

## 二、设计规则

### 2.1 已确认规则

| 编号 | 规则 |
| --- | --- |
| D01 | 同轮、相邻的 Thinking 与工具统一分组 |
| D02 | 只有组级折叠，子项无折叠箭头 |
| D03 | 收起时显示当前工具调用或 Thinking，不显示“执行过程”固定标题 |
| D04 | 执行中默认展开，正式 `run_end` 后自动收起 |
| D05 | 状态图标固定在左侧 |
| D06 | 组头、Thinking 明细、工具名和命令均与正文同字号，默认档为 16px |
| D07 | 相邻明细图标之间使用细灰色短竖线；图标周围留断口，不连接组头 |
| D08 | 保留现有扁平风格，不引入大卡片、阴影、步骤编号和耗时列 |
| D09 | 正文仍在过程组之外，不跨正文搬运或重排 Thinking、工具 |
| D10 | 整轮结束只能由正式 `run_end` 确认 |

### 2.2 推荐补全规则及确认门禁

R01—R04 最初为补齐实施边界提出的推荐规则，现已在 P0 由用户一次性全部确认，活动承载规则亦一并确认。下文保留建议的理由说明；实施与测试采用已确认的推荐分支，不得自行改选其他规则。

#### R01：手动选择优先于默认折叠

建议：

- 自动展开不产生“用户展开选择”。
- 用户手动收起后，同一组新增内容不把它强行打开。
- 用户手动展开后保留该组展开状态，包括收到 `run_end` 后。
- 没有手动选择的组，按“运行展开、结束收起”执行。
- 选择仅在当前会话展示生命周期内保存，不写入 IndexedDB 或偏好设置。

原因：避免用户正在查阅时被自动收起打断。如果用户要求“结束后一律收起，包括手动展开”，必须在实施前明确替换本条，不能由实现模型自行判断。

#### R02：并行时显示最新开始、仍有效的活动

建议：

- 在有效活动中选择最近开始的一项。
- “最近开始”依据稳定的首次观察顺序，不按最后一次输出时间、完成时间或 React 渲染顺序选择。
- 当前项结束后，选择剩余有效活动中最近开始的一项。
- 不排队补播已经完成的调用。
- 当前显示工具时，`+N` 表示另外正在运行的工具数量。
- 当前显示 Thinking 时，`+N` 表示同时仍在运行的工具数量。
- 无额外运行工具时不显示 `+0`；可访问名称解释数量含义。

#### R03：Thinking 明细打开同款阅读器

建议：

- 有实际文本的 Thinking：点击整行打开 Thinking 阅读器。
- 复用 `ReaderShell`，不另造 Modal、返回栈或手势。
- 空历史 Thinking 痕迹：保留静态条目，不提供无内容的阅读入口。
- 只含一个空历史痕迹、没有其他可展开信息时，保留静态展示，不制造无意义的折叠操作。

#### R04：自动收起不撤走正在使用的控件

建议：

- 阅读器打开或退出过程中，暂缓所属组的自动收起。
- 退出完成后，没有手动展开选择时再执行待处理的自动收起。
- 键盘焦点位于将被隐藏的明细中时，不直接卸载焦点所在节点；保护解除后再处理待收起状态。
- 自动收起后的回焦目标优先为稳定组头，而不是已经或即将隐藏的子项。
- 不覆盖用户已经转移到输入框等有效控件的焦点。

### 3.2 数据链路

```text
既有 TimelineRuntime / 显示快照
                ↓
既有 projectTimeline()
                ↓
统一过程分组 + 分组身份协调
                ↓
组头状态 / 展开状态 / 活动归属
                ↓
ProcessGroup + Thinking / Tool 明细
                ↓
既有 ReaderShell 与视口协调器
```

禁止从 DOM 上有没有 spinner 反推工具运行状态，再猜测整轮结束。

### 3.3 三种状态分开

| 状态 | 来源 | 不得承担的职责 |
| --- | --- | --- |
| 工具、Thinking 的展示状态 | 当前条目、连接情况、轮次归属 | 不能确认整轮完成 |
| 整轮完成状态 | `RunCompletion`，仅来自 `run_end` | 不能伪造每个工具的结果 |
| 展开与阅读状态 | 默认策略、用户操作、阅读器生命周期 | 不能修改业务运行状态 |

### 3.4 优先复用的能力

- `projectTimeline()`：稳定条目身份、展示顺序和对象复用。
- `timelineActivity()`：末轮、正式结束、旧轮与残留 partial 过滤。
- `runCompletions()`：严格结束语义。
- `ThinkingTextParser`、`useThinkingHeading()`：增量解析与标题显示。
- 工具参数、类别、摘要和详情解析。
- `Collapse`：现有折叠呈现。
- `ReaderShell`、`useReaderIntent`、焦点恢复工具。
- `TimelineViewportCoordinator`、Layout、Observers。

这是展示重构，不是新增第二套运行时。

## 四、统一分组契约

### 4.1 分组成员

建议类型如下；这是目标接口草案，不是已经存在的导出：

```ts
type ProcessEntry = Extract<
  PresentationEntry,
  { kind: "thinking" | "tool" }
>;

type ProcessGroup = {
  key: string;
  groupId: string;
  entries: readonly ProcessEntry[];
};
```

直接使用已有 `ThinkingEntry` 和 `ToolEntry`，不复制一份包含工具参数、输出和正文的平行数据模型。

### 4.2 分组边界

下面可以合组，前提是同轮、展示相邻、没有缺口或可见分隔项：

```text
Thinking → Tool → Tool → Thinking → Tool
```

下面必须断组：

```text
Thinking → 正文 → Tool
Tool → 用户消息 → Thinking
Tool → 已发布文件 → Tool
Thinking → 历史缺口 → Tool
上一轮 Tool → 下一轮 Thinking
```

此外：

- 可见摘要、错误记录和其他可见记录按现有顺序保留。
- 本地压缩终态提示落在组内成员之间时，也必须形成展示边界。
- 不把本地提示挪到整组前后，从而改变发生位置。
- 分组不能吞掉轮末完成时间。
- 不因工具失败、中断或未知而将其排除在分组外。

### 4.3 历史缺口专项扩展

当前 `projectTimelineGaps()` 的内部断组只检查 `tool → tool`。重构后覆盖：

```text
thinking → thinking
thinking → tool
tool → thinking
tool → tool
```

保持两个不同概念：

1. 缺口提示的位置。
2. 禁止跨越的分组边界。

不能为了断组重复渲染提示，也不能因空 Thinking 去重吞掉提示。建议将返回字段 `toolBreakKeys` 改为 `processBreakKeys`，同步全部直接消费者与测试，不维护两个含义相同的字段。

### 4.4 组身份

不能使用数组下标、文本、当前活动工具 ID、摘要、最后完成工具、时间戳、随机数或随普通提交推进的 `leaf_id` 作为组身份。

| 变化 | 结果 |
| --- | --- |
| Thinking 增量更新 | 组不重建 |
| 工具运行转正式结果 | 组不重建 |
| 并行工具逆序完成 | 组内不重排 |
| 新成员追加 | 已有组身份不变 |
| 更早历史前插 | 已有组身份不变 |
| 原锚定成员消失，但仍有共同成员 | 保留已有组身份，不能只重新取数组第一项 |
| 会话或真实来源失效 | 清理旧状态，不继承到新会话 |

建议先划分候选组，再与上一份分组协调：

1. 按当前展示顺序划分相邻组。
2. 用共同成员身份匹配上一份分组。
3. 普通更新沿用已有组 key。
4. 拆分时，原锚定成员所在部分保留旧 key；锚定成员已不在时，按原成员顺序确定一个继承者。
5. 其余拆分部分使用新的、由稳定成员身份派生的 key。
6. 合并时确定性保留一个旧组 key，不能产生重复 key。
7. 展开选择独立按成员继承，不依赖最终保留哪个组 key。

如果一次替换没有任何可靠共同身份，不得按相似文本或接近时间猜测是同一条内容；补充来源证据或停止该边界的实现。

### 4.5 DOM 身份

过程组根节点是消息列表的顶层语义行，例如：

```tsx
<article
  data-viewport-row={group.key}
  data-timeline-key={group.key}
>
```

- React key 与视口行身份都要稳定。
- 不能每次取当前数组第一项重新生成视口 key。
- 子项使用稳定成员 key，不能被误当成另一条顶层消息行。
- 组头从摘要切到当前活动时，不重建整个组。
- 真实来源切换与普通 leaf 推进必须区别处理。

## 五、组头与状态推导

### 5.1 展示状态表

| 场景 | 组头文字 | 左侧状态 |
| --- | --- | --- |
| 收起，有当前工具 | 工具名＋命令／路径摘要 | 当前组的有效运行状态 |
| 收起，有当前 Thinking | Thinking 标题或摘要 | 运行图标 |
| 收起，当前过程仍运行但暂时无具体输出 | `Working…` | 运行图标 |
| 展开 | 分类摘要；仅有 Thinking 时使用 Thinking 文案 | 当前组状态 |
| 正式结束 | 分类摘要，保留失败／中断／未知提示 | 与真实结果相符 |
| 离线，或当前不再运行但结束未确认 | 摘要或最后有效描述，明确未知 | 未知状态，不旋转 |
| 空历史 Thinking | `Thinking` | 静态中性图标或既有静态呈现 |

此表不授权推断缺失的结果：

- `run_end` 已到达时，迟到 `working=true` 不能重新点亮运行状态。
- 工具失败不能因整轮最后 `complete` 而显示成全成功。
- 正式工具结果已经完成，不能因整轮出错而反写为工具失败。
- 已结束轮残留的工具 partial 不能继续显示为执行中；没有对应正式工具结果时仍按未知处理，不制造成功或中断结果。
- 历史缺少 `run_end` 时不得补完成时间。工具自身已有正式结果仍按真实结果显示，不能把整组每一项都覆盖为未知。

### 5.2 当前 Thinking 的有效性

不能把所有 `streaming=true` 的 Thinking 都当作当前活动。显示缓冲可能仍在收尾，而后续工具或正文已经出现。

至少同时检查：

1. 当前轮归属。
2. 尚未正式结束。
3. 不是旧轮或空闲残留。
4. 没有被后续同轮输出明确取代。
5. 连接和运行状态允许显示为活动。

Thinking 文本尚未放完，不等于模型此刻仍在思考。并行工具仍有效时也不能仅因后续 Thinking 出现就伪造工具结束。

### 5.3 删除工具组头展示队列

完整删除被替代机制，而不是缩短时间：

- `GROUP_HEAD_QUEUED_VISIBLE_MS`。
- `GROUP_HEAD_MIN_VISIBLE_MS`。
- `GROUP_HEAD_MAX_BACKLOG`。
- `useGroupHeadTool()` 的排队计时及相关状态。
- 换调用时文字向上进入的动画。
- 仅为补播服务的 `appendedTools()` 消费链路。

快速完成的调用全部保留在明细中，不要求逐个占据组头。不得用新的 100ms、200ms 或 debounce 重新实现隐形轮播。迁移期间可以有短暂的未接入代码，但最终交付不保留两套生产组头状态机。

### 5.4 Thinking 标题解析保留

保留：

- 最新完整整行加粗标题。
- 未闭合标题过滤与暂定标题失效回退。
- 首个非空行摘要。
- 120ms 有界摘要合并，连续输入不延长当前窗口。
- epoch、模式切换及卸载清理。
- 正文增量解析的线性工作量。

删除的是槽位伸缩与标题横移，不是解析器和正确的标题边界。120ms 摘要窗口仅合并视觉摘要，不能阻塞正文或工具状态，不能与被删除的 800ms 工具排队混为一谈。

模型标题与摘要保持原文，不翻译。Thinking 占位沿用 `Thinking…`／`Thinking`，新组操作与数量文案使用现有 i18n 机制，不顺带重写全项目语言规则。

### 5.5 分类摘要

复用现有统计语义：

- 类别按首次出现排序。
- read、edit、write 按不同路径计数。
- command、search 等按调用计数。
- 失败、中断分别保留。
- 未确认状态不能生成“全部完成”的暗示。

如需匹配效果稿的紧凑收起文案，由同一统计结果生成以下展示字段，不分别维护两套统计逻辑：

```ts
{
  fullLabel,
  compactLabel,
  failureCount,
  interruptedCount,
  unknownCount
}
```

## 六、展开状态与阅读意图

### 6.1 区分默认、手动与临时保护

不要只保存一个来源不明的 `expanded: boolean`。至少区分默认展开状态、用户手动选择、临时禁止自动收起的阅读状态。

按 R01、R04 推荐的有效展开规则：

```text
有手动选择
    → 使用手动选择
否则，存在临时阅读保护
    → 暂时保持展开
否则，已有正式 completion
    → 收起
否则，当前组属于有效运行
    → 展开
否则
    → 保持已经建立的展示状态；首次加载的历史默认收起
```

保持已有展示状态是为了避免短暂断线或 metadata 抖动反复开合，不代表离线时仍显示运行图标。新阶段、手动选择与来源失效各自有独立输入，不通过模糊的超时推断。

### 6.2 关键转换

| 输入 | 预期 |
| --- | --- |
| 首次出现运行中的组 | 直接以展开态出现，不先闪收起再展开 |
| 同组新增工具或 Thinking | 保持用户选择；无选择时按默认策略 |
| 工具全部完成，但没有 `run_end` | 不自动收起 |
| 同轮后续正文出现 | 可以改变活动归属，但不能冒充整轮完成；此前过程组不因正文出现而自动收起 |
| 正式 `run_end` | 无手动展开／阅读保护时收起 |
| 重复 completion | 不重播折叠 |
| 已结束历史首次加载 | 直接收起，不播放结束动画 |
| 断线 | 停止不可信运行提示，不伪造结束 |
| 重连 | 不重播历史调用，不清空手动选择 |
| 会话切换 | 清理本会话选择、计时器和阅读器状态 |

同轮可能有多个被正文分开的过程组；正式结束时逐组按自己的手动选择与保护状态处理，不把它们重新搬到一起。

### 6.3 默认展开不能暂停跟随

禁止直接写成：

```ts
onReadingChange(group.expanded);
```

这会让执行中默认展开一直暂停自动跟随。必须区分：

- 自动展开：不产生阅读锁。
- 用户手动展开：按既有阅读语义暂停自动跟随。
- 打开阅读器：保持阅读锁到退出完成。
- 组内状态更新：不重新申请阅读锁。
- 点击“最新”：恢复跟随，不必强制折叠用户展开的组。
- 点击“最新”后，后续增量不能仅因该组仍展开而再次暂停。
- 一个组收起时，不能释放仍由其他组手动阅读或阅读器持有的阅读状态。

### 6.4 分组变化后的选择继承

沿用“按成员记录最近选择”的思想：

- 一次操作记录到当时的组成员。
- 组拆分后各部分继承该选择。
- 合并时最近一次用户操作优先。
- 新成员加入已有组不能覆盖旧选择。
- 自动展开不能写成一次“最近用户操作”。

## 七、组件与视觉实现

### 7.1 建议组件分工

```text
ProcessGroup
├── ProcessGroupHeader
└── Collapse
    └── ProcessEntryList
        ├── ThinkingProcessRow
        └── ToolCard / ToolProcessRow
```

| 模块 | 职责 |
| --- | --- |
| 组组件 | 组合组头、折叠内容和明细 |
| 组头 | 渲染推导好的内容，不拥有排队计时器 |
| Thinking 行 | 标题、状态、阅读入口 |
| 工具行 | 名称、参数摘要、真实状态、阅读入口 |
| 状态槽 | 固定尺寸，原位切换图标 |
| 分组／状态 helper | 纯数据计算，不读写 DOM |
| 阅读器控制器 | 单一选择、互斥、退出和回焦 |

不要把全部逻辑塞入 `ConversationTimeline`，也不要为了文件拆分复制状态所有权。

### 7.2 字号与布局

生产 CSS 使用现有 token：

- 组头与子项使用正文 token，默认字号档对应 16px；随用户字号档位一致变化。
- 不修改全局 `--pwa-text-list` 来实现局部放大。
- 工具名为系统字体，命令与路径保持等宽。
- Thinking 保留斜体、中性色风格。
- 触控目标至少 44px；状态槽固定 16px。
- 长文本单行省略；右侧只有组头存在折叠箭头。
- 只有一个子项时也保留有效组语义，空历史痕迹例外按 R03。

覆盖很长的自定义工具名、命令、路径、并行数量、失败提示和大字号档位。优先压缩摘要，再处理工具名省略；不能让长工具名把状态图标、计数或箭头挤出屏幕。完整内容通过可访问名称、阅读器或适用的 title 提供，不以悬停作为移动端唯一读取方式。

### 7.3 短竖线

目标：

- 1px 宽；默认效果稿中约 16px 高。
- 主题中性色，浅深色均可辨认。
- 只出现在相邻明细之间，与图标留断口。
- 不连接组头，不影响布局和点击，收起后不可见。

优先使用伪元素，并设置 `pointer-events: none`。不能照搬静态稿的 `top: -11px` 就视为完成，必须核对生产盒模型、行间距和字号档位。

验证首项上方无多余线、末项下方无悬空线、单项无线、图标切换不带动线、大字号不碰图标、折叠退出无残留线段。

### 7.4 动效

- 图标槽不伸缩，标题不横移。
- 工具切换不逐条滑入。
- 新成员不使整组重新入场。
- 已展开内容增长不重播展开动画。
- 折叠使用现有时长 token，不新增任意魔法时长。
- Reduced Motion 不播放高度／位移运动。
- 无限 spinner 不得驱动持续几何轮询。
- 已运行的组级 spinner 在运行成员变更时保留节点与动画连续性，不能每次更新都重新淡入。

## 八、阅读器设计

### 8.1 复用现有壳

Thinking 阅读器复用 `ReaderShell`、`reader-shared.ts`、`use-reader-history.ts` 与现有 swipe／drag 能力。

保留桌面右侧 Drawer、移动端全屏、`.pwa-root` Portal、系统返回只关闭阅读器、单一遮罩、焦点陷阱、上层弹窗独占 Escape、退出完成后释放阅读锁。

具体专项验证遵循 [Mantine 叠层验证技能](../../../.agents/skills/validate-mantine-stacked-overlays/SKILL.md)。

### 8.2 选择模型

建议将工具／Thinking 选择统一为可区分类型：

```ts
type ProcessReaderSelection =
  | {
      kind: "tool";
      entryKey: string;
      groupKey: string;
      trigger: HTMLButtonElement;
    }
  | {
      kind: "thinking";
      entryKey: string;
      groupKey: string;
      trigger: HTMLButtonElement;
    };
```

真实生命周期仍复用已有选择 generation／intent 机制，不以本类型替代来源校验。

- 用稳定条目 key 查找内容，不用数组下标。
- 新工具或 Thinking 不抢占已打开目标。
- partial 转正式结果时更新当前内容，不重新打开 Drawer。
- 来源消失或会话切换时关闭并释放旧状态。
- 旧退出回调不能关闭后来打开的新阅读器。
- 与文件、摘要阅读器保持互斥。
- 不把本轮新建的阅读器与旧阅读器同时保留为两个可操作叠层。

### 8.3 Thinking 正文

- 使用现有 Markdown 渲染，只展示实际收到的文本。
- 不为历史空 Thinking 编造正文。
- 不在消息流中再做第二层“展开全文”。
- 阅读器中按既有阅读风格呈现。
- 停在底部时可跟随增量；用户上翻后停止自动跟随。
- 阅读器滚动不联动主消息列表。
- 大段正文不能使所有历史过程行在每个字符到达时反复重做 Markdown 渲染。

### 8.4 工具阅读器状态一致性

当前 `ToolReader` 自行从 `value` 推导状态。重构后防止“明细行状态未知、阅读器仍旋转”。明细与阅读器使用同一有效状态判断，必要时为阅读器增加明确状态输入；不能为了外观同步修改原工具事件对象。

### 8.5 焦点恢复

按以下顺序处理：

1. 用户已主动移到有效控件：不干预。
2. 原触发器仍可见、可用，且不会在紧接的自动折叠中隐藏：回原触发器。
3. 所属组已收起或即将自动收起：回稳定组头。
4. 来源整体消失：回消息列表。

使用 `focus({ preventScroll: true })`。不能仅凭矩形非零判断退出中的控件可回焦，还要检查连接、可见性、`inert`、隐藏和禁用状态。

## 九、Working 与过程组交接

### 9.1 保持原运行边界

继续复用末轮判断、新发送与已入队消息区别、`run_end` 排除、空闲遗留 partial 排除和旧轮 partial 排除。

存在任意 partial、任意工具或旧 spinner 仍挂在 DOM，都不是当前轮正在运行的充分条件。

### 9.2 活动承载规则

以下规则与 R02 一并在 P0 冻结：

1. 当前末段过程组有有效 Thinking／工具时，由该组承载具体运行状态。
2. 过程组仍是当前输出末段、暂时没有具体活动时，可在组头承载 `Working…`。
3. 其后已有正文或其他硬边界时，不把通用运行状态强行挂回较早的历史组。
4. 没有合适过程组承载时，继续使用末尾 Working 兜底。
5. 压缩状态按既有优先级处理，不同时渲染两个等价的通用提示。
6. 组内多个工具各自真实的运行图标不属于重复兜底；不能为“只保留一个 spinner”隐藏真实子项状态。

### 9.3 状态与实际呈现分开

`tool-indicator-visibility.tsx` 可复用或泛化。其职责仍是判断由业务状态注册的运行图标是否被透明度、折叠裁剪或退出冻结影响，而非从 DOM 推断业务状态。

这里的可见性是组件呈现可见性，不是“滚入浏览器视口才算运行”。不得因用户滚动浏览历史反复插入或移除 Working，也不为此新增全局 IntersectionObserver。

DOM 观察只在必要的有限呈现过渡内逐帧执行，状态或集合未变时去重，不因无限 spin 长期采样。

### 9.4 逐帧交接

覆盖：

```text
Working → Thinking
Thinking → Tool
Tool → Thinking
具体活动 → 暂时等待
过程组 → 正文＋Working
运行中 → run_end
展开 → 收起
收起 → 展开
```

要求：

- 不出现已绘制的一帧“双通用运行提示”。
- 仍运行且无具体提示时，不出现无提示空窗。
- 同高度替换不产生额外占高。
- 退出冻结图标的归属仍核对当前轮。
- 真实完成状态不为维持动画而延迟。
- 采样在该帧相关提交完成后进行，不能把绘制前中间态当成用户已经看到的帧。

## 十、滚动与自动收起

### 10.1 唯一滚动写入者

主消息列表继续由 `TimelineViewportCoordinator → TimelineViewportLayout` 统一管理滚动。

过程组件禁止：

- 调用 `scrollIntoView()`。
- 自己写主列表 `scrollTop`。
- 新建一套贴底 rAF。
- 长期保留补偿 padding。
- 用固定延迟等待“页面稳定”后再滚动。

### 10.2 区分布局变化

| 类型 | 原则 |
| --- | --- |
| 纯状态／文字替换，高度不变 | 不启动滚动 |
| 新成员加入、真实内容增长 | 走既有几何观察与跟随逻辑 |
| 自动折叠、整组真实收缩 | 保持跟随或阅读锚点，处理净高度与短期可达空间 |

不能全部当成“新增一个 Working 行”。当前 `added` 主要表达新增净占高，观察层将负值钳到 0；不能传负高度就声称实现整组收缩协议。

### 10.3 实施路径与接口门禁

先验证 `Collapse + ResizeObserver + 现有 Coordinator` 能否满足自动收起场景，不预先重写协调器。

- 每帧消费真实几何，不按猜测高度推算。
- 不因每次 ResizeObserver 回调重启动画。
- 不把 CSS 折叠进度与另一套补偿进度反复叠加。
- 同一提交中的组收起、Working 消失、完成时间出现按净布局处理。
- 已存在发送过渡时只更新目标，不抢输入区所有权。
- 原位置不可达时，短期补偿必须在交接结束后完全释放。
- 不能将适用于单行状态的高度与时长假设未经验证推广到数屏高的过程组。

现有接口不足、需要新增明确布局原因或生命周期通知时，先冻结事件含义、触发阶段、所有权、中断规则、清理规则及对发送／Working 的影响。不得由实现者一边猜契约、一边修改协调器。

### 10.4 跟随与回看

处于跟随状态：

- 默认展开不暂停跟随。
- 状态替换不重置已有滚动速度。
- 自动收起后仍保持跟随，不误显示“最新”。
- 不为补回已借用留白产生二次推进。

用户回看：

- 不自动跳到底部。
- 历史前插保持锚点。
- 组收缩优先保持仍可定位的阅读内容。
- 子项锚点失效时退回稳定组头，不使用旧 DOM 节点继续恢复。

以下情况必须终止或交还旧过程：上滚、拖动、键盘回看、切换会话、页面隐藏、Reduced Motion 变化、阅读器打开、组件卸载。不得由旧回调在之后重新接管滚动。

### 10.5 组收起的视口契约（2026-10-30 用户确认并已实现）

P6 用真实组件逐帧探测了「16 个工具、超过一屏的运行组在 `run_end` 时自动收起，同时出现完成时间」，1280px 与 390px 结论一致：

| 场景 | 实测 | 判断 |
| --- | --- | --- |
| 跟随中 | 第一帧先向下跟随约 30px 去露出新的完成时间，随后在 140ms 收起过程中回落到新的底部 | 违反 13.4「自动收起＋完成时间出现按净高度处理，不分两次追赶」，需要修复 |
| 回看，正在读的正文位于收起组下方（原位置可达） | 锚点每帧偏差不超过 1px，`scrollTop` 同步回补 | 已符合 10.4，现有锚点恢复即可，不改动 |
| 回看，下方内容不足，原位置不可达 | 浏览器按新的滚动范围夹住位置，阅读内容随收起在约 140ms 内平滑下移一次 | 见下文取舍 |
| 回看，锚点位于组内明细 | 明细卸载，位置随收起平滑回落，组头进入可视区 | 组头作为退回目标可见，符合「退回稳定组头」 |

关于不可达场景的取舍：要让阅读内容不动，只能在底部临时垫空白；但第二章已冻结「不用长期占位」，空白必须在交接内释放，释放时内容照样移动。临时补偿只会把「随收起一次平滑下移」变成「先停顿再下移」，终点不变，还多一段停顿。因此不可达场景保持现状，并写入 DESIGN：只做一次与收起同步的平滑移动，不留占位。

**契约（仅解决跟随场景）**

1. 事件：`ConversationTimeline` 在任一过程组的展开状态由 true 变为 false 的那次提交中（自动收起或手动收起都算），在 layout effect 里沿用 `TIMELINE_GEOMETRY_EVENT` 派发 `{ reason: "collapse", removed, duration }`。`removed` 是这些组的明细在收起开始时的实际渲染高度之和，即预计收回的高度，非负；该值只作为预期，不作为位置终点。`duration` 为 `--pwa-duration-collapse-out` 加 `Collapse` 既有的 50ms 兜底。该 effect 声明在 Working 显隐通知之前，同一提交里协调器先得知收起。
2. 触发阶段：子组件的 layout effect 先于 `useTimelineViewport` 对同一提交的处理，因此协调器在处理完成时间等新增内容之前就已得知收起。
3. 观察层：只对 `reason: "collapse"` 接收 `removed`，转发为新的 `collapse(removed, duration)` 事件；`activity` 的 `added` 仍钳到不小于 0，含义不变。
4. 协调器：跟随中、未暂停，且当前不是发送过渡或「最新」过程时，进入收起保持期。保持期内跟随目标不得高于当前位置：不为同一提交里的新增内容先跟随，让收起带来的自然回落把底部带入视野；向上修正（如 Working 消失）不受限制。保持期在以下任一时刻结束：
   - 测量到自然底部已收回 `removed`；
   - 到达收起时长（`--pwa-duration-collapse-out`）加既有的 50ms 兜底。

   结束后按现有规则跟随剩余的净变化，方向只会继续向下，不会反向。
5. 所有权与中断：保持期不拥有任何滚动写入，也不改 padding。以下情况立即清除保持期：`exit`、`reset`、发送接管、用户输入或回看、页面隐藏、Reduced Motion 变化、来源切换。不新增 RAF 或计时器所有者，使用协调器现有的调度。
6. 不适用的情况：未跟随或已暂停时忽略该事件（由现有锚点恢复负责）；`animate` 为 false 时（Reduced Motion 或页面隐藏，收起本身没有高度过渡）忽略；发送过渡期间忽略，不抢输入区所有权。
7. 验证：
   - 协调器 Node 测试：保持期阻止向下的先行一步；按收回量或时限结束；在暂停、回看、发送、「最新」、无动画时都被忽略；`exit` 或 `reset` 时清除。
   - 真实组件 Browser 测试：跟随场景逐帧 `scrollTop` 单调不增，结束时完成时间完整可见且保留基础间距，仍在跟随，无残留 padding；把原位置可达的回看与组内锚点两类回看场景固化为回归用例。
   - 发送、Working 与排队出队等现有 `message-send`、`timeline-viewport.integration`、`use-timeline` 用例全部保持通过。
