# 时间线视口协调层重构方案

- 日期：2026-10-22
- 用途：在新会话、新分支中实施局部重构的设计与验收依据；本文不是当前实现说明。
- 项目级状态：见 [ROADMAP](../../ROADMAP.md)，不在本文另设状态表。
- 基线：[PR #133](https://github.com/yefengr/pi-reach/pull/133) 已压缩合并，提交 `49edf356be5c7330f52028f778355756a7d27dec`。
- 当前事实来源：[ARCHITECTURE](../../ARCHITECTURE.md)、[DESIGN](../../DESIGN.md)、[已关闭决策](../../adr/20260518-closed-decisions.md)。实现完成后再把成立的架构事实同步至长期文档。

## 1. 决策与边界

保留现有产品交互，重整“时间线视口与发送布局协调层”，不重写消息系统。重构要消除分散在事件回调中的控制权交接与隐式推进依赖，而不是仅拆文件、换动画库或增加特殊分支。

本轮已完成原 PR 合并与方案落盘，不开始重构、不创建实施分支。后续从更新后的 `main` 创建独立分支，以新 PR 交付。本文不授权升级版本、生产发布或自动合并新 PR；功能分支推送与 staging 覆盖按 [DEPLOYMENT](../../DEPLOYMENT.md#功能分支部署-staging) 核对。

### 必须解决

1. 同一组变化，分开到达、同次提交或交换顺序时，阅读意图与最终位置一致。
2. 动画结束、用户中断、编辑下一草稿、切换会话都有完整的退出与交接规则。
3. 阅读位置不依赖组件恰好使用某种包装层或视觉 class。
4. 能追踪位置变化的来源，支持原设备单帧异常取证。

### 不改动

- 协议、Relay、Extension、上传传输、消息持久化与流式显示节拍。
- 投递、unknown delivery、取消、重试、草稿版本保护及附件最终提交的业务语义。
- 真正等待队列与在途消息的区分；不得使用带 Owner 权限含义的 `cancelable` 代替权威阶段字段。
- 已确认的视觉 token、气泡身份和动效；不引入全局 smooth、整列表 transform／高度动画、永久占位或新依赖。
- 键盘识别算法、阅读器叠层及焦点规则。只在确有必要时调整它们向视口报告变化的接口。

## 2. 已验证问题与未闭合风险

PR #133 包含以下问题的修正，它们是重构必须保留的回归基线，不代表还要重新实现同一补丁。

| 已验证现象 | 暴露的契约缺口 | 新方案应提供的保证 |
| --- | --- | --- |
| Working 单独更新时留下底部间隙，伴随新消息数组时瞬间滚动 | 几何变化依赖消息更新顺便触发 | 实际状态显隐独立进入布局处理 |
| Latest 或短会话重置后沿用旧位置 | 多入口分别维护滚动基线 | 绑定代际和实际落点统一维护 |
| 长用户消息独占视口时，前插历史使阅读段落移动数百像素 | 锚点选择器没有识别消息外层 | 显式可锚定行与稳定身份契约 |
| 发送期间输入下一条等高草稿，仍距底部 142px | 取消动画后没有后继调度；等高输入不会触发尺寸观察 | 每次退出都决定下一步，不能依赖后续事件救场 |

滚动动画虽已有统一 RAF，但 React 布局提交、autosize、状态通知、键盘补偿、浏览器钳制和异步 scroll 仍可能以不同顺序交错。单个动画调度器不能代替完整的布局与交接规则。

**原 iOS 录屏的首个单帧回跳仍未取得原设备的 DOM／合成层根因证据。** 它出现在 Working 之前，不能归因于 Working 显隐，也不能根据桌面通过就宣称关闭。不同缺陷有相近的视觉表现，不能强行归为一个根因。

### 合并时的验证边界

原 PR 最新头提交 `eb876ab` 的 [Linux CI](https://github.com/yefengr/pi-reach/actions/runs/39735971074) 与 [staging 部署](https://github.com/yefengr/pi-reach/actions/runs/39735964321) 成功，已有两条 Codex P2 已修复并回复关闭，局部修正有独立审查。用户明确授权不再等待该提交尚未结束的 Codex 复评，按已有验证结果合并。这不等同于最新 Codex 复评通过，也不等同于原设备问题完成验收。

## 3. 必须保持的交互

行为仍以 [DESIGN 的组件规则](../../DESIGN.md#组件规则)为准，本节只列本次重构的关键不变量：

- 本地文字或附件消息成功提交后立即恢复跟随，输入区／footer 回缩和真实滚动约 160ms 协调完成。上传开始不改变阅读位置，失败不创建成功发送过渡。
- 新气泡保留 6px／160ms 入场，pending、在途与正式记录交接保持节点和动画身份；历史恢复、重试、回执与正文增量不重播。
- Working 图标立即出现，文字约 120ms 淡入；具体思考／工具运行提示优先，正式 `run_end`、离线和残留 partial 的语义不变。
- Working 在发送过程内只更新目标，不重启时钟；发送结束后且仍在跟随时，允许约 160ms 的局部状态交接。
- 同次提交中的 Working 与 Thinking／工具替换按净几何变化处理，等高替换不额外滚动，不把移除和添加拆为两次可见移动。
- 用户回看立即优先；touchstart 或轻点本身不暂停，手指向下拖对应向更早消息回看。
- Reduced Motion 下没有尺寸和滚动动画，保留适用的短淡入；中途切换偏好要立即结束几何过渡并使旧回调失效。

## 4. 职责与数据流

```text
成功发送 / 用户操作 / 内容提交 / 状态显隐 / 视口变化
                         ↓
                   视口协调器
          意图、控制权、绑定代际、交接、后续调度
                         ↓
                   布局适配层
            测量、应用尺寸、滚动、读取实际落点
                         ↓
                   原生消息滚动区
```

| 模块 | 负责 | 不再负责 |
| --- | --- | --- |
| `useTimelineViewport` | React 适配、监听注册、向 UI 提供跟随与未读状态 | 在各回调内分别拼装取消、恢复与调度步骤 |
| 视口协调器 | 状态转换、当前过程、生命周期、后继调度 | 判断消息是否投递成功 |
| 布局适配层 | 测量、应用输入高度和临时尺寸、滚动、读取实际落点 | 自行决定用户是否还想跟随 |
| Composer autosize | 计算自然高度、预算上限和溢出策略 | 与发送动画交替直接写同一输入框 |
| 时间线组件 | 渲染内容，报告本次提交及实际状态显隐 | 自行写滚动位置 |
| 阅读锚点模块 | 捕获和恢复语义行、可读块及偏移 | 根据视觉 class 猜测消息行 |

键盘模块继续拥有外壳 visual viewport 补偿，其变化作为协调器的布局输入。不要求所有 DOM 由一个模块渲染；要求每项可变几何属性只有明确的写入者。协调器可通过注入布局与调度端口实现，不应为了记录每帧内部状态触发整棵 React 组件树重渲染。

现有曲线时钟、clone 高度测量、自然 chrome 预算、稳定 presentation 身份与观察目标差分优化优先复用。具体新增文件名在实施时按职责确定，不以拆分数量作为完成标准。

## 5. 状态模型与不变量

### 阅读意图

区分“跟随最新内容”与“保持阅读位置”。详情展开等阅读暂停有明确原因与恢复规则，不与用户回看混为一谈：关闭详情不得覆盖用户已形成的回看意图；点击 Latest 仍可按既有规则显式恢复，不能因简化状态机而失效。

### 当前过程

同一时刻只有一种滚动控制模式：普通跟随、发送布局过渡、活动状态交接或 Latest 平滑滚动。过程不各自启动独立滚动器，而由同一个协调器管理。普通跟随可以处于已到达目标的静止状态。

### 绑定与代际

复用现有会话／历史作用域，绑定当前列表 DOM 和当前操作代际。重置、容器替换或卸载后，旧测量结果、RAF、观察器通知与程序滚动回执都必须失效。普通 leaf 推进不能被当成新视图；合法历史阅读位置按原有 scope 恢复。

### 必须始终成立

1. 跟随未暂停且尚未到达可达目标时，必须有推进中的过程或下一次调度。
2. 用户开始回看后，旧动画不能继续写位置。
3. 同一输入高度不能同时被 autosize 与发送动画写入。
4. 过程退出后不残留输入绑定、footer 高度或临时补偿 padding。
5. 程序滚动基线来自浏览器实际接受的位置，而非仅记录请求值。
6. 新视图不能使用旧视图的几何基线或迟到回调。
7. 相同高度、相同内容引用下的语义变化也能独立推进，不依赖新的消息、尺寸观察或回执。

## 6. 统一交接规则

调用方只报告事件，不再自行组合 `cancel → finish → restore → schedule`。协调器根据退出原因，一次完成取消旧帧、释放临时尺寸、必要的锚点恢复、实际基线更新以及后继行为选择。

| 事件 | 行为 |
| --- | --- |
| 本地消息成功提交 | 恢复跟随、创建发送过程并保证首次推进 |
| 上传开始／提交失败 | 不创建成功发送过程，保持原阅读意图与失败保留规则 |
| 发送中编辑下一草稿 | 释放尺寸控制权后继续普通跟随；不等待高度变化或新输出 |
| 用户向上回看 | 取消当前过程，释放临时尺寸，恢复并保留阅读锚点 |
| Working 显隐或具体状态替换 | 按提交后的净变化处理，已有发送过程不重启 |
| 普通正文或回执 | 更新目标，不因此创建新的平滑过程 |
| 点击 Latest | 显式恢复跟随，完成后交给普通跟随；期间仍可被用户中断 |
| 切换／重置／卸载 | 作废旧代际并释放资源，不把旧基线带入新视图 |
| 开启 Reduced Motion | 按有效阅读意图立即结束几何过程，旧回调失效 |
| 页面隐藏／外部尺寸变化 | 明确结算或失效当前过程，恢复时使用有效布局；不靠旧帧续写 |

“结束动画”必须同时决定下一步由谁负责，不能留下只清理资源、不处理后继状态的中间态。

## 7. 布局提交机制

### 7.1 发送前捕获与成功激活分离

文字和附件最终提交入口目前的更新顺序不完全相同，不能依赖 React 恰好批处理。

- **只读捕获**：在最终提交前记录可见位置、输入区自然尺寸及 footer 尺寸；不注册尺寸 owner、不写 style、不改变跟随意图。
- **成功激活**：仅在既有业务逻辑确认提交成功后使用快照启动过程。
- **失败丢弃**：失败、异常、目标失效或绑定变化时丢弃快照。附件上传期间不长期占有布局控制权。

不得为了动效重排投递和 unknown delivery 的业务语义。真实附件最终回调、草稿版本保护、卡片移除与消息插入必须由集成测试覆盖，不能用简化夹具证明真实入口的时序。

### 7.2 一次处理的顺序

1. 接收变化与原因，核对绑定和操作代际。
2. 读取当前布局及自然目标尺寸。
3. 根据意图与模式决定贴底、保锚点、过程推进或不处理。
4. 应用本次尺寸变化。
5. 必要时重新测量实际可达滚动范围。
6. 写入位置并记录浏览器实际落点。
7. 明确结束，或安排下一次推进。

尺寸释放与位置纠正不能故意拆成两次可见绘制。React 提交后的必要纠偏仍保留绘制前路径，不机械地全部延迟到下一帧。同步提交与动画帧共用处理入口，防止同步通知重入；重入只合并待处理原因，不递归推进多轮动画。

这不意味着 JavaScript 可以原子化浏览器合成层，原设备仍须验证。

### 7.3 通知与补偿

ResizeObserver、内容提交、实际状态显隐及键盘变化统一进入协调器。可以合并重复通知，但不能丢失用户输入或作用域失效事件。

- 不靠复制 `items` 触发滚动。
- 不把 ResizeObserver 当作漏调度后的补救。
- 不用固定时限忽略所有 scroll。
- 状态移除时仅保留当前过程尚需收回的临时空间；完成、取消和失效路径都释放。
- 不保持虚假的 running 状态来等待退出动画。

## 8. 显式阅读锚点

可锚定的顶层时间线行提供语义标记和稳定行键，优先复用已有 presentation 身份。

- 不新增包装层，不借用带 margin 的视觉 class。
- pending 到正式记录使用现有投影保留的行身份，不能切到会在确认时变化的新键。
- 锚点记录行键、可读块定位及相对视口偏移；节点仍在时优先身份恢复，节点替换后按明确键查找。
- 行键只在当前有效视图内定位；内容缺失时不得恢复到无关消息。
- 正式用户、pending、正文、Thinking、工具与摘要等直接行消费者均需盘点，不能只补用户行而保留新的隐式遗漏。

必测“只有一条高于视口的用户消息可见，前插历史后当前段落保持位置”。

## 9. 诊断与验证

### 最小诊断能力

提供默认关闭、显式启用的有界内存记录。诊断模式须可用于 staging 原设备，而非只存在于开发 bundle；不默认上传、不写正式持久化。

允许记录：事件顺序、相对时间、意图、模式、本地非业务代际、列表／输入区／footer／visual viewport 几何、请求值与实际落点。禁止记录消息正文、附件内容、凭据、完整业务身份或地址。

记录应能读取和清空，关闭诊断或解绑时有明确清理边界。不得借诊断新增通用执行能力或任意数据导出入口。

### 三层验证

| 层级 | 重点 | 不能替代 |
| --- | --- | --- |
| DOM 独立状态测试 | 事件转换、退出策略、代际失效、后继调度与非法组合 | 浏览器布局 |
| 真实浏览器组件与集成 | 实际高度、锚点、输入、附件最终提交、异步通知和逐帧行为 | 原设备输入与合成过程 |
| 原设备验收 | iOS 键盘开／关、文字／附件、跟随／回看及原录屏场景 | 代码层不变量覆盖 |

事件组合至少覆盖：Working 单独到达／伴随回执／发送中／发送后；等高与变高的下一草稿；连续发送；Latest 后切会话；长用户消息前插；详情暂停与恢复；用户回看；减少动效、页面隐藏及容器替换；取消后的迟到回调。

测试同时检查过程位移、Latest 是否闪现、最终位置、草稿保留、节点身份、临时资源释放和无效回调无写入，不能只看最终 gap 为零。几何按整像素与合理容差比较，真实帧等待使用稳定条件和宽裕上限，不依赖慢 CI 无法保证的短墙钟窗口。

直接入口包括现有 `message-send.browser.test.tsx`、`use-timeline-viewport.browser.test.tsx`、`timeline-viewport-anchor.browser.test.tsx`、`timeline-viewport.integration.browser.test.tsx`、autosize／短屏 Composer、Working fallback 和 `pwa-app.browser.test.tsx` 的文字／附件最终提交用例。沿用 [PWA 验证规则](../../../pwa/AGENTS.md#验证与交付)，本地运行直接受影响范围，更广回归由新 PR 的 CI 覆盖。

WebKit 自动化可补充覆盖，但不能替代原 iOS 设备。原单帧回跳如果仍存在，须取得有效时序证据后再定位，不能继续用桌面绿灯宣布关闭。

## 10. 实施阶段与完成标准

| 阶段 | 产出与门槛 |
| --- | --- |
| 冻结基线 | 核对新分支基线、状态交接表、直接消费者及原设备观测方式；不扩展动效需求 |
| 协调核心 | DOM 独立状态／调度核心及不变量测试通过，再接入布局端口 |
| 入口迁移 | 接入发送捕获／激活、下一草稿、活动通知、Latest、阅读与生命周期；任一时刻只有一个有效写入者 |
| 收口验收 | 移除旧控制路径和临时切换开关，完成定向验证、独立审查、CI、staging 与原设备复测 |

实现可分小步验证，但生产不保留新旧控制器同时生效。不得以“引入 reducer”或“拆出 controller 文件”代替行为收敛。

完成必须同时满足：

- 已知缺陷都有能在旧逻辑上失败的回归，状态和资源不变量成立。
- 两个真实成功提交入口及失败／草稿保护未回归。
- 相关类型、lint、构建、文档与 diff 检查通过；未覆盖项逐项保留。
- 新 PR 评审意见已处理；代码实现完成与原设备缺陷关闭分别说明。
- 原设备场景取得验证证据。若原回跳未闭合，本事项不能以局部重构或自动化通过替代设备验收。
