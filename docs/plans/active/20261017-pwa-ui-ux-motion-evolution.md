# PWA UI、UX 与动效演进方案

- 日期：2026-10-17
- 用途：保留设计评审、分批实施边界与验证证据；候选部分不代表已经实现或生效。
- 项目级状态：已确认的阶段 B 见 [ROADMAP](../../ROADMAP.md)，尚未确认的后续范围见 [BACKLOG](../../BACKLOG.md#pwa-uiux-与动效后续演进)。
- 当前实现基线：[DESIGN](../../DESIGN.md)。本方案包含候选方向与评审记录；正式代码按批落地并同步规范前，继续以当前实现说明为准。

## 1. 目标与结论

让 Pi Reach 在长时间阅读时安静清晰，在操作时立即响应，在状态变化和页面切换时保持空间连续。改进的重点是表面层次、信息密度、局部反馈与动效语义，而非给所有元素增加动画。

建议采用以下方向：

1. 以细微表面差异和有限抬升建立层次，允许 Composer 等关键操作区使用轻阴影。
2. 将阅读密度、操作密度与设备输入方式分开，不再由一个屏幕断点决定所有组件表现。
3. 高频反馈在操作原位完成，减少成功 Toast；异步状态切换保持尺寸与焦点稳定。
4. 建立按动作分类的动效语言：按钮短促、菜单轻巧、展开平稳、面板跟手、图片连续放大。
5. 保留现有阅读锚点、历史恢复、用户展开选择和手势中断能力，并将它们写成新规范的基础保证。
6. 宽屏允许对话与产物并排工作；移动端继续以单栏和全屏阅读为主。

本轮不以既有的纯灰、无页面阴影、单断点、三条动效曲线或统一尺寸为不可变前提。每条规则按其解决的问题重新判断；对比度、可操作性、状态真实性仍是验收要求。

## 2. 调研证据与适用边界

### 2.1 证据分层

本方案参考 Claude 风格界面的第三方设计解析与组件示例，并与 Pi Reach 源码对照。未直接运行或测量 Claude 官方客户端，也未运行第三方展示页。因此，下文“参考设计”表示已阅读的示例机制，不能解释为对官方现行行为的完整确认。

| 层级 | 可以支持的判断 | 不能支持的判断 |
| --- | --- | --- |
| 第三方组件源码 | 表面、布局、状态与动画的实现意图，部分实际机制 | 官方完整规范、真机帧率、实际触感与所有无障碍保证 |
| 第三方文档／代码注释 | 可用于提出待验证的设计假设 | 不能单独证明功能已实现或达到生产质量 |
| Pi Reach 代码与 DESIGN | 当前 token、组件行为、直接改动入口 | 不能替代新方案的视觉原型和真机验收 |

参考快照为 `ddf3aea1711db62fd6d24343bbab500a5ae69f64`，Pi Reach 调研基线为 `c3ba0ee`。这是本次分析的版本记录，不要求后续实现固定在该版本。

### 2.2 参考设计中值得保留的机制

| 设计机制 | 对体验的价值 | Pi Reach 的吸收方式 |
| --- | --- | --- |
| 接近的表面明度、细边界、低强度阴影 | 让界面有层次，同时保持长篇阅读安静 | 从 Composer、Popover、文件卡片建立有限层级 |
| 控件外壳与绘制层分离 | 按压反馈不改变点击区域和布局 | 复用现有图标按钮伪元素，扩展微交互 |
| 选中滑块、图标原位替换 | 表达同一控件内部状态的连续变化 | 用于确有分段选择需求的控件与复制反馈 |
| 容器宽度自适应 | 组件在窄面板中仍保留关键操作 | Composer、阅读器工具栏按自身宽度降级 |
| 消息、推理、工具与产物分层 | 用户能先读结论，再按需检查过程 | 保留当前折叠策略，改善层级和状态交接 |
| 缩略图与预览的共享元素过渡 | 解释打开与关闭的空间关系 | 图片阅读器优先验证 |
| 柔和滚动边缘 | 提示局部区域还有内容 | 用于长菜单、附件横排，谨慎用于正文 |
| 可调宽的产物工作区 | 支持边看结果边继续提问 | 宽屏引入可固定的非模态面板 |

### 2.3 不能直接继承的声明与实现

抽查发现：Diff 示例仍随全文变化重新解析；确认框声明焦点锁定，但组件本身没有完整焦点陷阱与恢复实现；多个按钮／复制示例没有等待异步成功便更新成功状态；动画主题只对部分效果限制了动态偏好，不能视为全局减弱动效方案。

因此，不整包移植示例，不因代码注释写了“物理引擎”“生产级”“合成器动画”就认定其正确。视觉参考、交互模型与工程实现分别验收。纯 CSS 的高度、网格、模糊或阴影动画也可能产生布局或绘制开销。

## 4. UI：建立安静而可辨认的视觉层次

### 4.1 表面与抬升

建议按角色定义画布、导航、可操作表面和浮层，而非让每个组件独立决定背景与阴影：

| 角色 | 建议表现 | 使用场景 |
| --- | --- | --- |
| 阅读画布 | 稳定底色，无装饰阴影 | 会话正文、设置正文 |
| 导航／次级承载 | 与画布有细微明度差 | 侧栏、历史说明、工具展开区 |
| 操作表面 | 细边界，可有极轻阴影 | Composer、可点击产物卡片 |
| 浮层 | 比操作表面更明确的轮廓与投影 | Menu、Popover、Toast |
| 模态层 | 遮罩与投影，明确阻断关系 | 确认框、移动阅读器 |

浅色主题先试验 Composer 的 `0 2px 12px` 低透明黑色阴影与细描边组合；该值仅用于原型。深色优先靠表面明度和边界区分，不机械加深阴影。

正文消息、普通导航行和每条工具输出不逐项加阴影。悬停不默认让卡片上浮，避免鼠标扫过时整页运动。

### 4.2 配色方向

推荐先保留雾蓝主色，用中性表面完成层次改进。同时提供一份低饱和暖灰对照稿；不预先把 R=G=B 作为评审门槛。

比较时固定字体、间距和内容，只替换表面色，验证中文长文、代码、Diff 与深色主题。若暖灰胜出，再以新 ADR 说明对 [中性底色决策](../../adr/20261001-neutral-surfaces-mist-blue.md) 的修订，保留原决策背景。

不直接采用大面积陶土色，不让品牌色渗入所有选中底、状态底和代码底。色彩调整必须同时维护状态语义与文字对比度。

### 4.3 轮廓、圆角与焦点

将“一处只出现一个主要闭合轮廓”作为减噪启发，而非绝对禁令。已有外框的卡片内部，次级按钮优先使用浅底或 ghost；输入字段、危险操作与需要明确边界的控件仍可描边。

Composer 可试验 16px 外圆角、内部 8–10px 控件圆角；浮层可试验 10–12px。嵌套圆角按内缩距离协调，不让外层和内层同大导致视觉拥挤。贴屏边缘与安全区仍按实际几何处理。

保留清晰的键盘焦点。鼠标聚焦和键盘聚焦可以采用不同强度的视觉反馈，但不能以柔光代替可辨识轮廓。

### 4.4 字体、行长与密度

推荐继续使用系统字体，不为模仿外观引入网络字体。正文 16px、输入 16px 和中文阅读行高先保持；元数据不以极小字号制造精致感。

将当前统一规则改为按任务选择：

- 长篇正文保留舒适密度；代码、路径与表格可按内容选择更宽阅读区。
- 桌面细指针环境的导航与菜单可试验 36–40px 行高；触屏／粗指针保持至少 44px 操作区域。
- 混合输入设备以可触控为优先，不因窗口宽度大就缩小所有点击区。
- 不先加入全局“紧凑模式”设置；验证一套自适应默认值，只有明确需求再提供用户偏好。
- 复制、移除等小图标可以视觉紧凑，但实际点击区域不得与相邻控件重叠。

### 4.5 图标与内容呈现

保留单一图标语言和一致线宽。状态图标、折叠箭头、操作图标分别预留槽位，避免文本更新推动控件。

普通回复保持无卡片底，用户消息保留轻底区分。对超长用户输入可以试验渐变收起与“展开”，必须保留完整复制、键盘操作和会话内展开状态；不默认折叠模型结论，不用遮罩掩盖错误或关键操作。

代码工具栏和正文滚动分离，保留复制可达性。结构化 Diff 可增加文件名、增删统计、hunk 导航与宽屏左右视图；原始输出继续可查看，识别失败时回退纯文本。

## 5. UX：让操作、状态与结果在同一上下文中连续

### 5.1 Composer 是主要操作表面

输入、附件、模型和发送应形成一个整体，内部不再层层加边框。聚焦时外轮廓与轻阴影略增强，取消聚焦后恢复；不改变尺寸。

工具栏按自身宽度逐级收敛：先隐藏次级说明，再收短模型文本，最后将低频设置收进菜单。附件与发送／停止优先保留。键盘快捷键不能只靠隐藏后的图标提示，帮助入口继续可达。

发送动作立即给出已触发反馈，但“已送达”“正在执行”必须由实际回执决定。输入内容清空和失败回填沿用现有身份与版本判断；不能为了流畅动画提前丢弃用户内容。

新增文本草稿恢复作为独立实施单元：按电脑、Pi 与会话隔离持久化，刷新后可恢复。目标退出后允许复制或明确选择转用，不自动发往新实例。附件原件是否持久化另行评估，本轮不承诺恢复原件，也不引入离线自动发送。

### 5.2 反馈分级与去重

| 操作 | 推荐反馈 | 关键要求 |
| --- | --- | --- |
| 复制 | 原位对勾，约 2 秒恢复，简短读屏播报 | 等剪贴板成功后再确认；不再同时弹成功 Toast |
| 模型／思考设置 | 控件原位显示实际生效值 | 操作中与已生效分开；失败保留原因与重试 |
| 附件与文件获取 | 原卡片进度、成功、错误、重试 | 固定操作槽位，不添加第二套全局进度 |
| 普通成功 | 优先局部文字或图标 | 没有可见来源且结果容易被错过时才用 Toast |
| 错误与危险 | 说明影响及下一步，必要时持久显示 | 不用成功动画暗示未确认结果 |
| 连接状态 | 标题区摘要，持续故障再展开说明 | 不让短暂重连反复挤动正文 |

图标替换使用固定宽高槽位；出现“已复制”等文字时预留宽度或仅在辅助说明呈现。无须把所有成功都染成绿色或做弹跳。

文件获取后自动打开前，目前固定停留完成态 600ms。建议评估取消强制等待：显式点击“查看”的用户，在内容与阅读器准备好后直接进入；完成提示可以在卡片或阅读器内交接。是否保留短停留应由可感知性验证决定，不把旧数值当作必需规则。

### 5.3 思考、工具与运行状态

保留默认折叠与用户决定权；运行开始、流式增长和结束不强制改变用户选择。

采用“一个主要动态提示”的策略：当前过程已有明确运行提示时，不再叠加闪烁文字、呼吸背景和重复 spinner。工具展开列表需要逐项说明状态时可以保留真实状态，但避免所有完成项持续动画。

参考设计的三点波浪可与现有 spinner 做对照，选择辨识度好、注意力负担低的一种；不要求每种运行状态都拥有不同装饰动画。思考标题更新仍按语义块处理，不逐字模糊或逐字跳动。

完成图标原位交接，标题与箭头不跳动。`run_end`、中断与未知等真实性规则继续由协议和状态模型决定，动画结束不代表业务结束。

### 5.4 导航与任务辨识

侧栏先改善扫描效率：主标题、路径／分支、运行状态采用明确层级，元数据不同时争抢字重。只有可靠数据才显示 Git 信息；不能由目录推断实例身份。

常用项固定与排序可作为后续增强，拖拽必须有键盘替代和明确落点。初期不让每次工具更新触发侧栏重排，不自动把运行中的 Pi 抢到用户正在点击的位置。

跨电脑任务总览是后续信息架构议题，不作为本轮微交互改造的前置依赖。

### 5.5 桌面工作区与移动阅读

宽屏推荐支持可固定的右侧工作面板，让文件、工具与 Diff 和对话并排。面板为非模态，输入区保持可用；提供拖拽调宽、键盘调宽、恢复默认与关闭。新产物不自动抢占面板，用户选择后才打开或替换。

是否进入分栏取决于主区扣除侧栏、安全区后的实际宽度；原型起点可用对话最小约 480px、工作面板约 360px，再加分隔与留白。空间不足时退为覆盖阅读，不把两栏挤到不可读。手机仍用全屏阅读，平板按实际空间决定。

这会修订“桌面阅读器固定为 720px 模态 Drawer”的规则。非模态面板不能机械复用模态焦点陷阱；Esc、Tab、系统返回、原位置恢复和目标切换都要重新定义并验证。

## 6. 动效：按语义建立有限的动作词汇

### 6.1 总体规则

每个动画必须回答至少一个问题：操作是否被接受、哪个元素发生了变化、内容从哪里来、关闭后回到哪里。无法回答时默认静态。

优先动画 `transform` 与 `opacity`。高度和网格动画只用于有限范围的用户主动展开，不把流式增量变成持续布局动画。阴影变化控制范围，不默认添加 `backdrop-filter` 或长时间 `will-change`。

同一组件的进入、退出、手势、业务状态变化必须有唯一的动画归属，防止 CSS、Mantine 与 WAAPI 同时控制同一属性。新动作必须能取消、反向或直接落到正确终态。

### 6.2 推荐动效矩阵

下表为原型起始值。参数通过桌面与真机评审后再进入正式 token，不直接作为已生效常量。

| 动作 | 进入／变化 | 时长起点 | 退出与中断 |
| --- | --- | --- | --- |
| 按钮按压 | 内部绘制层缩至 0.97–0.98，颜色同步 | 按下 70–100ms，释放 100–140ms | 移出、取消、禁用立即复位，不执行动作 |
| 菜单／Popover | 从真实锚点缩放 0.98→1，淡入，可上移 2–4px | 进入 140–160ms | 退出 100–120ms；关闭后不得继续接收操作 |
| Modal | 上移 4–8px并淡入，缩放可省略 | 进入 180–220ms | 退出 120–160ms；焦点交接不受视觉延迟阻挡 |
| 用户主动折叠 | 高度连续变化，箭头同步旋转 | 展开 160–200ms，收起 120–160ms | 反向续播；流式增长不重播 |
| 附件新增 | 淡入，上移 4px；必要时缩放 0.98→1 | 140–180ms | 移除后邻项有限补位，不驱动整条时间线 |
| 复制成功 | 图标交叉淡化；可选极小缩放 | 100–140ms，停留约 2s | 再次复制刷新反馈计时，不堆叠动画 |
| 图片预览 | 缩略图到预览区的连续几何过渡 | 200–280ms | 关闭回源；无有效来源时普通淡化 |
| 面板／设置页 | 单层覆盖移动，保持跟手 | 维持现有约 200ms 基线 | 从当前位置续播，手势收尾按剩余距离缩短 |
| 会话切换 | 旧内容撤下、新内容短淡入 | 100–180ms 试验 | 快速切换只保留最后目标，不排队播放 |
| 加载骨架 | 低对比呼吸或窄扫光二选一 | 循环约 1.8–2.2s | 加载完成即交接真实内容，保留防闪策略 |

曲线按用途分为 press、reveal、resize、panel、feedback。大面板不明显回弹；小控件释放可试验极轻弹性，作为可选反馈而不是全局基调。退出通常比进入短，面板的方向对称性与手势节奏单独决定。

保留时长与曲线集中管理，可先用 CSS 自定义属性、Mantine transition 和现有 WAAPI 实现。只有复杂布局连续性确实无法合理满足时才评估动画库，不为几个微动画引入全局运行时。

### 6.3 消息与流式内容的专门规则

- 本地新发送消息可以轻微淡入，默认不模拟输入文字“飞入气泡”，避免长文本几何变形与异步失败回退复杂度。
- 模型首块内容可短淡入；后续 token、Markdown 重排、代码高亮完成不重播入场。
- 历史加载、重连补齐、分页前插与返回已读会话不播放逐条入场。
- 读者回看时不因新增消息改变滚动锚点；动画与“最新”计数不能抢回底部。
- 删除、折叠和图片加载造成的高度变化纳入既有锚点机制，不另建一套自动滚动 hook。

### 6.4 图片共享元素过渡

使用单个稳定来源与目标标识，处理 `object-fit: contain` 的实际图片边界；避免从占位框整体拉伸成图片。图片必须已完成获取和可用解码，不能等待网络后再播放一次迟到的开场。

过渡与阅读器切换只能选一个主要视觉动作，避免图片放大叠加整屏滑入。关闭时来源被卸载、滚离可用范围或目标已经切换，使用淡化退出，不跳向错误缩略图。

优先评估浏览器 View Transition API，提供无 API、减少动态效果、连续点击和过渡失败的回退。返回、关闭、资源清理与最终业务状态不得依赖 `transition.finished` 一定成功。

### 6.5 滚动边缘与持续动画

局部列表的渐变提示由真实溢出状态控制，触顶／触底移除对应边缘；内容或容器尺寸变化后重新测量。初始可试验 12–20px 羽化，不照搬复杂渐变档数。

不让遮罩覆盖焦点轮廓与固定操作，不把正文最后一行长期淡化。页面不可见、元素离开可见范围时暂停装饰性循环；状态文字继续反映真实状态。

### 6.6 减少动态效果与可访问性

建议修订当前“运行中图形照常动画”的统一例外：

- 减少动态效果时关闭空间移动、缩放、弹簧、扫光、波浪和装饰呼吸。
- 运行状态优先使用静态图标与文字；若确有必要保留简单 spinner，须逐项证明必要性，不整类豁免。
- 仍用约 100–120ms 短淡化表达状态交接，必要时直接切换；不人为延长真实完成时间。
- 键盘、读屏和触摸操作不依赖动画完成后才能发现结果；不逐 token 播报动态正文。
- 动态偏好在页面打开期间变化也立即生效，当前动画取消后落到正确状态。
