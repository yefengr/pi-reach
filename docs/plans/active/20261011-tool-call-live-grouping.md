# 工具调用实时分组与折叠方案

本文记录 PWA 会话中工具调用从第一条起即进入折叠组、组头显示当前运行命令、展开选择由用户决定的方案：现状、界面规则、分组与身份、滚动与阅读、实施与验收。本文不独立维护项目级状态，事项状态见 [ROADMAP](../../ROADMAP.md)；当前设计规则以 [DESIGN](../../DESIGN.md#组件规则) 为准，实现完成后把仍有效的规则同步到 DESIGN，再归档本方案。

本方案调整 [ADR-20260930](../../adr/20260930-strict-run-completion.md) 中工具摘要的展示条件，处理方式见「[设计约束与决策记录](#设计约束与决策记录)」。效果稿评审结论（2026-10-11）见「[已确认决策](#已确认决策)」。

## 目标与非目标

目标：工具调用从第一条开始就进入折叠组。用户不展开时，通过组头了解当前在跑什么；用户展开后，新调用追加到该组最下面。

核心规则：**运行状态决定组头显示什么，用户选择决定组是否展开。运行状态不得覆盖用户的展开或收起选择。**

非目标：

- 只调整 PWA 展示层，不修改 Relay、共享协议或 Extension。
- 不新增工具审批（见[已关闭决策](../../adr/20260518-closed-decisions.md)），不修改工具执行方式。
- 不改变“只有正式 `run_end` 能确认整轮结束”的完成语义。
- 不做展开选择的跨刷新持久化。
- 组头不做循环轮播或跑马灯。

## 术语

| 术语 | 含义 |
| --- | --- |
| 轮 | 同一 `group_id` 的一次运行，以正式 `run_end` 确认结束 |
| 工具段 | 同一轮内展示相邻、未被边界打断的连续工具调用 |
| 工具组 | 工具段在界面上的折叠容器，即组头加可展开的工具行 |

## 已确认决策

| 编号 | 决策 |
| --- | --- |
| C1 | 组头不显示“工具调用 · N 项”之类的说明 |
| C2 | 折叠时组头只显示**最后开始**的那条工具；它结束后组头回到分类摘要，较早开始、仍在运行的工具不再回到组头，直到有新工具开始 |
| C9 | 组头工具结束时若进入组头未满 1.5 秒，继续停留到满 1.5 秒（图标换成结束状态）（2026-10-11 补充，由 C10 细化） |
| C10 | 组头改为排队：按开始顺序显示在线期间新出现的每条工具；后面还有排队时每条至少停留 0.8 秒，积压超过 3 条时跳到最新一条；最后一条结束后停留满 1.5 秒再回到摘要（取代 C2 中“立即替换”的部分，2026-10-11 补充） |
| C3 | 组头回到摘要但组内仍有工具在运行时，摘要前保留旋转图标，只表示仍在运行 |
| C4 | 展开时组头只显示分类摘要，不显示当前命令；运行状态看各工具行 |
| C5 | 运行中的末段工具组展开后仍自动跟随；已结束的工具组展开后照旧暂停自动跟随 |
| C6 | 只有一条工具也成组 |
| C7 | 原「Pi 正在思考…」改为「Working…」，按 Pi 的 `working` 状态显示：Pi working、末尾没有正在输出的正文、思考或运行中的工具，且最后一轮尚未收到 `run_end` |
| C8 | `run_end` 不再参与分组与组头，只用于轮末完成时间与结束状态 |

## 现状

分组入口是 [`conversation-timeline.tsx`](../../../pwa/src/components/pwa/conversation-timeline.tsx) 中的 `completedToolRuns`，单条工具和组头分别由 [`tool-card.tsx`](../../../pwa/src/components/pwa/tool-card.tsx) 的 `ToolCard`、`ToolGroupCard` 展示。

| 场景 | 当前行为 |
| --- | --- |
| 本轮正在运行 | 工具逐条展示，不形成工具组 |
| 收到本轮正式 `run_end`，且本轮没有流式内容 | 相邻、状态为成功、失败或中断的工具至少两条（`TOOL_GROUP_MINIMUM`）才合并 |
| 工具状态未知 | 不参与合并，仍逐条展示 |
| 正文、思考、可见记录、已发布文件或历史缺口 | 打断工具段 |
| 工具组首次出现 | 默认收起，组头按类别显示计数摘要 |
| 点击单条工具 | 直接打开详情阅读器，不在会话中展开参数或输出 |
| 用户展开工具组或思考 | 暂停会话自动跟随 |
| 阅读尚未合并工具的详情时整轮结束 | 通过 `pinnedKey` 延后该段合并，关闭阅读器后才合并 |
| 等待 Pi 首段输出 | 显示「Pi 正在思考…」，本轮出现任何输出后不再显示 |

需要处理的实现细节：

- `expansionChoices` 按组 key 保存展开选择，组 key 取组内第一个工具的 key，历史向前补齐会改变它。
- 任一工具组或思考展开时 `readingInline` 为真，[`use-timeline-viewport.ts`](../../../pwa/src/lib/pwa/use-timeline-viewport.ts) 停止所有自动跟随。
- `ToolCard` 在离线时把 partial 覆盖为“未知”，但 `toolGroupSummary` 与组头错误图标不传该覆盖。
- 调用 key 为 `session_id + leaf_id + group_id + tool_call_id`，partial 与正式结果共用；[`timeline-presentation.ts`](../../../pwa/src/lib/pwa/timeline-presentation.ts) 的 `reconcileOrder` 保证已观察条目不因完成时间改变位置。
- [`collapse.tsx`](../../../pwa/src/components/pwa/collapse.tsx) 只在 `open` 变化时播放伸缩动画，已展开内容增长时不重播。

## 界面

### 组头

| 状态 | 组头左侧 | 右侧 |
| --- | --- | --- |
| 折叠，最后开始的工具仍在运行 | 旋转图标 + 工具名 + 参数摘要（复用 `toolHeaderSummary`） | 错误图标（有失败时）+ 折叠箭头 |
| 折叠，最后开始的工具已结束，仍有其他工具运行 | 旋转图标 + 分类摘要 | 同上 |
| 折叠，没有运行中的工具 | 分类摘要 | 同上 |
| 展开 | 分类摘要 | 同上 |

- 组头排队规则见 C10，实现为 [`tool-group-head.ts`](../../../pwa/src/components/pwa/tool-group-head.ts) 的纯函数：`GROUP_HEAD_QUEUED_VISIBLE_MS`（0.8 秒）、`GROUP_HEAD_MIN_VISIBLE_MS`（1.5 秒）、`GROUP_HEAD_MAX_BACKLOG`（3 条）；停留中的已结束工具显示结束状态图标。
- 当前工具变化时，新内容从下方进入、旧内容向上离开，只播放一次；减少动态效果时直接替换。组头高度不变，长命令单行省略。
- 分类摘要沿用现有规则（按类别计数、读取等按路径去重、失败与中断计数追加在末尾），运行中的工具也计入。
- 可访问名称包含展开状态、当前命令（如有）与分类摘要；组头不设 live 区域，运行状态仍由各工具行的 `role="status"` 表达。

### 运行状态派生

组头与工具行使用同一状态派生：离线时 partial 统一视为“未知”，不作为当前命令显示，也不计入旋转图标。实现上把现有的离线覆盖传给工具组，不在组头另行推导。

### 展开

- 保留现有标题式工具行和左侧从属竖线；点击工具行打开现有详情阅读器。
- 新调用追加到组内最下面；同一调用的流式更新、正式结果、失败或中断只更新原位置。

### Working 提示

- 文案改为「Working…」，位置与样式沿用原「Pi 正在思考…」。
- 显示条件见 C7：用户刚发送、工具全部结束等待模型、两段输出之间均显示；正文或思考正在流式输出、或有工具运行时不显示。
- 本轮尚无输出时立即显示；两段输出之间延迟 400ms（`WORKING_BETWEEN_OUTPUTS_DELAY_MS`）显示，避免正文结束到下一个工具开始的交接瞬间闪现。
- 最后一轮已收到 `run_end` 时不显示，避免 `working` 状态晚于结束事件更新时闪现。
- 只按末轮（最后一条正式记录所属的轮）判断：运行时把 partial 排在正式事件之后，已收到 `run_end` 或不属于末轮的残留 partial 不算正在输出，也不决定末尾位置。

## 分组与身份

### 工具段边界

同一会话与分支范围、同一轮内，相邻工具组成工具段。正文、思考、可见记录、已发布文件和历史缺口打断工具段，不跨边界归并。运行中、成功、失败、中断和状态未知的工具都进入工具组；分组本身不证明执行成功或整轮结束。

### 用户选择优先

- 没有选择：默认收起。
- 用户展开或收起后保持，直到用户再次切换；新增调用、partial 转正式结果、失败、中断、`run_end` 和短暂重连都不重置。
- 刷新后默认收起；不同会话、分支或历史范围之间不复用。

### 组身份与选择继承

- 组的 React key 与选择锚点取组内**最早被观察到**的工具 key；历史向前补齐的工具晚于实时工具被观察，不改变已有组的身份。
- 展开选择记录在切换时的锚点工具 key 上，组的有效选择取组内成员上最近一次的选择；重新分段时新段从成员继承。
- 实时分组后不再需要 `pinnedKey` 与 `ReaderState.grouped` 的延后合并：工具从出现起即在组内，阅读器按工具 key 取值，关闭后来源控件仍在则回焦，否则回焦列表。

## 滚动与阅读

- 组头内容变化只改变内部内容，不触发会话滚动。
- 用户在工具组属于最后一轮、仍在运行且位于时间线末尾时展开，该展开不加阅读锁，自动跟随继续；其余展开照旧暂停自动跟随（C5）。该属性在展开时确定，之后不随运行状态变化。
- 用户上滑回看时，不因工具更新抢回底部；未读输出沿用现有“最新”入口。
- 工具详情阅读器继续单独持有阅读锁，关闭后恢复有效来源焦点。

## 设计约束与决策记录

被调整的约束：

- [DESIGN](../../DESIGN.md#组件规则)“思考与工具行”：结束前不合并工具；缺少 `run_end` 的历史不合并；状态未知的工具不参与合并；单条工具点击整行直接打开阅读器；展开摘要暂停自动跟随；“会话正文”中的「Pi 正在思考…」。
- [ADR-20260930](../../adr/20260930-strict-run-completion.md) 决策中的工具摘要展示条件。

ADR 原则上只追加：新增 ADR 取代 ADR-20260930 中工具摘要展示条件这一条，原文不改。保留的完成语义：**只有正式 `run_end` 能确认整轮结束**；Pi 空闲、下一轮出现或工具全部结束都不能替代；轮末完成时间仍只在收到 `run_end` 后显示。DESIGN 在实现完成时同步。

## 验收

| 场景 | 预期 |
| --- | --- |
| 第一条工具出现 | 即刻进入默认收起组，组头显示该工具 |
| 只有一条工具 | 成组；结束后显示分类摘要 |
| 顺序执行 | 组头依次显示每条新开始的工具 |
| 并行，后开始的先结束 | 组头回到摘要并带旋转图标，较早的工具不再出现 |
| 全部结束 | 组头显示分类摘要，无旋转图标 |
| 手动展开 | 组头显示摘要；新调用追加到底部，组保持展开 |
| 手动收起后新增工具 | 组保持收起 |
| partial 转正式结果 | 不重复工具行，不更换组身份，不丢失展开选择 |
| 运行中末段展开 | 继续自动跟随 |
| 已结束组展开 | 暂停自动跟随 |
| 断线、只读历史中的 partial | 显示未知，不作为当前命令，不显示旋转图标 |
| 历史向前加载 | 历史顺序正确，已有组身份与展开选择不变 |
| 正文、思考、文件或缺口插入 | 按真实边界分段 |
| 打开详情后工具继续更新 | 阅读器内容正确，关闭后恢复有效焦点，组不自动收起 |
| Working 提示 | 发送后、工具全部结束等待模型时显示；流式输出、工具运行、收到 `run_end` 或 Pi 空闲时不显示 |
| 收到 `run_end` | 显示轮末完成时间与状态，展开选择不变 |
| 减少动态效果 | 组头当前命令直接替换，无位移 |
