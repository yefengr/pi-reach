# 内容与空间过渡的时长、曲线与编排复核

- 日期：2026-10-31
- 用途：复核「内容与空间变化」类过渡的时长、曲线、位移与编排，先以对比原型确定取值，再修改规范与实现；本文不是当前实现说明。
- 项目级状态：见 [ROADMAP](../../ROADMAP.md)，不在本文另设状态表。
- 基线：`main` 的 `bdefc10`（PR #164 已合并）。
- 当前事实来源：[DESIGN「动效」](../../DESIGN.md#动效)与[「动效时长」](../../DESIGN.md#动效时长)。

## 1. 背景

2026-10-31 过程组收起的两轮真机录屏复核发现，规范取值让多处过渡在观感上接近瞬间。逐帧计算现行曲线的完成度（60Hz，每帧约 16.7ms）：

| 曲线 | 时长 | 第 1 帧 | 第 2 帧 | 完成 90% |
| --- | --- | --- | --- | --- |
| 进入 `(0, 0, 0, 1)` | 160ms（发送气泡） | 46% | 64% | 84ms |
| 进入 `(0, 0, 0, 1)` | 180ms（Modal、Toast） | 43% | 60% | 94ms |
| 标准 `(0.2, 0, 0, 1)` | 180ms（手动展开） | 13% | 46% | 97ms |
| 标准 `(0.2, 0, 0, 1)` | 140ms（手动收起） | 23% | 58% | 76ms |

进入曲线起步斜率无穷大，第一帧就完成近一半，4–8px 的位移在第一帧后只剩约 3px 可见。规范也没有规定同一时刻多处变化的先后：发送时空态提示消失、输入区清空与气泡进入在同一帧发生。过程组自动收起已单独改用 `collapse-settle`（320ms）与 `--pwa-ease-settle`，其余场景沿用原值。

## 2. 目标与不改动

目标：

- 把动效分成「操作反馈」（按压、悬停、复制反馈、菜单）与「内容与空间变化」（发送气泡、过程组展开与收起、Toast、Modal、浮动入口、内容出现与消失）两层；前者保持当前的干脆取值，后者重新确定时长、曲线与位移。
- 补充编排规则：同一时刻只有一个主动作，次要变化随后或同步完成，不与主动作并列瞬变；同时复核「输入区内的增减即时完成」等现有例外。
- 用状态展厅里的正式组件并排比较现行与候选参数，在手机和桌面实际操作后定稿，再统一修改 DESIGN、token 和脚本里读取时长的地方。

不改动：

- 减少动态效果的规则（`reduced` 120ms、只保留淡化）不变。
- 覆盖模型（Drawer、设置页 200ms 纯位移）与侧栏收展不在第一轮对比范围；定稿时再判断是否同层处理。
- [动效规范整理与一致性修复](20261027-motion-spec-cleanup.md)只整理结构、不改观感，本项不复用它的授权。

## 3. 对比原型

入口：`pnpm dev` 后打开 `/app/ui-states`，把「展示区域」选为「动效对比」。展厅只在 DEV 构建中存在，staging 与生产都打不开；手机比较时在电脑上启动 dev 服务（已监听 `0.0.0.0:3000`），手机与电脑处于同一局域网，访问 `http://<电脑局域网 IP>:3000/app/ui-states`。页头的「动效参数」切换现行与候选，并且对所有展示区域生效；它可以和「动画速度 · 0.25×」组合使用。

- **发送**：在输入区发送消息，气泡进入、输入区回缩与贴底跟随按正式发送顺序执行（`captureOwnSend` → 加入 pending → 清空草稿 → `followOwnSend`）；随后的演示回复可以观察普通行进入。
- **过程组**：点击组头查看手动展开与收起；「推进回复」逐步走完思考 → 工具 → 正文接续（自动收起）→ 本轮结束。
- **Toast 与 Modal**：使用同页「操作确认」「重命名电脑」「输入配对码」与三种 Toast 按钮。

实现方式：时长与位移以内联样式写到根元素的 `--pwa-*` token 上，脚本和 Mantine 读到的是同一组值；曲线只在消息区、输入区底部、Modal 与 Toast 的范围内改写 `--pwa-ease-enter`／`--pwa-ease-standard`，菜单、按压等操作反馈仍用根元素上的现行曲线。参数切换先写入根元素再触发渲染，Provider 的 Modal 时长随之更新。系统开启减少动态效果时清除全部覆盖，与慢放一致。原型只存在于 DEV 展厅，不进入生产构建。

### 3.1 候选参数（第一轮）

| 参数 | 现行 | 候选 A · 适中 | 候选 B · 舒缓 |
| --- | --- | --- | --- |
| `message-in`（气泡进入、输入区回缩、贴底） | 160ms | 240ms | 300ms |
| `collapse-in` / `collapse-out`（手动展开／收起、箭头） | 180 / 140ms | 240 / 200ms | 300 / 240ms |
| `collapse-settle`（自动收起） | 320ms | 320ms | 320ms |
| `toast` / `toast-out`（Toast、浮动入口出现） | 180 / 140ms | 240 / 180ms | 300 / 220ms |
| `modal-in` / `modal-out` | 180 / 140ms | 240 / 180ms | 280 / 200ms |
| 进入曲线 | `(0, 0, 0, 1)` | `(0.2, 0, 0, 1)` | `(0.2, 0, 0.2, 1)` |
| 标准曲线（展开收起） | `(0.2, 0, 0, 1)` | `(0.2, 0, 0, 1)` | `(0.2, 0, 0.2, 1)` |
| 退出曲线 | `(0.3, 0, 1, 1)` | 不变 | 不变 |
| 位移 `overlay` / `message` / `collapse` | 8 / 6 / 4px | 10 / 8 / 6px | 12 / 12 / 8px |

两个候选都保留「离开更快」。候选曲线的逐帧完成度：

| 曲线 | 时长 | 第 1 帧 | 第 2 帧 | 完成 90% |
| --- | --- | --- | --- | --- |
| `(0.2, 0, 0, 1)` | 240ms | 6% | 31% | 130ms |
| `(0.2, 0, 0.2, 1)` | 300ms | 3% | 12% | 185ms |

`content`（会话切换淡入）、`fade`（浮动入口消失）与操作反馈层的 `press-*`、`menu-*`、`feedback` 在第一轮保持不变。

### 3.2 编排

编排规则需要改动正式组件的时序（例如发送时空态提示先淡出、气泡再进入），第一轮原型只比较参数。参数定稿后，再按需要补充编排对比，或直接写入方案并实现。
