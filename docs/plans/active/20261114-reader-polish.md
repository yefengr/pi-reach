## 1. 背景与目标

用户反馈工具详情和文档阅读界面不好看。2026-11-14 在状态展厅里实际截图，归纳出三个原因：

1. 工具详情把原始数据直接摆出来：标题只有小写工具名（`edit`、`bash`），会话行里的「Edit tool-card.tsx +2 −1」点开后反而丢了；参数以 `path: …` 键值列出，像调试输出；输出直接铺在底色上，说明文字和代码之间没有边界。
2. 状态只有一个彩色图标，紧挨关闭按钮；手机上右上角只剩一个对勾，像「确认」按钮。
3. 文档阅读器标题栏只有文件名；二级标题 18px 只比正文 16px 大 2px，长文档层次不清；没有目录。

目标是在不改变阅读器外壳（Drawer 宽度、进出动画、手势、历史记录、焦点规则）的前提下，让用户直接阅读本次操作的对象：文件、文档、差异或命令日志。原始参数与通用成功回执不显示，也不设折叠入口。状态融入顶栏，正文前只保留路径和内容工具栏。当前数据缺口决定实施依赖与降级方式，不决定最终界面只能展示调试信息。

### 不改动

- 阅读器外壳：桌面 720px 右侧 Drawer、移动全屏、直角、`bg` 底色、48px 顶栏、右滑关闭、系统返回、焦点返回、滚动边缘分隔，均保持现状。
- 思考阅读器与摘要阅读器的内容（它们共用 `ReaderShell`，外壳改动不能破坏它们）。
- 图片阅读器（缩放、下拉关闭、几何过渡）。
- 不做语法高亮，不引入新依赖。
- 不改 Relay；第一期不改协议与扩展端。

## 3. 已核对的数据事实

以下为本轮实现前核对的基线，保留用于说明数据缺口；实现结果与验证边界见第 10 节。工具历史详情继续以 Pi 原生会话记录为准，不重新执行工具或读取当前磁盘。

1. **会话详情只带结果正文。** [`tool_detail_source.ts`](../../../pi-extension/src/timeline/tool_detail_source.ts) 组装详情时 `result: message.content`；运行中预览同样只取 `result.content`（[`runtime.ts`](../../../pi-extension/src/timeline/runtime.ts) 的 `publishToolPartial`）。Pi 工具结果里的 `details` 与 `structuredContent` 都没有传到 PWA。
2. **edit：真实详情里没有 diff。** Pi edit 工具的正文只有 `Successfully replaced N block(s) in <path>.`，diff 在 `details.diff`（Pi 自有格式，每行形如 `-18 旧文本`、`+18 新文本`、` 19 上下文`，省略处为 ` ... `，不带 `---/+++/@@`）与 `details.patch`（统一 diff）里。所以现在只有展厅演示数据会出现「Returned diff」块；时间线的「+N −M」同样依赖 diff，摘要（`toolSummarySchema`）里没有这项数据。
3. **bash：退出码与耗时不在详情里。** Pi 在 `structuredContent` 里给出 `exit_code` 与 `wall_time_seconds`；失败时只在正文末尾追加 `Command exited with code N`。不得解析这行文字推断退出码。
4. **read：行号可以在 PWA 计算，但请求范围不等于实际显示范围。** Pi 的 `offset` 为 1 起始的行号，未传时从第 1 行开始；现有 `readRange` 由请求参数计算，不能表示实际返回行数。`readLineOffset` 还接受 0，编号前须确认是正整数，非法值不能变成「第 0 行」。Pi 会在正文末尾追加续读提示，三种形式：
   - `\n\n[Showing lines A-B of N. Use offset=C to continue.]`
   - `\n\n[Showing lines A-B of N (50KB limit). Use offset=C to continue.]`（字节上限文字随 Pi 常量变化）
   - `\n\n[R more lines in file. Use offset=C to continue.]`

   另有单独一行的 `[Line N is …, exceeds … limit. Use bash: …]`，整段就是提示，没有文件内容。

## 4. 内容呈现规格（PWA 视图与目标效果）

### 4.1 工具详情标题（#1）

- 标题与时间线工具行同源：复用 `toolCallCopy`（[`tool-presentation.ts`](../../../pwa/src/components/pwa/tool-presentation.ts)）的动作词与对象，类型图标复用 [`tool-card.tsx`](../../../pwa/src/components/pwa/tool-card.tsx) 的 `TOOL_TYPE_ICONS`（建议导出共用，不复制一份映射）。
- 显示为：类型图标（20）＋动作词（系统字体、会话标题字号／600）＋对象（等宽、`soft-ink`、正文字号）。read、edit、write 的对象只放文件名，路径放正文元信息（#2）；bash 与搜索的对象为命令或搜索词，单行省略，完整内容在正文。标题只承担识别，路径、完整命令或搜索词由对应内容区承载，不再附原始参数表。
- 无法分类的工具（`kind: "generic"`）保持现状：标题为原始工具名，不加动作词。
- `ReaderShell` 的 `title` 目前是字符串，同时用作 `Drawer.Title` 内容与悬停 `title`。新增可选的标题节点参数，字符串仍用作可访问名称与悬停提示。复用 `toolCallCopy` 的动作与对象来源，但它的 `title` 已做长度限制，不能直接称为完整原始摘要；完整值从原参数取得并由正文承载。思考与摘要阅读器不传新参数，表现不变。
- 顶栏包括返回／关闭、标题、非交互的状态文字，以及适用的目录／保存操作；状态与标题同一行，不能只放一个像确认按钮的对勾。

### 4.2 顶栏状态与紧凑信息区（#2）

- 状态位于顶栏标题之后、操作按钮之前，图标＋元数据字号的短文字，无胶囊底色、无边框、无按钮交互。随固定顶栏始终可见，移除正文独立状态行，不增加正文遮挡或第二个滚动区。
- 完成状态：小对勾用 `complete`，文字用 `secondary`／400，降低常态权重；运行中用既有运行色和旋转图标，出错用错误色，准备中／已中断／未知用中性色。保留明确文字与可访问描述，不只靠颜色。图标使用现有行内 token，不新增尺寸档。
- 狭窄布局优先省略顶栏对象名称，保留动作、状态和返回操作；状态本身不能挤掉关闭或目录按钮。正文的完整路径负责补充文件识别信息。
- read、edit、write 的路径在标题下方正文首行直接显示：等宽、元数据字号、`secondary`，完整保留并自然换行，可选择复制。取消路径展开／收起及专用复制按钮，不为路径另起操作行；保留原始路径与分隔符含义。
- 内容工具栏放类型／实际范围／视图切换与对应的复制操作。Edit 的文件头在桌面将路径、真实增删计数和差异复制合为一行，路径占余下空间；手机先显示路径，下一行左右分别为计数和复制。文件头仅在下方画一条发丝线，直接衔接正文，不为这些信息分别建立多层区域。
- diff 正文不显示 `@@ … @@` 区块头，也不另写中文行号范围；旧／新行号已经承载位置。多个不连续的修改片段之间用「⋯」分隔，并提供「中间内容已省略」的可访问说明，不能拼成虚假连续范围。复制取真实返回的原始差异：有标准 patch 时保留文件头和所有 hunk 头；仅有 Pi 原生 diff 时保留原生格式，不补造缺失元数据。
- 原有 `pwa-tool-reader-description` 与 `aria-describedby` 关系继续指向顶栏状态。状态变化由简短 live region 播报，不把流式日志设为 live region；运行结束后保持同一状态位置，不产生正文位移。

### 4.3 按内容选择查看方式（#3）

抽屉沿用现有外壳；正文采用对应内容常见的查看方式，不统一包成「输入／输出」卡片。

| 内容 | 主体呈现 | 数据与边界 |
| --- | --- | --- |
| Read 代码／配置／纯文本 | 文件路径、实际显示范围、等宽源码与行号；直接使用正文宽度，不套「输出」圆角块 | 展示本次实际读取内容，不自动重读当前磁盘文件 |
| Read Markdown | 文档排版，可切换「预览／源码」；源码保留原文与文件行号 | 从中间开始或截断导致 Markdown 结构不完整时默认源码，并标记部分内容；不补造缺失正文 |
| Write | 「写入内容」为主体，Markdown 默认文档预览，代码／配置为源码；Markdown 可切换源码 | 内容取本次请求的 `content`，完成状态来自真实回执；它不是再次读取的磁盘快照。运行或失败时标为「待写入内容／尝试写入内容」，不能显示成已经写入 |
| Edit | 统一 diff：上下文、删除行、增加行，辅以旧／新行号、`−`／`+` 和轻底色 | 依赖真实返回差异，见第 5 节；720px 抽屉与手机默认都用统一视图，避免左右分栏挤压内容 |
| Bash | 完整命令与连续终端日志，等宽显示；仅命令带 `$` 提示符 | 失败日志仍用普通底色，由状态和错误文字说明失败；不从正文推断结构化退出码 |
| Search | 搜索词、范围与匹配结果；结构化结果按文件及行号组织 | 仅有原文时保留原文，不通过猜测格式生成跳转目标 |
| 未分类工具 | 实质返回内容，不附参数表与通用成功回执 | 不推断未知工具的文档、代码或执行语义；无法识别的结果保留原文，避免误删内容 |

- 文件、差异和 Run 共用 `bg` 主底色、正文边距、内容工具栏与轻分隔，不再嵌套通用输出卡片或单独的终端圆角面板。Run 上方显示完整命令及命令复制，下方复用内容工具栏放「执行日志」和日志复制，日志直接铺在正文底色上；保持等宽字体、`$` 提示符与原始日志结构。文档内本来就存在的代码块仍沿用 Markdown 代码块样式。
- Edit 主样例必须有 diff。没有差异的旧记录明确显示「本次未返回差异」；不得把 `oldText/newText` 自动伪装成实际执行的差异，也不能据此统计已完成的增删行数。
- Write 的 `content` 直接用于文档／源码主体，同一份正文只展示一次，不展示参数名、JSON 包装或成功回执。
- 复制复用 [`CopyButton`](../../../pwa/src/components/pwa/copy-button.tsx)，保留 44×44 点击区。文件复制取原文，diff 复制取原始差异，命令复制不带 `$`，日志复制不混入命令或界面标签。新文案进入现有中英文消息文件。
- 可识别的通用成功回执（如内置 Edit／Write 的 `Successfully replaced …`、`Successfully wrote …`）不再显示。实际错误原因、命令日志、搜索结果、截断提示与图片输出保留，不能因移除回执而吞掉实质结果；既有流式跟随规则保持。

### 4.4 只展示阅读所需的信息（#4）

- 移除原始参数与回执区域，包括「调用详情」等折叠入口。Read 的请求 `offset/limit`、Edit 的 `edits` 结构、命令超时等不作为界面内容。
- 路径、完整命令、搜索词、Write 的正文仍是用户要阅读的对象，按各自语义呈现并保留原文；不因不展示参数表而删掉这些内容。
- 当前调整仅涉及显示，不删除协议、会话或缓存中的数据；执行状态继续来自真实结果，Write 的请求内容也不能被当作磁盘读回内容。
- 主体取值继续复用 `PATH_KEYS`、`COMMAND_KEYS`、`QUERY_KEYS` 等现有逻辑，不新增猜测性参数解释。

### 4.5 read 行号（#5a）

- 只在源码视图满足以下条件时显示文件行号：结果恰好是一个文本块；不是出错状态；文本不是单独一行的 `[Line N is …]` 提示。文档预览不在段落旁硬加源码行号，范围信息保留在文件工具条。
- 起始行：`readLineOffset(value)`；未传时为 1，显式的非法或非正整数值不生成行号，也不显示虚假的实际范围。
- 先剥离末尾的续读提示（第 3 节第 4 条的三种形式，匹配必须锚定在文本末尾、前面紧接空行）；剥离出的提示放在文件内容之后，以 `.pwa-tool-notice` 样式显示，不编号。匹配失败时整段按正文编号，不报错。
- 版式：两列网格，行号列按最大行号位数留宽、右对齐、`secondary`、不可选中；长行折行时正文悬挂缩进，与本行首字对齐。输出复制保留内容原有空白和换行，不含行号、块标签或已分离的续读提示；提示本身仍完整可选中。
- 元信息使用「已显示第 A–B 行」，按剥离提示后的实际文本行数计算；空正文、纯提示、出错或无法可靠编号时不显示实际范围。明确处理末尾换行和空行，不把渲染占位空行计成文件行。
- 时间线 `readRange` 仍表示请求范围，不用详情结果改写。例如 `offset: 53, limit: 100`、文件只到第 62 行时，时间线显示 `L53–152`，详情显示「已显示第 53–62 行」，不再附原始请求参数。两者数值无需强行一致，时间线顺序按第 4.9 节调整。

### 4.6 文件信息与标题层级（#6）

- 文本文件阅读器正文第一行为文件信息：类型＋原件大小，如「Markdown · 3.1 KiB」「纯文本 · 12 KiB」，元数据字号、`secondary`，下方发丝线，与正文间隔 16。大小来自 `state.byteLength`（没有时用描述符的 `byte_length`）；格式化复用现有实现（`attachment-cards.tsx` 的大小格式化，或抽成共用函数），不再新写一份。预览被截断时在该行加「部分预览」，末尾仍保留现有截断说明；不显示章节总数。
- 标题层级用于已发布文件以及 Read／Write 的文档预览，复用现有安全 Markdown 渲染（跳过 HTML、不自动加载外部图片、沿用安全链接规则）；聊天 Markdown 与思考、摘要阅读器不变，复用现有语义 token：
  - h1：页面标题字号／600，标题行高 1.25，上方 24、下方 12；文档首个元素不留上边距；
  - h2：现有 Markdown 一级标题字号／600，标题行高 1.25，上方 24、下方 8；
  - h3：正文字号／600，界面行高 1.4，上方 16、下方 8；
  - 段落上下 8，正文行高仍为 1.65。
  默认桌面为 24／20／16，触控为 28／22／17；大／特大档直接跟随现有 token。不新增 700 字重、独立字号档位或非标准间距。标题的可辨认度由字号、字重与段前留白共同提供。
- 纯文本（非 Markdown）文件只加文件信息行，正文不变。

### 4.7 文档目录（#7）

- 仅在 Markdown 文档预览中、且 h1–h3 标题不少于 2 个时，在顶栏操作区显示目录按钮（图标按钮 44，Lucide `List` 或 `TableOfContents`，可访问名称与悬停说明「目录」）。Read／Write 也可使用同一目录；切换源码后隐藏。保存只用于真正具有文件获取能力的已发布文件，不因工具有路径而增加下载入口。
- 点按打开目录面板，复用现有 Mantine `Menu`（浮层面板圆角 12，与其他菜单一致）：按层级缩进列出 h1–h3，当前所在章节用既有 `selected` 底色和字重标识。面板宽高受阅读器与可用视口限制，长目录独立滚动，长标题完整换行；菜单项点击区最小高 44，缩进只表达三级层级，不随深度无限累加。
- 再次打开目录时让当前章节位于可见区域。选择后关闭菜单并在阅读器滚动容器内定位标题，遵守减少动态效果；标题完整露出，不被顶栏或其他固定内容遮住。只滚动目录或正文的对应容器，不带动背后会话。
- 目录来源与当前渲染的 Markdown 保持一致，忽略代码块中的伪标题并对重复标题去重定位。预览被截断时只列已渲染标题，面板注明「仅显示预览部分的目录」；不得列出点击无目标的未加载章节。标题不足 2 个时不显示目录按钮，即使原件可能还有更多章节。
- 标题锚点只用于阅读器内部定位：生成稳定的元素 id（文档内去重），不改变 URL、不写入历史记录。
- 叠层：目录菜单位于阅读器 Drawer 之上，必须满足 Escape 只关闭菜单、系统返回与右滑在菜单打开时先关菜单或被门禁拒绝（与现有 `readerHasOverlay` 一致）、焦点返回目录按钮。按 [overlay 验证技能](../../../.agents/skills/validate-mantine-stacked-overlays/SKILL.md) 验收，并把目录菜单补入技能的叠层组件清单（`scripts/overlay-skill-guard.test.mjs` 会校验）。
- 正文在进入动画结束后才渲染（现有规则），目录按钮在正文渲染后出现，不影响滑入。

### 4.8 视觉稿与展厅

- 评审稿以目标内容视图为主：Edit 统一 diff、Read 源码与 Markdown、Write 文档与代码、Bash 终端日志、搜索结果、已发布文档；另有「未返回差异」降级样例。提供浅深色、三个字号档位、手机／桌面切换。

### 4.9 会话过程组工具行的路径与行数顺序（#8，补充建议）

用户要求将「读取行的顺序对比」建议记录在本方案，待后续与阅读器优化一并调整。现有 read 行把文件名与行范围放在一起、目录排在最后；长文件名在手机宽度下可能把行范围挤成「L12…」。建议让路径按通常的阅读顺序连在一起，并单独保留行数信息的空间。

- **适用位置。** 会话过程组中的 read、edit、write 工具行；复用这些工具文案的收起组头同步调整。工具详情阅读器标题仍按第 4.1 节只放文件名，目录仍放正文元信息行。
- **排列顺序。** 类型／状态图标＋动作词＋目录/文件名＋行范围或增删行数，例如：
  - `Read pwa/src/components/pwa/tool-card.tsx · L1–40`
  - `Edit pwa/src/components/pwa/tool-card.tsx +2 −1`
  - `Write docs/plans/active/20261114-reader-polish.md`
- **路径与颜色。** 目录在文件名前，与文件名直接连成完整路径，不插入额外空格或 `·`；目录为等宽、`secondary`，文件名为等宽、`soft-ink`，字号沿用现有工具行。无目录时只显示文件名，如 `Read README.md`。路径仍取工具摘要中的值，保留原有相对／绝对路径语义。
- **省略优先级。** 保持单行。空间不足先从目录左侧省略，保留靠近文件名的末几级，如 `…/pwa/tool-card.tsx`；目录让出空间后仍放不下时，才对文件名做尾部省略。动作词、独立的行范围与增删行数不参与省略，不让长文件名再把 `L120–180` 挤成 `L12…`。
- **行数位置与来源。** read 的 `· L起始–结束`、edit 已有的 `+N −M` 紧跟完整路径之后，目录不再排在它们后面；增删颜色沿用 `complete`／`error`。复用现有行范围与 diff 计数，不新增推断：没有行范围或 diff 时不造占位，也不借本项扩大第二期的数据回传范围。
- **共享呈现与原有交互。** 复用 `toolCallCopy` 的动作与路径来源，将目录、文件名、行范围拆成可分别控制省略的呈现片段，核对工具明细与收起组头的直接消费者；悬停提示与可访问名称保留完整摘要，点击后仍进入原工具详情。命令、搜索与未分类工具沿用原有呈现。
- **验收样例。** 桌面阅读列与 390px 手机宽度均覆盖短路径、深层目录、长文件名、无目录及 edit 增删计数；在浅色／深色和三个字号档位下核对目录先省略、文件名其次、行数完整可见。

## 5. 第二期：扩展端补数据（#5b、#5c）

先确认可行性，再开始实现。Edit diff 是目标体验的必要工作；不可行时明确记录阻塞和降级范围，不标记 Edit 目标完成。Bash 的退出码和耗时可单独延后。

1. **字段来源。** 确认 Pi SDK（当前 1.3.0）会话记录里的工具结果消息是否保存 `details` 与 `structuredContent`，以及 `tool_execution_end` 事件里的 `result` 是否带这两个字段。历史会话打开详情时只能用会话记录里保存的字段。
2. **回传形状。** 详情的 `result` 目前是正文数组。若改为对象（如 `{ content, details }`），需核对 PWA `toolResult`、`toolOutputBlocks`、`reliableToolDiff` 与详情缓存的兼容性；`toolDetailsContentSchema` 的 `result` 为 JSON，预计不必改 schema，但须以协议测试确认。只回传本轮实际需要的白名单字段：精确 `edit` 工具的 `diff`、`patch`、`firstChangedLine`；Bash 的结构化退出码与耗时延后，不在本轮透传。不回传 `full_output_path` 等本机路径，并注意 `MAX_TOOL_DETAILS_BYTES` 上限。
3. **发布顺序。** 先部署能识别新字段的 PWA，再发布扩展（见 [DEPLOYMENT](../../DEPLOYMENT.md#extension-npm-发布)）；旧扩展没有这些字段时，PWA 按第一期显示。
4. **PWA 显示。**
   - edit：优先使用带明确 hunk 范围的 `details.patch`，按 hunk 头递进计算旧／新行号；无 patch 时按 Pi 自有 `details.diff` 的实际格式显示。只有单一行号的格式不能可靠还原双侧位置时，保留原始行号或省略不确定的一侧，不推算虚假的双侧行号。省略段用中性色，缺少两类差异时显示明确降级。元信息行加「+N −M」，计数复用 `diffLineKind`，文件头不计入。
   - bash：顶栏仍只显示简短状态；有结构化字段后，将「退出码 N」「用时 X 秒」放在命令信息中，不把长元信息塞进顶栏。没有字段时不显示，不从文字解析。
   - 新增详情字段后，是否让时间线工具行显示原先没有的「+N −M」属于另一处改动，不在本方案范围；如需要，另行确认。第 4.9 节只调整已有信息的顺序与省略方式，不增加时间线的数据来源。

## 9. 风险

- 标题改用动作词后，未分类工具与已分类工具的标题风格不同；这是有意保留的回退，不为未分类工具编造动作词。
