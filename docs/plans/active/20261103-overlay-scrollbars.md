# PWA 覆盖式滚动条候选方案

本方案记录后续改造方向，不描述当前已上线能力，也不启动滚动条迁移。事项入口见 [BACKLOG](../../BACKLOG.md#pwa-覆盖式滚动条)；当前规则仍以 [DESIGN](../../DESIGN.md#基础层) 为准。

## 要解决的问题

希望应用内的滚动条覆盖在内容边缘，不再占用布局空间：纵向不挤窄内容，横向不占额外高度，出现和消失也不改变内容尺寸。范围不只侧栏，还包括消息、设置、阅读器、菜单、输入框和内嵌代码块、表格。

当前实现使用原生细滚动条与透明轨道。[全局样式](../../../pwa/src/app/globals.css)中的消息区，以及[排队消息面板](../../../pwa/src/app/queued-messages.css)，还使用 `scrollbar-gutter: stable` 保持宽度稳定。透明轨道只改变绘制，不保证释放占位；原生滚动条是否覆盖内容仍受浏览器与系统设置影响。仅删除 gutter 或改用 `overflow: overlay`，不能实现可靠的跨平台统一。

侧栏截图中的左右留白差异尚未在目标环境确认根因；滚动条占位只是候选解释，本方案不以该截图作为已证明的根因，也不通过增加左侧 padding 补偿。

## 希望保留的体验

- 纵向滑块位于容器右侧内缘，横向滑块位于底部内缘；不为轨道另加占位。
- 延续细滑块、透明轨道、主题配色，以及滚动时出现、停止 3 秒后淡出的规则。拖动过程中不能消失；不顺带改为悬停显示。
- 保留鼠标滚轮、触控板、键盘、原生触摸惯性与滑块拖动，不自行实现滚动物理。
- 保留嵌套容器各自显隐、加载更早记录时的显示抑制，以及顶栏滚动边缘分隔。
- 不能仅隐藏原生滚动条而没有替代操作入口；初始化失败、减少动态效果与辅助显示模式须有明确降级。

此前的[滚动条显隐方案](20261026-pwa-scrollbar-auto-hide.md)解决颜色与显示时机，本方案新增的是“不占空间”。旧实现记录不在本次改写；真正落地后再同步当前设计规则及取代范围。

## 技术路线

采用成熟组件或库管理滑块绘制、比例计算、拖动和更新，实际滚动继续使用浏览器的滚动容器。不从零维护一套滑块拖拽、尺寸观察与生命周期管理，也不一开始就引入两套方案。

| 候选 | 可利用的能力 | 必须验证的边界 |
| --- | --- | --- |
| 已有 Mantine `ScrollArea` | 无需新增依赖；支持不为滚动条补 padding、显隐控制，以及通过 `viewportRef` 访问滚动节点 | 会增加容器结构；要核对消息列表的布局、ref、事件与滚动位置契约，不能全局机械套壳 |
| 专用覆盖式库 OverlayScrollbars | 保留原生滚动，支持 React 接入与显式指定已有 viewport | 需要新增依赖；自定义 viewport 不等于样式完全不变，要核对 padding、尺寸、观察器及卸载行为；文档列有 `textarea` 直接初始化限制，选定版本前重新核验 |

优先用已有组件做小范围兼容性验证。只有它无法满足关键滚动容器的契约时，才评估专用库；根据验证结果决定统一采用哪条路线。此处没有确定新增依赖或版本。

## 覆盖范围与难点

| 区域 | 验证重点 |
| --- | --- |
| 桌面侧栏、移动导航、设置列表 | 内容宽度不随滚动条变化，列表选中背景与底部固定操作不受挤压 |
| 消息列表 | 流式贴底、加载历史后的阅读锚点、会话切换恢复、“最新”入口、动态内容增长与收起保持原行为 |
| 菜单、Popover、Drawer 与阅读器 | 挂载和退出清理、Portal、焦点返回、滚动锁与移动端滑动关闭不受影响 |
| 代码块、表格、工具输出 | 横向滚动与父级纵向滚动独立；不改变长内容换行，也不抢移动手势 |
| Composer 与其他 `textarea` | 单独验证内部滚动、自动高度、输入法、选择与光标跟随；不能因容器库限制擅自改成 `contenteditable` |

“全应用统一”是覆盖目标，不是现成库已对所有控件开箱可用的承诺。普通列表接入较简单，复杂度主要在消息区和输入框的兼容与回归。

## 后续实施顺序

1. 盘点实际纵向、横向和嵌套滚动节点，以及 ref、滚动监听、尺寸观察和手势消费者；不要只按 CSS 选择器列清单。
2. 在侧栏与真实消息列表上验证候选方案，先证明不占位和原有行为能同时成立，再确定依赖与接入结构。
3. 单独验证输入框可行性、辅助模式与失败回退；存在无法覆盖的区域时先明确边界，不把部分覆盖称为全应用完成。
4. 冻结方案后分批迁移，并统一显隐、颜色、滑块尺寸与清理规则；不同时改消息滚动算法、叠层生命周期或协议。
5. 验证通过后同步 DESIGN；事项按项目文档规范流转，不提前把候选写成当前设计事实。

## 验收门槛

- 在采用占位式原生滚动条的目标环境中证明迁移后不再预留轨道空间；扣除边框后核对 viewport 几何。只在本来就使用覆盖式滚动条的机器上截图不足以证明。
- 浅色、深色、三档字号、桌面与移动布局下，滑块显隐和内容增减不造成正文宽度跳变，滑块不遮挡必须操作的控件。
- 鼠标拖动、滚轮、键盘、横向滚动与嵌套滚动均可用；真实移动设备验证惯性与滑动关闭，桌面模拟视口不替代真机。
- 消息区回归覆盖历史前插、流式增长、手动回看、恢复跟随和会话切换；输入框覆盖光标、文本选择、输入法和高度变化。
- 验证减少动态效果、初始化失败回退、动态挂载与卸载；长对话中不因每帧测量或观察器回写引入明显开销。

本方案不涉及 Extension、Relay、协议、持久化、浏览器或系统自身的界面滚动条，也不授权提交、部署或发布滚动条实现。
